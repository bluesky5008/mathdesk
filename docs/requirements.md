## 문제와 목적

학원 운영자(원장·강사)는 매 수업일마다 반별 출결, 교시별 진도, 과제 부여와 과제 평가, 당일 테스트 점수를 기록하고, 이를 학생·학부모에게 문자로 전달한다. 시험지를 출제·선정할 때는 문항별 단원과 난이도를 파악해야 하고, 시험 후에는 OMR 답안지를 수작업으로 채점한다. 현재는 이 작업이 종이·엑셀·수기 문자에 흩어져 있어 다음 문제가 발생한다.

1. 같은 정보를 출결표·성적표·문자에 반복 입력한다.
2. 학생별 누적 이력(과제 등급 추이, 테스트 점수 추이, 재검사 이력)이 남지 않아 상담과 지도 판단의 근거가 약하다.
3. 학부모 문자를 매번 손으로 작성하여 시간이 들고 내용 품질이 강사별·날짜별로 들쭉날쭉하다.
4. 30문항 OMR을 반 단위로 손채점하여 시간이 들고 오채점 위험이 있다.
5. 시험지 문항의 단원·난이도 분류가 강사의 암묵지에 머물러 재사용되지 않는다.

목적은 한 번의 입력으로 기록·집계·통보·분석이 연결되는 단일 시스템을 제공하여 위 다섯 가지를 해소하는 것이다.

## 대상과 시나리오

| 구분 | 대상 | 설명 |
|---|---|---|
| 주 사용자 | 강사 | 담당 반의 일일 입력, 문자 발송, 학생 이력 조회 |
| 주 사용자 | 원장 | 전체 반·학생 조회, 통계, 시험지 등록·분석, 연동 설정 |
| 수신자 | 학부모·학생 | 문자·알림톡 수신 (시스템에 로그인하지 않음) |
| 호출 주체 | 외부 연동 | 알리고 메시징 API, OpenAI 호환 LLM API |

주요 시나리오

1. **일일 수업 입력**: 강사가 수업일에 반을 선택하고 학생별 출결을 체크한 뒤 확정하고, 교시별 진도와 오늘의 과제를 한 번 입력하며, 학생별 과제 등급과 테스트 점수를 입력한다.
2. **학부모 통보**: 강사가 학생을 선택해 병합된 문자 본문을 확인하고 수신 대상을 고른 뒤 복사하거나 발송한다.
3. **대시보드 확인**: 원장이 로그인하여 재원생 수, 선택 반 등원 현황, 금주 과제 완수율, 주간 테스트 평균을 확인한다.
4. **시험지 등록·분석**: 원장이 시험지 파일을 올리면 문항별 단원·세부 유형·난이도·판단 근거 초안이 생성되고, 확인이 필요한 문항을 수정한 뒤 확정한다.
5. **OMR 자동 채점**: 시험 후 학생 여러 명의 OMR을 한 PDF로 올리면 수험번호로 학생이 매칭되고 판독 결과를 검수한 뒤 성적과 문항별 정답률에 반영한다.
6. **상담 준비**: 강사가 학생의 출결률·과제 등급 추이·테스트 점수 추이를 조회하고 상담일지를 기록한다.

## 범위

### 포함

- M0 인증·기본: 로그인, 사용자·역할, 캠퍼스, 연동 설정
- M1 학생/반 관리
- M2 일일 수업·성적 입력
- M3 종합 대시보드
- M4 메시지(미리보기·복사·리포트 이미지·알리고 발송·발송 로그)
- M5 성적 통계 분석
- M6 시험지 등록·문항 분석
- M7 OMR 자동 채점
- M8 카카오 알림톡
- M9 상담일지
- Phase A(로컬 `docker compose` 실행) 동작

### 제외

| 제외 항목 | 이유 |
|---|---|
| 학부모·학생용 로그인 포털 | 통보는 단방향 메시지로 충분하며 요청되지 않았다 |
| 수강료·결제·정산 | 요청 범위 밖이다 |
| 출결 하드웨어(키오스크·비콘) 연동 | 요청 범위 밖이다 |
| 시험지 자동 출제·문항 생성 | 분석만 요구되었다 |
| 모바일 전용 앱 | 반응형 웹으로 대체한다 |
| Phase B(Kubernetes) 실제 배포 | 이번 기준선은 Phase B 전환 가능성만 설계에 보장하고 배포는 수행하지 않는다 |
| 다국어 지원 | 한국어 단일이다 |

#### FR-03 상세

- 모든 도메인 엔터티(학생, 반, 수업 기록, 시험, 메시지 로그)는 하나의 캠퍼스에 귀속된다.
- 사용자는 접근 가능한 캠퍼스 목록을 가지며 상단 바에서 현재 캠퍼스를 전환한다.
- 서버는 요청마다 현재 캠퍼스와 사용자 권한을 검사하고, 권한 밖 자원 요청에는 데이터 존재 여부를 노출하지 않는 오류를 반환한다.
- 역할별 권한: 원장은 캠퍼스 내 전체 자원과 설정에 접근한다. 강사는 담당 반과 그 반 소속 학생에 접근하며 연동 설정과 사용자 관리는 조회·변경할 수 없다.

#### FR-05 상세

- OMR 수험번호는 8자리 숫자이며 자리별 허용 범위를 만족해야 한다: 1열 `1~9`, 2열 `0~9`, 3열 `0~5`, 4열 `0~9`, 5열 `0~9`, 6열 `0~9`, 7열 `0~2`, 8열 `0~9`.
- 수험번호는 캠퍼스 안에서 유일해야 한다.
- 재원 상태는 `재원`·`휴원`·`퇴원`이며, 퇴원 학생은 기본 목록에서 제외되지만 과거 기록은 보존된다.

#### FR-09 상세

- 입력 전 기본값은 `미확인`이며 집계에서 `출석`으로 취급하지 않는다.
- 선택된 상태를 다시 누르면 `미확인`으로 해제된다.
- `확인`을 누르면 해당 반·날짜의 출결이 확정되어 읽기 전용이 되고, `편집`을 누르면 다시 수정할 수 있다.
- 등원 인원은 `출석 + 지각 + 조퇴`로 계산한다.
- 확정·해제 시각과 수행자를 기록한다.

#### FR-12 상세

- 재검사 대상 판정 기준 등급은 설정값이며 기본값은 `B` 이하다.
- 판정 대상은 해당 학생의 직전 수업일 과제 등급이며, 결석으로 등급이 없으면 대상이 아니다.
- 화면에는 `직전 <등급> · <직전 수업일>` 형식으로 근거를 함께 표시한다.
- `합격`·`불합격` 선택은 표 일괄 저장을 기다리지 않고 즉시 저장한다.

#### FR-14 상세

| 저장 단위 | 대상 데이터 | 저장 시점 |
|---|---|---|
| 표 일괄 저장 | 출결 상태·사유, 과제 등급, 테스트 점수 | 표 하단 저장 버튼 |
| 즉시 저장 | 재검사 합격·불합격 | 선택 즉시 |
| 메모 저장 | 교시별 진도, 오늘의 과제, 영상 링크, 첨언 | 반 단위 메모 저장 버튼 |

- 한 단위의 저장이 다른 단위의 미저장 편집 내용을 덮어쓰지 않아야 한다.
- 미저장 내용이 있는 상태에서 반·날짜·학생을 전환하면 경고한다.

#### FR-15 상세

| KPI | 정의 |
|---|---|
| 총 재원생·반 현황 | 현재 캠퍼스의 재원 상태 학생 수와 활성 반 수 |
| 선택 반 등원 현황 | 선택한 반·날짜의 `출석 + 지각 + 조퇴` / 재적 인원 |
| 금주 과제 완수율 | 금주 과제 등급 중 기준 등급 이상 비율, 전주 대비 %p 증감, 미제출 건수, 재검사 대상 인원 |
| 주간 테스트 종합 평균 | 금주 테스트 점수 평균, 표본 수 N, 최고점(동점 인원), 최저점 |

- 모든 KPI는 원천 테이블의 집계이며 별도 저장하지 않는다.
- 표본이 없으면 값 대신 `—`를 표시한다.

#### FR-18 상세

메시지 본문은 다음 구획을 포함한다.

1. 제목(학생명 + 학습피드백), 학원명·강사명 인사말, 수업일
2. `■ 출결`
3. `■ 수업진도` — 교시별 항목
4. `■ 과제피드백` — 등급과 등급 문구
5. `■ 테스트` — 시험명, 학생 점수, 반 평균
6. `■ 오늘의 과제`
7. `■ 수업 영상 링크`

- 데이터가 없는 구획은 본문에서 생략한다.
- 본문은 저장하지 않고 렌더 시점에 생성하며, 발송할 때만 스냅샷을 발송 로그에 남긴다.

#### FR-23 상세

- 발송은 `테스트 모드`와 `실발송 모드`를 가지며 기본값은 테스트 모드다. 테스트 모드에서는 외부 API를 호출하지 않고 로그만 남긴다.
- 본문 길이에 따라 SMS·LMS를 자동 선택하고 이미지 첨부 시 MMS를 사용한다.
- 발송 로그는 수신자, 채널, 요청 시각, 결과 상태, 실패 사유, 본문 스냅샷, 과금 단위를 보존한다.
- 잔여 발송 가능량(장문·단문·이미지)과 조회 시각을 표시하고 수동 새로고침할 수 있다.

#### FR-27 상세

정규화 결과는 `{pages[], blocks[](text|equation|image|table), page_images[]}` 구조를 가진다.

| 포맷 | 처리 | 제약 |
|---|---|---|
| `.hwpx` | OWPML XML 직접 파싱 | 없음 |
| `.hwp` | 텍스트·표·수식 스크립트 추출 | 배포 금지·암호 설정 파일은 오류로 안내 |
| `.pdf` | 텍스트 레이어와 좌표, 페이지 이미지 추출, 텍스트가 없으면 이미지 경로로 폴백 | — |
| 이미지 | 페이지 이미지로 취급하고 이미지 경로로 처리 | 정확도는 화질에 의존 |

- 한글 수식 스크립트는 LaTeX가 아니며 원문 그대로 보존한다.
- 수식이 그림 개체로 삽입되어 텍스트 추출이 불가능하면 이미지 경로로 폴백한다.

#### FR-33 상세

판독 대상 필드와 판정 규칙은 다음과 같다.

| 필드 | 구성 | 판정 |
|---|---|---|
| 수험번호 | 8열 × 자리별 허용 숫자(총 68버블) | 열마다 단일 마킹 |
| 문형 | 홀수형·짝수형 | 단일 마킹 |
| 객관식 1~15, 23~28 | 21문항 × 5지 | 단일 마킹 |
| 단답형 16~22, 29~30 | 9문항 × 백·십·일 3열 | 열별 단일 마킹 후 정수 조합, 백의 자리 무마킹 허용 |

- 플래그 종류: `무마킹`, `복수마킹`, `저신뢰`, `매칭 실패`.
- 플래그가 있는 답안은 검수를 거치기 전에는 채점에 반영하지 않는다.

| AC-21 | 시험지 정규화 | `.hwpx`·`.pdf` 샘플을 업로드하면 페이지 수와 블록이 추출되고, 암호가 걸린 `.hwp`는 사용자에게 오류 사유가 안내된다 |
| AC-22 | 문항 분석 초안 | 30문항 시험지를 등록하면 문항 30건의 단원·세부 유형·난이도·판단 근거 초안이 생성되고 저신뢰 문항에 `확인 필요`가 표시된다 |
| AC-23 | LLM 어댑터 교체 | 설정에서 LLM 엔드포인트를 로컬 구현으로 바꾸면 코드 변경 없이 문항 분석이 그 엔드포인트를 호출한다 |
| AC-24 | OMR 판독 정확도 | 합성 마킹 답안지에 회전 3°·축소 0.6·원근 왜곡을 적용해도 30문항과 수험번호·문형이 모두 일치하고 의도된 복수마킹·무마킹이 플래그로 분류된다 |
| AC-25 | OMR 검수·반영 | 플래그가 있는 답안은 검수 전 채점에 반영되지 않고, 검수에서 값을 교정하면 교정 기록이 저장되며 점수와 문항별 정답률이 갱신된다 |
| AC-26 | 알림톡 폴백 | 알림톡 발송이 실패하면 설정에 따라 SMS로 대체 발송되고 두 시도가 모두 로그에 남는다 |
| AC-27 | 외부 전송 경계 | OMR 처리와 메시지 발송 경로에서 외부 LLM API 호출이 발생하지 않음을 테스트로 확인할 수 있다 |

| Q-04 | 가정 — 학원이 학생에게 8자리 수험번호를 부여해 OMR에 마킹시킨다 | 운영 절차 확인 |

| Q-06 | 가정 — 교시는 1~4교시로 고정한다 | 다른 반 구성이 필요하면 DCR |
