## 문제와 목적

학원 운영자(원장·강사)는 매 수업일마다 반별 출결, 교시별 진도, 과제 부여와 과제 평가, 당일 테스트 점수를 기록하고, 이를 학생·학부모에게 문자로 전달한다. 시험지를 출제·선정할 때는 문항별 단원과 난이도를 파악해야 하고, 시험 후에는 OMR 답안지를 수작업으로 채점한다. 현재는 이 작업이 종이·엑셀·수기 문자에 흩어져 있어 다음 문제가 발생한다.

1. 같은 정보를 출결표·성적표·문자에 반복 입력한다.
2. 학생별 누적 이력(과제 등급 추이, 테스트 점수 추이, 재검사 이력)이 남지 않아 상담과 지도 판단의 근거가 약하다.
3. 학부모 문자를 매번 손으로 작성하여 시간이 들고 내용 품질이 강사별·날짜별로 들쭉날쭉하다.
4. 30문항 OMR을 반 단위로 손채점하여 시간이 들고 오채점 위험이 있다.
5. 시험지 문항의 단원·난이도 분류가 강사의 암묵지에 머물러 재사용되지 않는다.

목적은 한 번의 입력으로 기록·집계·통보·분석이 연결되는 단일 시스템을 제공하여 위 다섯 가지를 해소하는 것이다.

## 대상과 시나리오

| 구분 | 대상 | 설명 |
|---|---|---|
| 주 사용자 | 강사 | 담당 반의 일일 입력, 문자 발송, 학생 이력 조회 |
| 주 사용자 | 원장 | 전체 반·학생 조회, 통계, 시험지 등록·분석, 연동 설정 |
| 포털 사용자 | 학생·학부모 | 포털에 로그인해 본인(자녀)의 학습 기록을 조회한다(FR-49). 문자·알림톡 수신자이기도 하다([DCR-024](./work/20260922-mathdesk-baseline/DCR-024-학생-학부모-포털.md)) |
| 호출 주체 | 외부 연동 | 알리고 메시징 API, LLM API (Anthropic 기본 · OpenAI 호환 폴백 · 테스트 모드) |

주요 시나리오

1. **일일 수업 입력**: 강사가 수업일에 반을 선택하고 학생별 출결을 체크한 뒤 확정하고, 교시별 진도와 오늘의 과제를 한 번 입력하며, 학생별 과제 등급과 테스트 점수를 입력한다.
2. **학부모 통보**: 강사가 학생을 선택해 병합된 문자 본문을 확인하고 수신 대상을 고른 뒤 복사하거나 발송한다.
3. **대시보드 확인**: 원장이 로그인하여 재원생 수, 선택 반 등원 현황, 금주 과제 완수율, 주간 테스트 평균을 확인한다.
4. **시험지 등록·분석**: 원장이 시험지 파일을 올리면 문항별 단원·세부 유형·난이도·판단 근거 초안이 생성되고, 확인이 필요한 문항을 수정한 뒤 확정한다.
5. **OMR 자동 채점**: 시험 후 학생 여러 명의 OMR을 한 PDF로 올리면 수험번호로 학생이 매칭되고 판독 결과를 검수한 뒤 성적과 문항별 정답률에 반영한다.
6. **상담 준비**: 강사가 학생의 출결률·과제 등급 추이·테스트 점수 추이를 조회하고 상담일지를 기록한다.
7. **포털 조회**: 학부모가 휴대폰으로 로그인해 자녀를 고르고 최근 수업일 기록·출석률·테스트 추이·시험 결과·상담 기록·받은 문자를 본다. 학생도 본인 계정으로 같은 화면을 본다([DCR-024](./work/20260922-mathdesk-baseline/DCR-024-학생-학부모-포털.md)).

## 기능 요구사항

| ID | 항목 | 내용 |
|---|---|---|
| FR-01 | 로그인·세션 | 사용자는 아이디와 비밀번호로 로그인하고 세션 쿠키로 인증 상태를 유지하며 로그아웃할 수 있어야 한다 |
| FR-02 | 사용자·역할 관리 | 원장은 사용자 계정을 생성·수정·비활성화하고 `원장`·`강사` 역할을 부여하며, 같은 캠퍼스 사용자의 비밀번호를 임시 비밀번호로 재설정할 수 있어야 한다. 모든 사용자는 현재 비밀번호를 확인한 뒤 자기 비밀번호를 바꿀 수 있어야 한다. 원장이 정한 비밀번호(새 계정·재설정·설정값으로 만든 최초 원장)로 로그인한 사용자는 새 비밀번호를 정하기 전에는 다른 기능을 쓸 수 없다. 역할에는 포털 계정인 `학생`·`학부모`도 있다. 포털 계정은 계정 관리 화면이 아니라 학생 관리 탭에서 발급하고(FR-48), 변경 강제 규칙은 포털 계정에도 그대로 적용된다([DCR-024](./work/20260922-mathdesk-baseline/DCR-024-학생-학부모-포털.md)) |
| FR-03 | 캠퍼스 관리와 스코프 | 캠퍼스를 등록하고 사용자에게 접근 가능한 캠퍼스를 지정하며, 모든 조회·변경은 현재 캠퍼스 스코프로 제한되어야 한다. [상세](#fr-03-상세) |
| FR-04 | 연동 설정 | 원장은 알리고 계정·발신번호, 카카오 발신프로필, LLM 엔드포인트·모델을 설정하고 연결 상태를 확인할 수 있어야 한다 |
| FR-05 | 학생 관리 | 학생의 이름, 학교, 학년, 학생 연락처, 재원 상태, OMR 수험번호, 성적(자유 텍스트 500자 이내, 비고로 쓴다)을 등록·수정·검색하고 퇴원 처리할 수 있어야 한다. 학생 목록은 학생 연락처·학부모 연락처·성적을 함께 보인다([DCR-014](./work/20260922-mathdesk-baseline/DCR-014-학부모-연락처와-성적-칸.md)). 학교는 FR-43에 등록된 학교 중에서 고르며 비워 둘 수 있고, 등록된 학교가 없으면 학교 탭에서 먼저 등록하라고 안내한다([DCR-015](./work/20260922-mathdesk-baseline/DCR-015-학교-관리와-학교-드롭다운.md)). [상세](#fr-05-상세) |
| FR-06 | 학부모 연락처 | 학생마다 보호자 관계·이름·연락처를 1건 이상 등록하고 통보 수신 대상 여부를 지정할 수 있어야 한다. 학생 등록·수정 화면에서 학부모 연락처 1건을 함께 입력·수정·삭제한다 — 새로 만들면 관계 "학부모"·통보 대상, 이미 있는 보호자는 번호만 바꾸고 관계·이름은 그대로, 비우면 그 보호자를 지운다([DCR-014](./work/20260922-mathdesk-baseline/DCR-014-학부모-연락처와-성적-칸.md)). 학생을 등록·수정할 때 같은 캠퍼스의 다른 학생이 같은 학부모 번호(숫자만 비교)를 가지면 "학부모 연락처가 ○○○ 학생과 같습니다. 형제가 아니면 번호를 확인하세요"를 안내한다. 저장은 막지 않으며 학생 목록의 학부모 연락처 칸과 [수정] 창에도 같은 안내가 보인다([DCR-026](./work/20260922-mathdesk-baseline/DCR-026-형제-연결-확인과-같은-학부모-번호-안내.md)) |
| FR-07 | 반 관리 | 반명, 학년, 담당 강사, 요일·시작 시각 시간표(수업 길이가 같아 종료 시각은 입력하지 않는다), 활성 여부를 등록·수정할 수 있어야 한다. 강사는 자기가 담당한 반의 반명·학년·시간표를 수정할 수 있고, 반 등록·담당 강사 지정·활성 여부 변경·삭제는 원장만 한다. 원장은 반을 활성 여부와 관계없이 반 목록이나 [수정] 창의 [삭제]로 바로 삭제할 수 있다([DCR-016](./work/20260922-mathdesk-baseline/DCR-016-반-바로-삭제.md)). [삭제 규칙](#fr-05-상세) |
| FR-08 | 수강 등록 | 학생을 반에 배정·해제하고 배정 기간 이력을 보존하여 과거 수업일의 소속 반을 재현할 수 있어야 한다 |
| FR-09 | 출결 입력 | 학생별 출결을 `미확인`·`출석`·`지각`·`결석`·`조퇴` 중 하나로 기록하고 사유를 입력하며, 확정과 편집의 2단계로 잠글 수 있어야 한다. [상세](#fr-09-상세) |
| FR-10 | 반 단위 수업 기록 | 수업일마다 1~4교시 진도, 오늘의 과제, 수업 영상 링크, 강사 첨언을 반 단위로 1건 기록할 수 있어야 한다 |

#### FR-03 상세

- 모든 도메인 엔터티(학생, 반, 수업 기록, 시험, 메시지 로그)는 하나의 캠퍼스에 귀속된다.
- 사용자는 접근 가능한 캠퍼스 목록을 가지며 상단 바에서 현재 캠퍼스를 전환한다.
- 서버는 요청마다 현재 캠퍼스와 사용자 권한을 검사하고, 권한 밖 자원 요청에는 데이터 존재 여부를 노출하지 않는 오류를 반환한다.
- 역할별 권한: 원장은 캠퍼스 내 전체 자원과 설정에 접근한다. 강사는 담당 반과 그 반 소속 학생에 접근하며(담당 반은 반명·학년·시간표 수정 가능) 연동 설정과 사용자 관리는 조회·변경할 수 없다. 학생·학부모(포털 계정)는 포털 API만 쓸 수 있고 그 밖의 모든 API는 거부된다. 학생 계정은 본인 1명, 학부모 계정은 연결된 자녀만 본다([DCR-024](./work/20260922-mathdesk-baseline/DCR-024-학생-학부모-포털.md)).

#### FR-05 상세

- OMR 수험번호는 8자리 숫자이며 자리별 허용 범위를 만족해야 한다: 1열 `1~9`, 2열 `0~9`, 3열 `0~5`, 4열 `0~9`, 5열 `0~9`, 6열 `0~9`, 7열 `0~2`, 8열 `0~9`.
- 수험번호는 캠퍼스 안에서 유일해야 한다.
- 재원 상태는 `재원`·`휴원`·`퇴원`이며, 퇴원 학생은 기본 목록에서 제외되지만 과거 기록은 **삭제하기 전까지** 보존된다.
- **삭제(FR-05·FR-07, [DCR-006](./work/20260922-mathdesk-baseline/DCR-006-퇴원-비활성-학생과-반의-삭제.md)·[DCR-012](./work/20260922-mathdesk-baseline/DCR-012-재원-학생의-바로-삭제.md)·[DCR-013](./work/20260922-mathdesk-baseline/DCR-013-학생-즉시-삭제.md)·[DCR-016](./work/20260922-mathdesk-baseline/DCR-016-반-바로-삭제.md)):** 원장은 학생을 재원 상태와 관계없이, 반을 활성 여부와 관계없이 삭제할 수 있다. 학생과 반 모두 [삭제]를 누르는 즉시 확인 없이 삭제된다. 삭제하면 그 기록이 함께 삭제된다 — 학생은 보호자·반 배정·일일 기록·시험 응시·매칭된 답안지 판독·발송 내역·상담 기록, 반은 시간표·반 배정·그 반의 수업과 그 수업의 모든 학생 일일 기록. 반에 연결된 시험과 결과는 남기고 반 연결만 끊는다. OMR 원본 PDF 파일은 남긴다. 학생을 삭제하면 그 학생과 포털 계정(FR-48)의 연결을 지우고, 연결이 남지 않은 포털 계정은 세션·캠퍼스 연결과 함께 삭제한다. 그 계정이 남긴 감사 로그는 행위자만 비우고 남긴다([DCR-024](./work/20260922-mathdesk-baseline/DCR-024-학생-학부모-포털.md)).

#### FR-09 상세

- 입력 전 기본값은 `미확인`이며 집계에서 `출석`으로 취급하지 않는다.
- 선택된 상태를 다시 누르면 `미확인`으로 해제된다.
- `확인`을 누르면 해당 반·날짜의 출결이 확정되어 읽기 전용이 되고, `편집`을 누르면 다시 수정할 수 있다.
- 등원 인원은 `출석 + 지각 + 조퇴`로 계산한다.
- 확정·해제 시각과 수행자를 기록한다.

#### FR-12 상세

- 재검사 대상 판정 기준 등급은 설정값이며 기본값은 `B` 이하다.
- 판정 대상은 해당 학생의 직전 수업일 과제 등급이며, 결석으로 등급이 없으면 대상이 아니다.
- 화면에는 `직전 <등급> · <직전 수업일>` 형식으로 근거를 함께 표시한다.
- `합격`·`불합격` 선택은 표 일괄 저장을 기다리지 않고 즉시 저장한다.

#### FR-13 상세

- 테스트명은 일일 입력의 "오늘 진도" 카드에서 반 단위로 입력하고 [메모 저장]으로 저장한다(100자 이내, 비울 수 있음). 만점은 입력하지 않는다.
- 테스트명은 그날 반 공통 값으로 문자·리포트 카드(FR-18)와 회차별 추이(FR-24)에 쓰인다. 점수는 기존대로 표에서 학생별로 입력한다([DCR-019](./work/20260922-mathdesk-baseline/DCR-019-테스트명-입력과-문자-리포트-공통-구획.md)).

#### FR-14 상세

| 저장 단위 | 대상 데이터 | 저장 시점 |
|---|---|---|
| 표 일괄 저장 | 출결 상태·사유, 과제 등급, 테스트 점수, 학생별 코멘트(FR-44) | 표 하단 저장 버튼 |

| 메모 저장 | 교시별 진도, 오늘의 과제, 영상 링크, 첨언 | 반 단위 메모 저장 버튼 |

- 한 단위의 저장이 다른 단위의 미저장 편집 내용을 덮어쓰지 않아야 한다.
- 미저장 내용이 있는 상태에서 반·날짜·학생을 전환하면 경고한다.

#### FR-15 상세

| KPI | 정의 |
|---|---|
| 총 재원생·반 현황 | 현재 캠퍼스의 재원 상태 학생 수와 활성 반 수 |
| 선택 반 등원 현황 | 선택한 반·날짜의 `출석 + 지각 + 조퇴` / 재적 인원 |
| 금주 과제 완수율 | 금주 과제 등급 중 기준 등급 이상 비율, 전주 대비 %p 증감, 미제출 건수, 재검사 대상 인원 |

- 미제출은 과제 등급 `F`로 판정한다. 별도의 제출 여부 필드를 두지 않는다.
| 주간 테스트 종합 평균 | 금주 테스트 점수 평균, 표본 수 N, 최고점(동점 인원), 최저점 |

- 표본이 없으면 값 대신 `—`를 표시한다.

#### FR-18 상세

메시지 본문은 다음 구획을 이 순서로 포함한다. 반 공통 구획을 위에, 학생 개별 구획을 아래에 둔다([DCR-017](./work/20260922-mathdesk-baseline/DCR-017-학생별-코멘트와-문자-공통-개별-구조.md)). 테스트명은 반 공통, 점수는 학생 개별에 둔다([DCR-019](./work/20260922-mathdesk-baseline/DCR-019-테스트명-입력과-문자-리포트-공통-구획.md)).

1. 제목(학생명 + 학습피드백), 학원명·강사명 인사말, 수업일
2. 반 공통
   - `■ 수업진도` — 교시별 항목
   - `■ 오늘의 테스트` — 테스트명(FR-13)
   - `■ 오늘의 과제`
   - `■ 수업 영상 링크`
   - `■ 선생님 코멘트` — 강사 첨언(일일 입력 화면의 [선생님 코멘트 (문자 공통)])
3. 학생 개별
   - `■ 출결`
   - `■ 과제피드백` — 등급과 등급 문구
   - `■ 테스트 점수` — 학생 점수, 반 평균(테스트명이 없어도 점수가 있으면 포함)
   - `■ 개별 코멘트` — 학생별 코멘트(FR-44)

- 데이터가 없는 구획은 본문에서 생략한다.
- 본문은 저장하지 않고 렌더 시점에 생성하며, 발송할 때만 스냅샷을 발송 로그에 남긴다.

#### FR-23 상세

- 발송은 `테스트 모드`와 `실발송 모드`를 가지며 기본값은 테스트 모드다. 테스트 모드에서는 외부 API를 호출하지 않고 로그만 남긴다.
- 본문 길이에 따라 SMS·LMS를 자동 선택하고 이미지 첨부 시 MMS를 사용한다.
- 발송 로그는 수신자, 채널, 요청 시각, 결과 상태, 실패 사유, 본문 스냅샷, 과금 단위를 보존한다.
- 잔여 발송 가능량(장문·단문·이미지)과 조회 시각을 표시하고 수동 새로고침할 수 있다.

#### FR-27 상세

정규화 결과는 `{pages[], blocks[](text|equation|image|table), page_images[]}` 구조를 가진다.

| 포맷 | 처리 | 제약 |
|---|---|---|
| `.hwpx` | OWPML XML 직접 파싱 | 없음 |
| `.hwp` | 텍스트·표·수식 스크립트 추출 | 배포 금지·암호 설정 파일은 오류로 안내 |
| `.pdf` | 텍스트 레이어와 좌표, 페이지 이미지 추출, 텍스트가 없으면 이미지 경로로 폴백 | — |
| 이미지 | 페이지 이미지로 취급하고 이미지 경로로 처리 | 정확도는 화질에 의존 |

#### FR-33 상세

판독 대상 필드와 판정 규칙은 다음과 같다.

| 필드 | 구성 | 판정 |
|---|---|---|

| 문형 | 홀수형·짝수형 | 단일 마킹 |

#### FR-45 상세

- 탭마다 주소가 있다: [반별 정보] `/daily`, [학생별 정보] `/daily/students`. 반·날짜·학생은 주소 쿼리(`class`·`date`·`student`)에 들어 있어 탭 전환·새로 고침·뒤로 가기·대시보드 링크(`/daily?class=&date=`)에서 유지된다.
- [반별 정보]에 저장하지 않은 입력이 있을 때 탭을 바꾸면 반·날짜 전환과 같은 경고를 띄운다(FR-14 상세).
- 학생 선택은 선택한 날짜에 배정된 학생 목록이며, 처음 열면 첫 학생이 선택된다. 배정된 학생이 없으면 [반별 정보]와 같은 안내를 보인다.
- 표의 열과 내용은 다음과 같다. 입력·수정은 하지 않는다(날짜 링크로 [반별 정보]에서 고친다).

| 열 | 내용 |
|---|---|
| 날짜 | `MM/DD(요일)`. 누르면 [반별 정보] 탭이 그 날짜로 열린다 |
| 출결 | 상태(`출석`·`지각`·`결석`·`조퇴`·`미확인`)와 사유. 상태 색은 [반별 정보]의 출결 버튼 색과 같다 |
| 이전 과제 재검사 | `직전 <등급> · <직전 수업일>`과 결과(`합격`·`불합격`·미입력). 대상이 아니면 `—` |
| 과제피드백 | 등급(`A+`~`F`) |
| 테스트 | 테스트명, `점수 / 반평균`. 점수가 없으면 `—` |
| 코멘트 | 학생별 코멘트(FR-44) |

- 표 위에 두 요약을 보인다: **출석 N / M회**(등원 `출석+지각+조퇴` 수 / 표에 보이는 수업 수), **테스트 평균 X점 (N회)**. 표본이 없으면 `—`.
- "기록이 있는 수업"은 그 세션에 학생 기록(출결·등급·점수·재검사·코멘트 중 하나라도 저장), 반 메모(진도·과제·영상·선생님 코멘트·테스트명), 출결 확정 중 하나라도 있는 세션이다. 조회만 해서 생긴 빈 세션은 수업으로 세지 않는다([DES-05 상세](./design.md#des-05-상세)).
- 학생이 그 세션에 배정되어 있지 않았던 날(배정 시작 전·종료 후)은 표에 넣지 않는다.
- **이미지 저장·복사:** 보이는 내용(학생 이름부터 표 끝까지)을 이미지 파일로 저장하고 클립보드에 복사할 수 있다. 학생 선택 옆에 [이미지 복사]·[이미지 저장] 버튼을 둔다. 이미지는 학원 브랜드(FR-40)를 따르고 웹 테마(FR-41)를 따르지 않으며 리포트 카드(FR-20)와 같은 디자인 토큰을 쓴다(NFR-18). 내용은 그 시점 화면의 학생·반·선택 날짜·회차 수와 같다. 파일명은 `학생별정보-<학생명>-<선택 날짜>.png`. 구성은 위에서 아래로 ① 머리말(브랜드 색 배경: 학원명 또는 로고, `<학생명> 학습 기록`, `<반명> · <선택 날짜>까지 최근 <N>회`) ② 요약 타일(`출석 N / M회`, `테스트 평균 X점 (N회)`, 표본 없으면 `—`) ③ 화면과 같은 6열 표(기록이 없으면 "선택한 날짜까지 기록이 있는 수업이 없습니다") — [DCR-021](./work/20260922-mathdesk-baseline/DCR-021-학생별-정보-이미지-저장.md)
- 강사는 담당 반의 학생만 볼 수 있다(FR-04의 역할 스코프 그대로). [DCR-020](./work/20260922-mathdesk-baseline/DCR-020-일일-입력-학생별-정보-탭과-수업일-달력.md)

#### FR-46 상세

- 날짜 칸은 선택한 날짜(`YYYY-MM-DD`)를 보이는 버튼이며, 누르면 그 달의 달력이 열린다. 달력에는 이전 달·다음 달 이동, [오늘], 요일 머리(월~일)가 있다. 날짜를 누르면 선택되고 달력이 닫힌다.
- 굵게 표시되는 수업일 = 시간표 요일에 해당하는 날 ∪ 기록이 있는 날(FR-45 상세의 정의). 기록이 있는 날은 아래에 작은 점을 더 찍어 보강 수업·시간표 밖 기록도 구분된다.
- 반을 바꾸면 달력도 그 반 기준으로 바뀐다. 시간표가 없는 반은 기록이 있는 날만 굵다.
- 선택한 날짜와 오늘은 각각 다른 테두리·배경으로 구분한다.
- 저장하지 않은 입력이 있을 때 날짜를 고르면 기존과 같이 경고한다(FR-14 상세).
- 두 탭이 같은 날짜 칸을 쓴다. [학생별 정보]에서는 고른 날짜가 표의 끝(최신) 날짜가 된다. [DCR-020](./work/20260922-mathdesk-baseline/DCR-020-일일-입력-학생별-정보-탭과-수업일-달력.md)

#### FR-47 상세

- 대상은 `GET /daily`와 같은 기준(그 날짜의 수강 등록)으로 정한다. 보낼 연락처가 하나도 없는 학생은 빠지고 확인 창에 이름이 나온다.
- 같은 세션에 성공(접수·대체 발송) 로그가 있는 학생은 "이미 보냄"으로 표시하고 기본 제외한다(체크로 포함). 테스트 모드 로그와 실패 로그는 세지 않는다.
- 학생 ID 순서로 한 학생씩 보낸다. 서버가 재시작되면 작업은 `queued`로 돌아가 아직 보내지 않은 학생부터 이어서 보내고, 로그가 남은 학생은 건너뛴다.
- 결과는 학생마다 성공(접수)·실패·테스트와 실패 사유, 작업 전체 요약(대상·성공·실패·건너뜀)이다.
- [실패만 다시 보내기]는 실패한 학생만 대상으로 같은 조건의 새 작업을 만든다. 학생 1명 발송의 실패 건에도 [다시 보내기]를 둔다.
- 알림톡 템플릿을 고르면 전원 알림톡으로 보내고 실패 시 FR-38대로 학생마다 문자 대체한다.
- 한 작업의 대상은 최대 500명이다. 넘으면 거부하고 안내한다. [DCR-023](./work/20260922-mathdesk-baseline/DCR-023-반-단위-일괄-발송.md)

#### FR-48 상세

- **전제:** 학생 계정은 학생 연락처가 있어야 발급할 수 있다. 없으면 버튼을 비활성화하고 "학생 연락처를 먼저 등록하세요"를 보인다. 학부모 계정은 보호자 연락처(FR-06)마다 발급할 수 있다(현재 화면은 보호자 1건).
- **전화번호 규칙:** 숫자만 남긴 10~11자리. 그 외는 발급을 거부하고 안내한다.
- **한 번호 = 계정 하나:** 같은 로그인 ID의 계정이 이미 있으면 ① 학부모 계정이고 발급하려는 것도 학부모 계정이면 새로 만들지 않고 그 계정에 이 학생을 연결한다(형제). 단 **바로 연결하지 않는다** — 화면은 그 계정에 연결된 학생 이름과 번호를 보이는 확인 카드를 띄우고, 원장이 [형제가 맞습니다, 연결]을 눌러야 연결한다. 서버는 확인 표시가 없는 요청을 거부한다(409). 발급 전부터 [수정] 창의 학부모 계정 줄에 "이 번호는 ○○○ 학생의 학부모 계정과 같습니다"를 안내한다([DCR-026](./work/20260922-mathdesk-baseline/DCR-026-형제-연결-확인과-같은-학부모-번호-안내.md)) ② 그 밖의 조합(학생 번호가 이미 학부모 계정인 경우, 학생 계정에 다른 학생을 연결하려는 경우, 원장·강사 계정과 같은 번호)은 거부하고 어떤 계정과 겹치는지 안내한다.
- **발급 상태:** 학생 목록과 [수정] 창은 학생 계정·학부모 계정 각각의 상태를 보인다 — `미발급`, `변경 대기`(발급 뒤 최초 비밀번호 변경 전, 남은 날짜 포함), `사용 중`, `만료`(변경 대기가 7일을 넘김), `비활성`(퇴원).
- **발급 유효기간:** 발급·재발급 뒤 7일(설정값) 안에 최초 비밀번호 변경이 없으면 로그인을 거부하고 "발급 기간이 지났습니다. 학원에 재발급을 요청하세요"를 보인다. 원장·강사 계정에는 적용하지 않는다(기존 동작 유지).
- **재발급:** [재발급]은 비밀번호를 로그인 ID로 되돌리고 변경 대기 상태로 만들며 그 계정의 로그인을 모두 끊는다. 비밀번호를 잊었거나 선점이 의심될 때 쓴다. 로그인 ID는 발급 시점 번호로 고정되며 연락처를 바꿔도 따라가지 않는다. 번호를 바꾸려면 새 번호로 다시 발급한다(기존 계정은 그 학생과의 연결이 끊기고, 연결이 0이 되면 삭제된다).
- **퇴원·삭제 연동:** 학생이 `퇴원`이 되면 그 학생에 연결된 계정 중 재원·휴원 학생 연결이 하나도 남지 않는 계정을 비활성화한다(로그인 불가). 재원으로 되돌리면 다시 활성화한다. 학생을 삭제하면(FR-05 상세) 연결을 지우고, 연결이 0이 된 계정을 세션과 함께 삭제한다.
- **감사:** 발급·재발급·연결 추가·자동 비활성·삭제는 감사 로그에 남긴다(대상 계정 ID·학생 ID, 전화번호는 쓰지 않음).
- **원장만:** 강사는 발급 상태를 볼 수만 있다. 발급·재발급 요청은 403.

#### FR-49 상세

- **본인 데이터만:** 다른 학생의 이름·점수·출결은 어떤 화면에도 나오지 않는다. 반 평균(FR-13·FR-24)은 문자에 이미 들어가므로 허용한다. 성적 비고(`score_note`), 반 통계(FR-25), 대시보드(FR-15)는 보이지 않는다.
- **노출 시점:** 강사가 저장한 값은 즉시 보인다. 출결 확정 여부는 조건이 아니다. 출결이 `미확인`이면 "미확인"으로 보인다.
- **수업일 목록 범위:** 학생이 배정되어 있던 날 중 기록이 있는 세션(DES-05 상세의 정의)만.
- **기록 탭 구성([DCR-025](./work/20260922-mathdesk-baseline/DCR-025-포털-기록-달력과-추이-그래프.md)):** 위에서 아래로 ⓐ 달력 카드 — 월 달력에 그 학생의 기록이 있는 날을 굵게·점으로 표시하고 월을 넘길 수 있다. 최초 선택은 가장 최근 기록일(없으면 오늘, 안내 문구) ⓑ 선택한 날의 기록 — 그날 그 학생의 수업 기록 카드(FR-18 구획). 같은 날 반이 둘이면 두 장. 기록 없는 날은 "이 날은 기록이 없습니다" ⓒ 전체 기록 카드 — 한 줄에 하나씩(날짜·반·출결·과제 등급·테스트 점수/반평균·개별 코멘트 앞부분), 최신순 20회·[더 보기](최대 50). 한 줄을 누르면 달력이 그날로 이동·선택된다.
- **추이 탭 구성([DCR-025](./work/20260922-mathdesk-baseline/DCR-025-포털-기록-달력과-추이-그래프.md)):** 위에 회차별 선 그래프(관리 화면 FR-24와 같은 표시: 내 점수·반 평균, 가로축은 고른 회차 수만큼 칸, 전체 회차가 10 이하이면 10회 고정), 회차 선택 10회/20회. 아래 표는 그대로.
- **받은 문자:** 그 학생을 대상으로 성공(접수·대체 발송)한 발송의 본문 스냅샷. 같은 세션에 학생·학부모 두 번 보냈으면 본문이 같으므로 한 건으로 보인다. 테스트 모드 발송은 보이지 않는다.
- **기기:** 학부모는 휴대폰으로 쓴다. NFR-14의 조회 부류로 390px에서 완전히 사용 가능해야 하며 데스크톱에서도 쓸 수 있다. 밀집 입력 화면 규칙(NFR-13)은 적용되지 않는다.
- **셸:** 원장·강사 화면의 메뉴·캠퍼스 선택·설정은 보이지 않는다. 테마(FR-41)는 포털에도 적용된다.

| AC-38 | 주간 시간표 | 강사로 로그인하면 자기 담당 반의 수업만 격자에 나오고, 원장으로 로그인하면 모든 활성 반이 강사 이름과 함께 나오며 강사를 고르면 그 강사의 반만 남는다. 수업 길이를 바꾸면 블록 길이가 따라 바뀌고, 시간표 없는 반은 "시간표 미등록"에, 비활성 반은 어디에도 나오지 않는다 |
| AC-37 | 반 시간표 | 반 등록·수정에서 요일과 시작 시각으로 시간표를 입력·수정·삭제할 수 있고, 목록에 "요일 시작 시각"(예: `화 18:00 · 토 10:00`)으로 표시된다. 같은 요일·시작 시각을 두 번 넣으면 저장되지 않는다 |
| AC-36 | 학생·반 삭제 | 원장이 학생 [삭제]를 누르면 확인 없이 바로, 재원·휴원·퇴원 어느 상태든 그 학생의 기록이 모두 사라지고 다른 학생의 데이터는 바뀌지 않는다([DCR-012](./work/20260922-mathdesk-baseline/DCR-012-재원-학생의-바로-삭제.md)·[DCR-013](./work/20260922-mathdesk-baseline/DCR-013-학생-즉시-삭제.md)). 원장이 반 목록 행이나 [수정] 창의 [삭제]를 누르면 확인 없이 바로, 활성·비활성 어느 반이든 그 반의 시간표·반 배정·수업·일일 기록이 사라지고 연결된 시험과 결과는 남으며 다른 반의 데이터는 바뀌지 않는다. 강사 화면에는 반 [삭제]가 없고 API도 거부된다([DCR-016](./work/20260922-mathdesk-baseline/DCR-016-반-바로-삭제.md)) |
| AC-29 | 로그인 시도 제한 | 잘못된 비밀번호로 임계 횟수(기본 10회) 연속 실패하면 올바른 비밀번호도 잠금 시간(기본 3분) 동안 거부되고, 잠금 시간이 지나면 다시 허용되며 잠금 사건이 감사 로그에 남는다 |
