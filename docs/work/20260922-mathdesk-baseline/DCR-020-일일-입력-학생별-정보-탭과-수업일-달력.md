## 요약

- 변경 분류: **요구사항 변경 + 공개 인터페이스 추가** — 일일 수업 & 성적 입력 화면을 **[반별 정보]**·**[학생별 정보]** 두 탭으로 나누고(FR-45 신설), 학생별 정보 탭에 한 학생의 날짜별 출결·이전 과제 재검사·과제피드백·테스트·코멘트를 읽기 전용으로 보인다. 날짜 선택을 **월 달력**으로 바꾸고 수업일을 굵게 표시한다(FR-46 신설). 조회 전용 REST 2건을 더한다. 데이터 모델 변경은 없다.
- 변경 요지: ① 기존 화면 내용은 그대로 [반별 정보] 탭이 된다. ② [학생별 정보] 탭은 반·날짜 머리말을 공유하고, 선택한 날짜에 배정된 학생 중 하나를 골라 **그 날짜까지의 최근 수업 20회**를 날짜별 표로 보인다. ③ 머리말의 날짜 칸은 월 달력 팝오버가 되며, **수업일(시간표 요일에 해당하는 날 ∪ 기록이 있는 날)을 굵게**, 기록이 있는 날은 아래에 점을 찍는다.
- 사용자 결정 필요: 없음(의견 요청 항목은 [대안 분석](#대안-분석)과 [제안](#제안-기준선-v21)에 Claude 추천안으로 결정해 두었다. 승인 또는 수정 요청으로 바꿀 수 있다).
- 사용자 재승인 결과: **승인 (2026-10-11)** — 기준선 `v20` → `v21` 발행

## 변경 사유와 증거

- **계기:** 사용자 요청(2026-10-11) — "현재는 반별·날짜별 정보만 보인다. 이 페이지를 [반별 정보] 탭으로 두고 [학생별 정보] 탭을 더해 학생별·날짜별 출결/이전과제재검사/과제피드백/테스트/코멘트를 보이고 싶다. 달력에서 수업이 있는 날짜를 굵게 표시해 어느 날이 수업일인지 알게 해 달라."
- **확인한 사실:**
  1. 일일 입력 화면(`apps/web/src/pages/DailyPage.tsx`)은 단일 라우트 `/daily`이며 머리말에 반 `Select`와 **브라우저 기본 `<input type="date">`** 가 있다. 기본 날짜 입력은 특정 날짜를 굵게 표시할 수 없으므로 달력 요구는 **저장소 소유 달력 컴포넌트**를 요구한다. 설치된 달력 라이브러리는 없다(`package.json`).
  2. 탭 패턴은 학생/반 관리의 `ManageTabs`(중첩 라우트 `/students`·`/students/classes`·`/students/schools`, `NavLink` + `Outlet`)가 이미 있다. 탭마다 주소가 있어 새로 고침·뒤로 가기에 탭이 유지된다.
  3. 대시보드는 `/daily?class=&date=`로 반·날짜를 주소에 넘긴다(TASK-74). 일일 화면은 이 쿼리를 초기값으로만 읽고 이후 변경은 컴포넌트 상태에만 둔다.
  4. 반의 시간표 요일은 `GET /classes` 응답의 `schedules[{weekday, start_time}]`(0=월 … 6=일)에 이미 들어 있어 **시간표 기준 수업 요일은 추가 API 없이** 화면에서 알 수 있다.
  5. `GET /daily`는 조회만 해도 `class_session` 행을 만든다(`_get_or_create_session`, DES-05 "첫 입력 시 생성"의 구현). 따라서 **세션 행의 존재는 수업이 있었다는 뜻이 아니다.** 달력·이력에서 "기록이 있는 날"은 학생 기록·메모·진도·출결 확정 중 하나가 있는 세션으로 정의해야 한다.
  6. 학생 기록(`student_daily_record`)은 표 저장에서 **편집된 학생만** 만들어진다. 그날 아무것도 입력되지 않은 학생은 기록 행이 없으므로, 학생별 이력의 행은 학생 기록이 아니라 **기록이 있는 세션**을 기준으로 만들고 그 학생의 값이 없으면 빈 값으로 보여야 한다.
  7. 재검사 대상 판정(직전 등급·직전 수업일)은 저장값이 아니라 조회 시 계산한다(DES-05 상세). 학생별 이력에서도 같은 규칙으로 날짜마다 직전 등급을 계산해야 한다.
  8. 기존 학생 이력 API `GET /stats/students/{id}`(DCR-018)는 **테스트 점수가 있는 날만** 회차로 삼고 사유·재검사·코멘트·테스트명이 없어 이 요구에 맞지 않는다(아래 대안 B).
  9. 선택 날짜에 배정된 학생 목록은 `GET /daily` 응답의 `records[].name`이 이미 준다. `GET /classes/{id}/enrollments`는 학생 이름이 없다.
  10. 일일 화면 테스트(`DailyPage.test.tsx`)는 `getByLabelText('날짜')`의 값을 `toHaveValue('2026-09-18')`로 확인한다. 날짜 칸을 바꾸면 이 단언을 새 컴포넌트에 맞게 고쳐야 한다.
- **보류한 구현:** 없음(구현 시작 전).

## 제안 (기준선 `v21`)

### 요구사항

- **FR-45(신설) 일일 입력 탭과 학생별 정보:** 일일 수업 & 성적 입력 화면은 [반별 정보]·[학생별 정보] 두 탭으로 나뉜다. 반·날짜 선택은 두 탭 공통 머리말에 있고 탭을 오가도 유지된다. [반별 정보]는 기존 화면(FR-09~FR-14, FR-44) 그대로다. [학생별 정보]는 선택한 날짜에 그 반에 배정된 학생 중 하나를 골라, **선택한 날짜까지 기록이 있는 그 반 수업 최근 20회**를 최신 날짜부터 날짜별로 **읽기 전용** 표로 보인다. 상세는 [FR-45 상세](#fr-45-상세).
- **FR-46(신설) 수업일 달력:** 일일 입력 머리말의 날짜 선택은 월 달력이다. 달력은 선택한 반의 **수업일을 굵게** 표시한다. 수업일은 반 시간표(FR-07)의 요일에 해당하는 날과 기록이 있는 날의 합집합이다. 기록이 있는 날은 날짜 아래 점으로 구분한다. 상세는 [FR-46 상세](#fr-46-상세).

#### FR-45 상세

- 탭마다 주소가 있다: [반별 정보] `/daily`, [학생별 정보] `/daily/students`. 반·날짜·학생은 주소 쿼리(`class`·`date`·`student`)에 들어 있어 탭 전환·새로 고침·뒤로 가기·대시보드 링크(`/daily?class=&date=`)에서 유지된다.
- [반별 정보]에 저장하지 않은 입력이 있을 때 탭을 바꾸면 반·날짜 전환과 같은 경고를 띄운다(FR-14 상세).
- 학생 선택은 선택한 날짜에 배정된 학생 목록이며, 처음 열면 첫 학생이 선택된다. 배정된 학생이 없으면 [반별 정보]와 같은 안내를 보인다.
- 표의 열과 내용은 다음과 같다. 입력·수정은 하지 않는다.

| 열 | 내용 |
|---|---|
| 날짜 | `MM/DD(요일)`. 누르면 [반별 정보] 탭이 그 날짜로 열린다 |
| 출결 | 상태(`출석`·`지각`·`결석`·`조퇴`·`미확인`)와 사유. 상태 색은 [반별 정보]의 출결 버튼 색과 같다 |
| 이전 과제 재검사 | `직전 <등급> · <직전 수업일>`과 결과(`합격`·`불합격`·미입력). 대상이 아니면 `—` |
| 과제피드백 | 등급(`A+`~`F`) |
| 테스트 | 테스트명, `점수 / 반평균`. 점수가 없으면 `—` |
| 코멘트 | 학생별 코멘트(FR-44) |

- 표 위에 두 요약을 보인다: **출석 N / M회**(등원 `출석+지각+조퇴` 수 / 표에 보이는 수업 수), **테스트 평균 X점 (N회)**. 표본이 없으면 `—`.
- "기록이 있는 수업"은 그 세션에 학생 기록(출결·등급·점수·재검사·코멘트 중 하나라도 저장), 반 메모(진도·과제·영상·선생님 코멘트·테스트명), 출결 확정 중 하나라도 있는 세션이다. 조회만 해서 생긴 빈 세션은 수업으로 세지 않는다.
- 학생이 그 세션에 배정되어 있지 않았던 날(배정 시작 전·종료 후)은 표에 넣지 않는다.
- 강사는 담당 반의 학생만 볼 수 있다(FR-04의 역할 스코프 그대로).

#### FR-46 상세

- 날짜 칸은 선택한 날짜(`YYYY-MM-DD`)를 보이는 버튼이며, 누르면 그 달의 달력이 열린다. 달력에는 이전 달·다음 달 이동, [오늘], 요일 머리(월~일)가 있다. 날짜를 누르면 선택되고 달력이 닫힌다.
- 굵게 표시되는 수업일 = 시간표 요일에 해당하는 날 ∪ 기록이 있는 날(FR-45 상세의 정의). 기록이 있는 날은 아래에 작은 점을 더 찍어 보강 수업·시간표 밖 기록도 구분된다.
- 반을 바꾸면 달력도 그 반 기준으로 바뀐다. 시간표가 없는 반은 기록이 있는 날만 굵다.
- 선택한 날짜와 오늘은 각각 다른 테두리·배경으로 구분한다.
- 저장하지 않은 입력이 있을 때 날짜를 고르면 기존과 같이 경고한다(FR-14 상세).
- 두 탭이 같은 날짜 칸을 쓴다. [학생별 정보]에서는 고른 날짜가 표의 끝(최신) 날짜가 된다.

#### 인수 조건

- **AC-45(신설) 학생별 정보 탭:** ① 일일 입력 화면에 [반별 정보]·[학생별 정보] 탭이 있고 처음에는 [반별 정보]가 열려 기존 표·메모 카드가 그대로 보인다. ② 같은 반에서 세 수업일에 각각 출결·과제 등급·점수·코멘트를 저장한 뒤 [학생별 정보]에서 그 학생을 고르면, 세 날짜가 최신 순으로 보이고 각 행에 저장한 출결(색·사유)·등급·테스트명과 `점수 / 반평균`·코멘트가 있다. 그 학생에게 아무것도 입력하지 않은 수업일(다른 학생 기록은 있음)도 행이 있고 값이 빈 채로 보인다. 조회만 한 날은 행이 없다. ③ 직전 수업 등급이 `B`인 날의 재검사 칸에 `직전 B · MM/DD`와 결과가 보이고, 직전 등급이 `A`인 날은 `—`다. ④ 날짜를 누르면 [반별 정보] 탭이 그 날짜로 열린다. ⑤ 반·날짜를 고른 채 탭을 오가도 선택이 유지되고, 주소에 반·날짜·학생이 있다. ⑥ 21회 이상 기록이 있으면 최근 20회만 보인다. ⑦ 강사가 담당하지 않는 반 학생의 이력 API는 403이다.
- **AC-46(신설) 수업일 달력:** ① 날짜 칸을 누르면 그 달의 달력이 열리고, 시간표가 `월·목`인 반이면 그 달의 모든 월·목이 굵다. ② 시간표에 없는 토요일에 기록을 저장하면 그 토요일이 굵어지고 아래 점이 생기며, 기록이 있는 월요일에도 점이 있다. ③ 조회만 한 날은 굵어지지도 점이 생기지도 않는다. ④ 날짜를 누르면 선택되어 `GET /daily`가 그 날짜로 조회되고 달력이 닫힌다. ⑤ 반을 바꾸면 굵은 요일이 그 반의 시간표로 바뀐다. ⑥ 저장하지 않은 입력이 있을 때 날짜를 고르면 경고가 뜨고 취소하면 날짜가 바뀌지 않는다.

### 설계

- **데이터 모델:** 변경 없음. 마이그레이션 없음.
- **DES-05 상세에 "기록이 있는 세션" 정의 추가:** `class_session`에 `student_daily_record`가 1건 이상 있거나, `class_session_progress`가 있거나, `homework`·`video_url`·`teacher_note`·`test_name` 중 하나가 NULL이 아니거나, `attendance_confirmed_at`이 있으면 기록이 있는 세션이다. 조회로 생긴 빈 세션을 수업으로 세지 않기 위한 규칙이며, 아래 두 REST가 공유한다(`daily.py`의 헬퍼 하나).
- **REST 추가(일일 기록, 조회 전용, 권한은 `_visible_class` 그대로):**
  - `GET /daily/calendar?class_id=&month=YYYY-MM` → `{ "recorded_dates": ["2026-10-02", ...] }` — 그 달의 기록이 있는 세션 날짜. 시간표 요일은 포함하지 않는다(화면이 `GET /classes`의 `schedules`로 안다). `month` 형식이 틀리면 422.
  - `GET /daily/history?class_id=&student_id=&to=YYYY-MM-DD&limit=20` → 아래 형식. `to`까지(포함) 기록이 있는 세션 중 그 학생이 배정되어 있던 날만, 최신 날짜부터 `limit`개. `limit`은 1~50, 기본 20. 그 반에 배정 이력이 없는 학생은 403.

```jsonc
// GET /daily/history?class_id=3&student_id=12&to=2026-10-11&limit=20
{ "student": { "id": 12, "name": "김나윤" },
  "klass": { "id": 3, "name": "고1 인A" },
  "rows": [
    { "date": "2026-10-10", "attendance_status": "late", "attendance_reason": "버스 지연",
```

  - 행의 재검사 판정은 `GET /daily`와 같은 규칙(`_is_recheck_target`, 그 반에서 그 날짜 이전 가장 최근의 등급)으로 날짜마다 계산한다. `class_average`는 그 세션에 점수가 있는 모든 학생의 평균(`GET /daily`의 `summary.test_average`와 같은 식).
  - 응답 모델은 `DailyOut`과 분리한다(`HistoryOut`). 기존 엔드포인트의 계약은 바뀌지 않는다.
- **화면 구조(웹):**
  - 라우트 `/daily`를 중첩 라우트로 바꾼다: `DailyLayout`(머리말 반·날짜·탭 `NavLink`, `Outlet`) 아래 `index` = 기존 `DailyPage` 본문([반별 정보]), `students` = 새 `StudentDailyPage`([학생별 정보]). 탭 컴포넌트는 `ManageTabs`와 같은 방식이되 `NavLink`의 `to`에 현재 쿼리를 그대로 붙인다.
  - 반·날짜·학생 선택의 **정본은 주소 쿼리**(`useSearchParams`)다. 지금은 쿼리를 초기값으로만 읽는데, 탭 둘이 같은 선택을 공유해야 하므로 쿼리에 쓰기까지 한다. 저장하지 않은 입력 경고(`dirty`)는 [반별 정보]가 소유하므로, 레이아웃은 "이동 전 확인" 콜백을 자식에게 등록하게 한다(React 컨텍스트 하나). [학생별 정보]는 편집이 없어 등록하지 않는다.
  - [학생별 정보]: 학생 `Select`(`GET /daily` 응답 `records`의 이름, 쿼리 `student` 없으면 첫 학생) → `GET /daily/history` → 요약 `Stat` 2개 + 읽기 전용 `Table`. 출결 색은 `AttendanceButtons`의 `ATTENDANCE` 상수(라벨·톤)를 재사용하고, 날짜 칸은 `Link`(`/daily?class=&date=`)다.
- **공통 컴포넌트(DES-24에 추가):** `components/ui/month-calendar.tsx` — 입력: 선택 날짜, 보이는 달, 굵게 표시할 날짜 집합(또는 판정 함수), 점을 찍을 날짜 집합, 선택 콜백. 출력: 7열 격자 `<button>`들(`aria-pressed`로 선택, `aria-label`에 날짜와 `수업일`·`기록 있음` 표기). 외부 달력 라이브러리는 쓰지 않는다(ADR-010의 "공통 컴포넌트는 저장소 소유", NFR-13). 팝오버는 `DatePickerButton`으로 감싸고 바깥 클릭·Esc로 닫는다. 로컬 달력 기준 날짜 문자열은 `lib/date.ts`의 `isoDate` 계열을 쓴다(UTC 하루 어긋남 방지). 요일 변환은 `(getDay()+6)%7`로 `class_schedule.weekday`(0=월)에 맞춘다.
- **달력 데이터 흐름:** 수업 요일 = `classes.data`에서 선택 반의 `schedules[].weekday`. 기록 날짜 = 보이는 달이 바뀔 때 `GET /daily/calendar`. 저장(표·메모·재검사·확정) 성공 시 `['daily-calendar', classId, month]` 쿼리를 무효화해 점이 바로 바뀐다.
- **성능:** 달력은 달 하나(최대 31행) 집계, 이력은 세션 ≤ 50건 + 그 세션들의 기록 조인이다. 인덱스는 기존(`class_session.class_id`, `student_daily_record.session_id`)으로 충분하다.
- **메시지·리포트·통계:** 변경 없음.

## 검증 방법

- API(선행 테스트): `calendar` — 기록 있는 날만 나오고 조회만 한 날은 빠짐(AC-46 ③), 메모만·확정만 있는 세션도 포함, 달 경계, `month` 형식 오류 422, 강사 담당 외 403. `history` — 세션 기준 행 구성(그 학생 기록이 없는 날도 행, AC-45 ②), 배정 전·후 날짜 제외, `to` 이후 제외, 최신 순·`limit` 절단(AC-45 ⑥), 날짜별 재검사 판정(AC-45 ③), `class_average`가 `GET /daily`의 `summary.test_average`와 일치, 배정 이력 없는 학생·담당 외 403(AC-45 ⑦).
- 웹(선행 테스트): 탭 두 개와 초기 탭(AC-45 ①), 탭 전환 후 반·날짜 쿼리 유지(⑤), 학생 표 열·값·빈 행(②), 날짜 링크(④), `MonthCalendar` 굵은 날·점·선택 콜백(AC-46 ①②④), 반 변경 시 요일 변경(⑤), 미저장 경고(⑥), 기존 `DailyPage.test.tsx` 통과(날짜 단언만 수정).
- `npm run build`, API 전체 테스트.
- 공개 주소: 고1 인A(08-11~10-10 테스트 데이터)로 달력 굵은 날·점과 학생별 표를 눈으로 확인.

## 남은 위험과 미해결 사항

- 날짜를 키보드로 직접 타이핑하는 길이 없어진다. 필요하면 달력 팝오버 안에 `YYYY-MM-DD` 입력 칸을 더하는 수정 요청으로 처리한다.
- "최근 20회"는 임의값이다. 성적 통계의 10·20회 선택(DCR-018)과 맞추기 위해 20으로 두었다. 바꾸려면 수정 요청.
- 테스트 운영 DB에 조회로만 생긴 빈 세션이 남아 있어도 화면에는 영향이 없지만, 데이터 정리는 이 변경의 범위 밖이다.
