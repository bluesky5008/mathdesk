## 요약

- 목적: 시각 설계를 **장식이 아니라 매출 자산**으로 규정하고, 누락된 디자인 요구사항을 기준선에 추가한다. 학부모에게 반복 도달하는 리포트 카드를 1순위로 강화하고, 웹 UI에 공유 디자인 토큰 기반의 스타일 체계를 도입한다.
- 현재 결론 또는 상태: 승인 대기. 승인되면 기준선 `v4`가 발행된다.
- 다음 행동: 재승인 후 TASK-44(토큰·공통 컴포넌트 기반) → TASK-45(카드 렌더러 전환) → TASK-46(카드 재설계·브랜드) → TASK-47(기존 화면 재작성) 순서로 구현한다.

## 변경 사유와 증거

사용자가 "시스템의 UI 꾸미기는 언제 하게 되는가, 지금은 예쁘지 않다"고 물었고, 이어서 목표를 밝혔다 — **"클라이언트는 본인이 보기에 예쁜 것도 중요하지만, 이 뷰를 학생과 학부모에게 보여줌으로써 매출 확대를 도모하려 한다. 학생을 더 많이 모집하고 싶다."**

조사한 사실은 다음과 같다.

| 사실 | 확인 방법 |
|---|---|
| 웹 앱에 스타일이 전혀 없다 — CSS 파일 0개, `className`·`style` 0회, 스타일 라이브러리 0개 | `find src -name "*.css"`, `grep -rho 'style=\|className='` |
| 기준선에 디자인·미관 요구사항이 없다. UI 관련 항목은 NFR-13(조작 효율)·NFR-14(해상도)뿐 | [requirements.md 비기능 요구사항](../../requirements.md#비기능-요구사항) |
| 설계 문서에 CSS·디자인·스타일 언급이 0건이다 | `grep -n "디자인\|스타일\|CSS\|UI" docs/design.md` |
| **학부모·학생은 시스템에 로그인하지 않는다** | [대상과 시나리오](../../requirements.md#대상과-시나리오) "문자·알림톡 수신 (시스템에 로그인하지 않음)" |
| **학부모·학생용 로그인 포털은 명시적 범위 제외다** | [범위 · 제외](../../requirements.md#제외) "통보는 단방향 메시지로 충분하며 요청되지 않았다" |
| 학부모에게 도달하는 시각물은 리포트 카드(FR-20)와 난이도 분석표 카드(FR-30)뿐이다 | 위 두 항목의 논리적 귀결 |
| 리포트 카드는 Pillow 직접 드로잉 105줄 — 760px 고정, 단색 배경 + 둥근 사각형 + 상단 바 + 텍스트 나열 | [apps/api/src/mathdesk/report.py](../../../apps/api/src/mathdesk/report.py) |
| 설계 DES-08은 원래 "카드형 HTML로 구성해 이미지로 변환"이었고, Q-10 해소 때 판단 기준이 의존성 무게였다 | [design.md DES-08](../../design.md#컴포넌트와-책임), [Q-10](../../design.md#가정과-미해결-질문) |
| 웹 테스트 20건이 전부 의미 기반 쿼리다(`getByRole` 15·`getByLabelText` 5·`getByText` 10, `getByTestId`·`querySelector`·`container` 각 0) | `grep -rho` 집계 |
| 컨테이너는 `python:3.12-slim` + `fonts-nanum` 두 이미지 모두 동일 | [apps/api/Dockerfile](../../../apps/api/Dockerfile), [Dockerfile.testops](../../../Dockerfile.testops) |

사용자 결정 3건: 범위는 "지금 공통 기반 + 화면별 다듬기까지", 방식은 "변경 범위가 커지더라도 기능적으로 가장 좋고 미관적으로 가장 이쁜 솔루션"(추천 위임), 도달 경로는 "카톡·문자로 받는 리포트 카드(현행)", 렌더러는 "HTML/CSS 렌더링으로 전환".

## 기존 기준선과 설계

- 디자인·미관에 대한 요구사항이 **존재하지 않는다.** 누락이지 의도적 제외가 아니다.
- [DES-08](../../design.md#컴포넌트와-책임): "렌더된 본문을 카드형 HTML로 구성해 이미지로 변환" — 구현이 설계와 다르다.
- [Q-10](../../design.md#가정과-미해결-질문): "해소(2026-09-22) — 헤드리스 브라우저 대신 이미지 라이브러리로 직접 그린다".
- [AC-16](../../requirements.md#인수-조건): 내용 동치만 요구하고 시각 규격이 없다.
- 카드 생성 시간에 대한 성능 요구사항이 없다(NFR-01·NFR-02는 대시보드·일일 입력 대상).
- 학원 브랜드(이름·로고·색)를 담을 설정이 없다.

## 제안 설계

**시각 투자 우선순위를 매출 기여도 순으로 재정렬한다.**

| 순위 | 대상 | 근거 |
|---|---|---|
| 1 | 리포트 카드 · 난이도 분석표 카드 | 학부모에게 매 수업 반복 도달하고 스크린샷으로 전파되는 유일한 자산 |
| 2 | 공유 디자인 토큰 | 원장 화면과 학부모 카드가 하나의 브랜드 언어를 갖게 하는 구조적 장치 |
| 3 | 내부 운영 화면 | 밀도·속도가 미덕. 심미는 일관성 수준으로 충분 |

```text
tokens.css  (색 · 간격 · 타이포 · 라운드 · 그림자 — 순수 CSS 변수, 단일 소스)
   ├── 웹 앱          Tailwind v4가 @theme로 읽음 → 12개 화면
   └── 카드 템플릿    서버가 인라인 → Chromium 스크린샷 → 학부모 폰
```

1. 웹은 Tailwind v4 + shadcn/ui 패턴(Radix) + Recharts. 컴포넌트 소스를 저장소에 둔다([ADR-010](./ADR-010-웹-UI-디자인-시스템.md)).
2. 카드는 HTML 템플릿 + Playwright(Chromium) 스크린샷. 브라우저는 앱 수명주기에 1개 warm([ADR-011](./ADR-011-리포트-카드-HTML-렌더링.md)).
3. 학원 브랜드(이름·로고·시그니처 색)를 `integration_setting`에 두고 카드와 웹이 함께 읽는다.
4. 재작성 시 역할·레이블을 보존해 기존 테스트 20건을 그대로 통과시킨다.

## 영향 범위

- 요구사항과 인수 조건: FR-40·NFR-18·NFR-19·AC-30~32 신설. 기존 FR 변경 없음. NFR-13은 의미 보강만.
- 인터페이스와 데이터: REST 계약 변경 없음. 브랜드 설정은 기존 `integration_setting` 사용 — **스키마 변경 없음.**
- 보안: 렌더러가 늘어 보안 표면이 커진다. 템플릿에는 서버가 조립한 내부 데이터만 들어가고 외부 입력을 렌더하지 않는다. [NFR-04](../../requirements.md#nfr-04-상세) 경계는 영향 없음(렌더링은 서버 내부에서 끝난다).
- 운영: 컨테이너 이미지 +300~400MB, Chromium 상시 메모리 약 200MB. 맥미니에서 home-wiki와 공존하므로 실측 필요.
- 진행 중인 구현: 없음. TASK-23 완료 후 TASK-24 착수 전이라 보류할 구현이 없다.
- 테스트: 기존 웹 20건은 의미 기반이라 유지 전망. 카드 시각 회귀 테스트를 새로 만들고 Pillow 글리프 테스트는 교체한다.

## 고려한 대안

대안 비교는 [ADR-010 고려한 대안](./ADR-010-웹-UI-디자인-시스템.md#고려한-대안)(Tailwind+shadcn / 컴포넌트 라이브러리 / 순수 CSS / 현행 유지)과 [ADR-011 고려한 대안](./ADR-011-리포트-카드-HTML-렌더링.md#고려한-대안)(Playwright / WeasyPrint / Satori / Pillow 유지)에 있다.

우선순위 자체에 대한 대안도 검토했다. "웹 UI를 먼저 예쁘게"는 직관적이지만, 학부모가 웹에 도달하지 않는다는 사실이 확인된 이상 매출 목표에 대한 기여가 간접적이다. 사용자가 도달 경로를 리포트 카드로 한정 확인했으므로 카드를 1순위로 둔다.

## 구현된 코드의 처리

- 유지: 사이클 1·2의 모든 기능 구현과 검증 기록. 이 변경은 기능 동작을 바꾸지 않는다.
- 수정: 웹 화면 5개(Dashboard·Daily·Students·Classes·Messages)와 `LoginForm`·`Roster`·`AttendanceButtons`의 마크업. 역할·레이블은 보존한다.
- 되돌림: `report.py`의 Pillow 렌더 경로와 글리프 커버리지 테스트. 렌더러 교체로 대체된다.

## 마이그레이션과 롤백

- 데이터 마이그레이션 없음. 브랜드 설정은 기존 `integration_setting` 키를 쓴다.
- 새 의존성: 웹 8개 내외(Tailwind·Radix·Recharts 등), API 1개(`playwright`) + Chromium 런타임.
- 롤백: 웹은 커밋 되돌리기. 카드 렌더러는 전환 커밋 되돌리기로 Pillow 경로 복구. 두 변경이 독립적이라 따로 되돌릴 수 있다.
- 컨테이너 크기가 문제가 되면 [ADR-011](./ADR-011-리포트-카드-HTML-렌더링.md)의 대안 B·C로 렌더러만 교체한다. 토큰과 템플릿은 재사용된다.

| 디자인 품질은 도구가 보장하지 않는다 | 기대 미달 | 카드는 시안을 먼저 만들어 사용자 확인 후 확정한다(TASK-46) |
| 브랜드 자산(로고)이 아직 없다 | 카드에 넣을 것이 없음 | 로고 미설정 시 학원명 텍스트로 대체하는 기본 동작을 둔다 |
