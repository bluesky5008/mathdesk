## 요약

- 변경 분류: **요구사항 변경** — 새 기능(주간 시간표 화면)과 새 설정(수업 길이)을 더한다.
- 변경 요지: 반마다 등록한 시간표를 모아 **요일 × 시간 축 격자(달력형)의 주간 시간표**로 보여 주는 탭을 만든다. 강사는 자기 담당 반만, 원장은 모든 반을 보며 원장은 강사 이름과 강사별 보기를 쓴다. 블록 길이는 학원 전체에 하나인 **수업 길이(기본 120분)** 설정으로 그린다.
- 사용자 결정(2026-09-24): 표시 형태 "시간 축 격자(달력형)", 원장 화면 "강사 이름 표시 + 강사별 보기", 선행 작업 "함께 진행", 수업 길이 "2시간(120분)" — **[DCR-010](./DCR-010-수업-길이-4시간.md)에서 240분(4시간)으로 정정**(학원 설정에서 변경 가능).
- 사용자 재승인 결과: **승인 (2026-09-24)** — 기준선 `v8` → `v9` 발행

## 변경 사유와 증거

- **계기:** 사용자가 반별 시간표를 모은 주간 시간표 화면을 요청했다(2026-09-24). 강사·원장만 보고, 강사는 자기 시간표만, 원장은 전체.
- **확인한 사실:**
  1. 반 목록 API(`GET /classes`)는 이미 역할로 거른다 — 강사는 담당 반(`class.teacher_id = 본인`)만, 원장은 캠퍼스 전체(`masterdata._visible_classes`). 권한 구조는 그대로 쓸 수 있다.
  2. **선행 요구사항 두 개의 화면이 없다(승인된 요구사항 미구현, DCR 대상 아님):** FR-02 사용자 계정 생성·수정·비활성화(API `GET/POST/PATCH /users`는 있음), FR-07 반의 담당 강사 지정(반 등록·수정 화면에 선택이 없음). 이대로면 모든 반의 담당 강사가 비어 강사 화면이 항상 비어 있다. → 계획에 선행 작업 TASK-64·65로 넣는다.
  3. 종료 시각은 DCR-007로 저장하지 않는다. 격자에 블록 길이를 그리려면 수업 길이가 필요하다. 사용자는 "수업 시간이 동일하다"고 했고 120분으로 정했다.
- **보류한 구현:** 없음.

## 제안 (기준선 `v9`)

### 요구사항

- **FR-42 주간 시간표(신설):** 활성 반의 시간표를 요일(월~일) × 시간 축 격자로 보여 준다. 수업 블록은 시작 시각부터 학원의 수업 길이만큼 그린다. 강사는 자기 담당 반만, 원장은 캠퍼스의 모든 반을 본다. 원장 화면은 블록에 담당 강사 이름을 표시하고 강사별로 걸러 볼 수 있다. 시간표가 없는 반은 격자 밖에 "시간표 미등록"으로 모아 보여 준다. 원장은 학원 설정에서 수업 길이(분, 기본 120)를 바꿀 수 있다.
- **AC-38(신설):** ① 강사로 로그인하면 자기 담당 반의 수업만 격자에 나온다 ② 원장으로 로그인하면 모든 활성 반이 강사 이름과 함께 나오고, 강사를 고르면 그 강사의 반만 남는다 ③ 수업 길이를 바꾸면 블록 길이가 따라 바뀐다 ④ 시간표 없는 반은 "시간표 미등록"에 나온다 ⑤ 비활성 반은 나오지 않는다.

### 설계

- **`GET /timetable`(신설):** 로그인한 사용자 기준(역할·캠퍼스 스코프 공통 규칙)으로 `{class_minutes, slots[], unscheduled[]}`를 준다. `slots[]` = 활성 반의 시간표 한 줄마다 `{class_id, class_name, grade, teacher: {id, name} | null, weekday, start_time, end_time}` — `end_time`은 저장값이 아니라 `start_time + class_minutes`로 계산한다. `unscheduled[]` = 시간표 없는 활성 반. 강사 이름을 서버가 붙이므로 강사가 `/users`(원장 전용)를 부를 필요가 없다.
- **`PUT /settings/class-minutes`(신설, 원장 전용):** `{class_minutes}` 30~480분. 캠퍼스 설정 `integration_setting`의 키 `class_minutes`에 저장(없으면 120). `GET /timetable`이 값을 함께 준다.
- **화면:** 상단 탭 "주간 시간표"(`/timetable`). 데스크톱은 요일 열 × 시간 행 격자(시간 축은 가장 이른 시작~가장 늦은 끝에 맞춘다, 같은 시간대 수업은 열 안에서 나란히), 원장은 상단에 "전체 / 강사별" 선택. 휴대폰(390px)은 7열이 들어가지 않으므로 요일별 세로 목록(시작~끝 시각과 반 이름)으로 바꾼다. 학원 설정에 "수업 길이(분)" 입력 추가.
- **선행(설계 변경 아님):** FR-02 강사 계정 관리 화면(목록·생성·이름/역할 수정·비활성화), FR-07 반 등록·수정의 담당 강사 선택.

## 대안 분석

| 대안 | 장점 | 단점·위험 | 판단 |
|---|---|---|---|
| A. 시간 축 격자 + 수업 길이 설정 (선택) | 시간대가 한눈에 보인다(사용자 선택) | 수업 길이 설정이 필요하다. 좁은 화면에서는 다른 배치가 필요하다 | **채택** |
| B. 요일별 열 + 시작 시각 순 카드 | 종료 시각·설정이 필요 없다 | 시간대 겹침이 덜 보인다 | 사용자가 A를 골랐다 |
| C. 화면만 추가하고 `GET /classes`·`/users`를 조합 | 서버 변경이 없다 | 강사는 `/users`를 못 불러 강사 이름을 못 얻는다. 종료 시각 계산이 화면에 흩어진다 | 기각 |

**ADR을 만들지 않는 이유:** 기존 구조(역할 스코프, 캠퍼스 설정 저장소, 화면 탭) 안의 기능 추가이며 되돌리기 쉽다.

## 마이그레이션과 롤백

- **마이그레이션:** 없음.
- **롤백:** 탭·엔드포인트 2개·설정 입력을 제거한다. 저장된 `class_minutes` 행은 남아도 무해하다.

## 검증 방법

- **AC-38:** API — 강사/원장/타 캠퍼스별 `GET /timetable` 결과(강사는 담당 반만, 원장은 전체, 다른 캠퍼스의 반은 나오지 않음), `end_time` 계산, 수업 길이 변경 반영, 미등록·비활성 반 처리, `PUT` 원장 전용·범위 검증. 웹 — 격자 배치(요일 열·시각 위치·블록 길이), 원장 강사별 보기, 390px 목록 전환(VER-35에 화면 추가).
- 선행 작업은 각자의 테스트(FR-02·FR-07)로 검증한다.

## 남은 위험과 미해결 사항

- FR-02는 비밀번호 재설정을 요구하지 않아 API에도 없다. 강사가 비밀번호를 잊으면 지금은 원장이 계정을 새로 만들어야 한다. 필요하면 별도 요청으로 다룬다.
- 반마다 수업 길이가 달라지면 이 설정 하나로는 표현할 수 없다(그때는 DCR-007의 종료 시각 입력을 다시 연다).
