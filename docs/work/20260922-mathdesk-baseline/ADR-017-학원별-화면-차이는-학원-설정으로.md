# ADR-017: 학원별 화면 차이는 같은 이미지의 학원 설정으로 흡수한다

## 요약

- 목적: 클라이언트(학원)마다 화면에 보이는 항목이 달라야 할 때 그 차이를 어디에 둘지 정한다.
- 현재 결론 또는 상태: 승인(2026-11-12) — **빌드·브랜치를 나누지 않는다. 학원이 정할 차이는 DB의 학원 설정(`integration_setting`)에 두고 원장이 설정 화면에서 바꾼다. 개발자가 켜고 끄는 기능 스위치는 `.env`에 둔다.**
- 다음 행동: 없음. 첫 적용은 [DCR-028](./DCR-028-일일-기록-항목의-학원별-구성.md).

## 배경

- 사실: 운영 서버는 클라이언트마다 하나이고 같은 이미지에 `.env`만 다르다(NFR-08, ADR-013, ADR-015).
- 사실: 2026-11-12 사용자 요청 — 한 클라이언트는 일일 기록에서 "이전 과제 재검사"를 빼고 "수업태도"를 넣고 싶어 하고, 다른 클라이언트는 지금 화면을 유지하고 싶어 한다. 빼는 쪽도 나중에 재검사가 다시 필요할 수 있다.
- 사실: 학원 이름·로고·색은 이미 `campus`·`integration_setting`에 저장되고 원장이 설정 화면에서 바꾼다(FR-40). 문자 모드·LLM 공급자는 `.env`로 정한다.

## 영향을 받는 요구사항과 제약

- NFR-08(동일 이미지), DES-25(운영 서빙), FR-40(학원 설정).
- 제약: 개발자 1명이 서버 2대를 운영한다. 버전이 갈라지면 수정·검증·배포가 두 배가 된다.

## 고려한 대안

| 대안 | 장점 | 단점 | 판단 |
|---|---|---|---|
| A. 학원 설정(DB) — 원장이 설정 화면에서 | 재배포·재기동 없이 바뀐다. 학원이 스스로 정한다. 기존 설정 저장 구조를 그대로 쓴다. 백업·복원에 함께 들어간다 | 설정 화면과 검증 코드가 필요하다 | **채택** — 학원이 정할 차이에 |
| B. `.env` 스위치 — 개발자가 서버에서 | 구현이 가장 작다 | 바꿀 때마다 SSH·재기동. 학원이 못 바꾼다. 항목 이름 같은 자유 값에 맞지 않는다 | **채택** — 개발자가 통제할 기능 on/off에 한해 |
| C. 클라이언트별 빌드·브랜치 | 무엇이든 다르게 만들 수 있다 | NFR-08·ADR-015 위반. 수정·테스트·배포 이중화, 버전 분기 | 기각 |

## 결정

1. 클라이언트별 빌드·브랜치·이미지를 만들지 않는다. 두 서버는 계속 같은 태그를 받는다.
2. **학원이 정할 차이**(항목 표시 여부, 항목 이름, 추가 항목)는 `integration_setting`에 캠퍼스 단위로 저장하고 원장이 학원 설정 화면에서 바꾼다.
3. **개발자가 통제할 차이**(실험·미완성 기능의 on/off)는 `.env`의 환경변수로 둔다. 이번에는 추가하지 않는다.
4. 설정이 없는 학원의 화면과 응답은 변경 전과 같아야 한다(기본값 = 현행).
5. 항목을 숨겨도 저장된 값은 지우지 않는다. 다시 켜면 그대로 보인다.

## 이유

- 요청의 차이는 "기능이 있고 없고"가 아니라 "어떤 항목을 보일지"이며, 이는 학원 운영자가 정할 일이다.
- 결정 4·5로 기존 클라이언트는 영향이 없고, 바꾼 클라이언트도 되돌릴 수 있다(사용자 요청 2번).

## 결과와 감수할 단점

- 화면 코드에 "설정에 따라 그린다"는 분기가 생긴다. 항목이 늘수록 조합이 늘어 테스트가 필요하다 — 기본값(현행) 경로를 기존 테스트가 수정 없이 통과하는 것으로 지킨다.
- 설정 구조가 한 번 운영 데이터에 들어가면 바꾸기 어렵다 — 항목 식별자를 한 번 발급하면 재사용하지 않는 규칙으로 완화한다([DCR-028](./DCR-028-일일-기록-항목의-학원별-구성.md)).
