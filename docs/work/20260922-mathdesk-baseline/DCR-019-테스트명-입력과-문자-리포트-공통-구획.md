> 관련 문서: [REQ-mathdesk: 요구사항](../../requirements.md), [DESIGN-mathdesk: 설계](../../design.md), [PLAN-mathdesk: 구현 계획](../../plan.md), [결정 등록부](../../decisions.md)

## 요약

- 변경 분류: **요구사항 변경** — 일일 테스트의 테스트명을 화면에서 입력할 수 있게 하고(FR-13 상세 신설), 문자 본문과 리포트 카드에서 테스트명을 학생 개별 구획이 아니라 **반 공통 구획**으로 옮긴다(FR-18 상세·AC-14 변경). 데이터 모델·REST 변경은 없다.
- 변경 요지: 일일 입력의 "오늘 진도" 카드에 **[테스트명]** 한 칸을 더한다(만점 칸은 두지 않는다). 문자는 반 공통에 `■ 오늘의 테스트`(테스트명), 학생 개별에 `■ 테스트 점수`(학생 점수·반 평균)를 둔다. 리포트 카드는 요약 타일 "테스트"(점수·반평균)를 그대로 두고 상세(반 공통)에 "오늘의 테스트"(테스트명)를 더한다.
- 사용자 결정(2026-10-11): ① 만점 칸은 **두지 않는다** ② 테스트명을 문자와 리포트의 **공통 영역**에 넣는다.
- 사용자 재승인 결과: **승인 (2026-10-11)** — 기준선 `v19` → `v20` 발행

## 변경 사유와 증거

- **계기:** 사용자 요청(2026-10-11) — 성적 통계의 회차별 추이(AC-19)에 보이는 시험명을 화면 어디에서 입력하는지 물었고, 입력 칸이 없음을 확인한 뒤 "만점은 없어도 되고 테스트명만 있으면 된다. 테스트명을 리포트와 문자의 공통 영역에 포함시켜라"고 결정했다.
- **확인한 사실:**
  1. FR-13은 "반 단위로 테스트명을 정하고 학생별 점수를 입력"을 요구하고, 설계 데이터 모델에 `class_session.test_name`·`test_max_score`가 있으며, `PATCH /daily/{id}/notes`가 두 필드를 받는다. 그러나 일일 입력 화면의 메모 칸 목록(`DailyPage.tsx` `NOTE_FIELDS`)은 과제·영상 링크·선생님 코멘트 셋만 있어 **테스트명을 화면에서 입력할 길이 없다** (FR-13 미구현 부분).
  2. 테스트 운영 DB의 테스트명 18건은 모두 2026-10-11 테스트 데이터 스크립트가 넣은 것이다. 화면에서 입력한 점수 7건은 테스트명이 없다.
  3. 문자 렌더러(`messaging.render_daily_message`)의 `■ 테스트` 구획은 학생 개별 구획에 있고 **테스트명과 점수가 둘 다 있을 때만** 나온다. 따라서 화면에서 입력한 점수 7건은 지금 문자에 나오지 않는다(이름이 없어서).
  4. 리포트 카드(`report._facts`)의 "테스트" 요약 타일은 점수·반평균만 보이고 테스트명은 어디에도 없다. 상세(`_details`)는 진도·과제·영상·선생님 코멘트, 즉 반 공통 항목만 담는다.
  5. 알림톡 변수 `ALIMTALK_FIELDS`에 `test_name`(테스트명)이 이미 있다. 변경 없음.
  6. 회차별 추이(TASK-88)는 `class_session.test_name or "테스트"`를 시험명으로 보여 준다. 입력 칸이 생기면 그대로 반영된다.
- **보류한 구현:** 없음(구현 시작 전).

## 제안 (기준선 `v20`)

### 요구사항

- **FR-13 상세(신설):** 테스트명은 일일 입력의 "오늘 진도" 카드에서 반 단위로 입력하고 [메모 저장]으로 저장한다(100자 이내, 비울 수 있음). 만점은 입력하지 않는다. 테스트명은 그날 반 공통 값으로 문자·리포트 카드(FR-18)와 회차별 추이(FR-24)에 쓰인다. 점수는 기존대로 표에서 학생별로 입력한다.
- **FR-18 상세 변경 — 본문 구획과 순서:**
  1. 제목, 인사말, 수업일 (기존)
  2. **반 공통** — `■ 수업진도` · `■ 오늘의 테스트`(테스트명) · `■ 오늘의 과제` · `■ 수업 영상 링크` · `■ 선생님 코멘트`
  3. **학생 개별** — `■ 출결` · `■ 과제피드백` · `■ 테스트 점수`(학생 점수·반 평균) · `■ 개별 코멘트`
  - 데이터가 없는 구획은 생략한다(기존 규칙). `■ 오늘의 테스트`는 테스트명이 있을 때, `■ 테스트 점수`는 그 학생의 점수가 있을 때 나온다 — 테스트명이 없어도 점수가 있으면 점수 구획은 나온다(기존의 "둘 다 있을 때만" 규칙 폐기).
- **AC-14 변경:** 모든 값이 있는 학생의 미리보기는 제목과 9개 구획(수업진도·오늘의 테스트·오늘의 과제·영상 링크·선생님 코멘트·출결·과제피드백·테스트 점수·개별 코멘트)을 **이 순서로** 포함하고, 테스트명이 없으면 오늘의 테스트 구획이, 점수가 없으면 테스트 점수 구획이, 코멘트가 없으면 해당 코멘트 구획이 생략된다.
- **AC-44(신설):** ① "오늘 진도" 카드에서 테스트명을 적고 [메모 저장]하면 다시 열었을 때 그대로 보인다 ② 같은 날 두 학생의 문자 미리보기에 같은 `■ 오늘의 테스트` 구획이 공통으로 있고, 점수는 각자의 `■ 테스트 점수` 구획에 있다 ③ 테스트명 없이 점수만 있으면 `■ 테스트 점수` 구획만 나온다 ④ 리포트 카드 상세에 "오늘의 테스트"(테스트명)가 보이고 요약 타일 "테스트"에는 점수·반평균이 보인다 ⑤ 입력한 테스트명이 성적 통계의 회차 표 시험명 칸에 나온다 ⑥ 테스트명이 100자를 넘으면 저장이 거부된다.

### 설계

- **데이터 모델:** 변경 없음. `class_session.test_max_score`는 열을 유지하되 화면 입력이 없는 예비 열로 표기한다(기존 데이터 18건은 그대로 둔다).
- **REST:** 변경 없음. `PATCH /daily/{session_id}/notes`의 `test_name`에 **100자 상한**을 더한다(422). 기존 규칙대로 보내지 않으면 건드리지 않고, 빈 문자열은 NULL로 저장한다.
- **메시지 렌더러(DES-07):** `render_daily_message`의 반 공통 구획에 `■ 오늘의 테스트\n{test_name}`를 수업진도 다음에 넣고, 학생 개별의 `■ 테스트: {이름}` 구획을 `■ 테스트 점수: {점수}점\n   반평균: {평균}점`으로 바꾼다. 조건은 각각 테스트명 유무·점수 유무. 순수 함수 유지.
- **알림톡 변수:** 변경 없음(`test_name`·`test_score`·`class_average`가 이미 있다). `daily_message`(일일 피드백 전체)는 새 구획을 따른다. 등록된 템플릿 0건.
- **리포트 카드(DES-08, ADR-011 유지):** 요약 타일 "테스트"(점수·반평균)는 그대로. 상세(`_details`)에 "오늘의 테스트"(테스트명)를 **수업 진도 다음**에 더한다. 레이아웃·순서 결정은 바꾸지 않는다.
- **화면 — 일일 입력 "오늘 진도" 카드:** 1~4교시 진도 다음, [오늘의 과제] 앞에 **[테스트명]** 한 줄 `Input`(`maxLength` 100)을 둔다. 다른 메모 칸과 함께 [메모 저장]으로 저장한다(`NotesPatch.test_name`). 만점 칸은 두지 않는다. 표의 "테스트" 열 머리말은 그대로 둔다.
- **성적 통계:** 변경 없음(회차 표가 `test_name`을 이미 보여 준다).

## 검증 방법

- API: 렌더러 9구획 순서(AC-14), 테스트명만 있을 때 공통 구획만·점수만 있을 때 개별 구획만·둘 다 없으면 둘 다 생략, 두 학생 공통 같음·점수 다름(AC-44 ②), 카드 HTML 상세에 "오늘의 테스트"와 요약 타일 점수(AC-44 ④), 메모 저장 101자 422·빈 값 NULL·생략 시 불변(AC-44 ⑥), 회차 표 시험명(기존 테스트 유지).
- 웹: [테스트명] 칸 입력 → [메모 저장] 본문에 `test_name`, 재조회 표시(AC-44 ①), 만점 칸 없음.

## 남은 위험과 미해결 사항
