## 요약

- 변경 분류: **요구사항 변경** — 학생 삭제의 2단 확인(삭제 미리보기 창 + 이름 입력)을 없앤다. 삭제 API 계약(`confirm_name`)도 바뀐다.
- 변경 요지: [삭제]를 누르면 바로 하드 삭제한다. 함께 지우는 범위(DCR-006)는 그대로다. 반 삭제는 바꾸지 않는다(미리보기 + 이름 입력 유지).
- 사용자 지시(2026-10-11): "학생 삭제 버튼은 2단 확인을 하지 않고 삭제와 동시에 HARD 삭제로 변경하자".
- 확인한 사실: 현재 삭제는 이미 **하드 삭제**다 — 학생 행과 보호자·반 배정·일일 기록·시험 응시·답안지 판독·발송 내역·상담 기록을 DB에서 지운다. 남는 것은 OMR 원본 PDF(다른 학생 답안지가 같은 파일에 있음)와 백업뿐이다. 따라서 이번 변경의 실체는 확인 절차 제거다.
- 사용자 재승인 결과: 대기 — 안 A·B 중 선택 포함

## 변경 사유와 증거

- **계기:** 사용자 지시(위). DCR-012로 목록 행에 [삭제]를 둔 직후다.
- **현재 흐름(기준선 `v13`):** [삭제] → 삭제 창(함께 지워질 건수, 재원 경고, "되돌릴 수 없습니다") → 이름 입력 → [영구 삭제] → `DELETE /students/{id}` 본문 `confirm_name`(서버가 이름 불일치 시 422).
- **위험 사실:**
  1. 행의 [삭제]는 [수정] 바로 오른쪽에 있다. 확인이 없으면 잘못 누른 한 번으로 학생과 모든 기록이 사라진다.
  2. 되돌리는 방법은 백업 복원뿐이고, 복원은 DB 전체를 백업 시점으로 되돌린다(그 뒤 입력한 다른 학생의 기록도 사라진다).
  3. 테스트 운영에는 자동 백업이 없다(배포 때 수동 백업만, [TASK-57](../../plan.md#task-57-운영-구성-준비) 대기).
- **보류한 구현:** 없음.

## 제안 (기준선 `v14`)

공통:

- 학생 삭제는 미리보기 창과 이름 입력 없이 진행한다. 서버는 학생 `DELETE`에서 `confirm_name`을 확인하지 않는다(본문이 와도 무시 — 기존 호출과 호환).
- 그대로 두는 것: 함께 지우는 범위, 원장 전용(강사 403), 캠퍼스 스코프, 한 트랜잭션, 감사 로그(상태·건수, 이름 없음), 반 삭제 절차.
- 삭제가 끝나면 목록에서 바로 빠진다. 실패하면 목록 아래에 서버 메시지를 보인다.
- `GET /students/{id}/deletion-preview`는 남긴다(계약 유지). 화면은 학생 삭제에 더 쓰지 않는다.

두 가지 안 — **사용자 선택 필요:**

| 안 | 동작 | 장점 | 위험 |
|---|---|---|---|
| A. 즉시 삭제 (지시 그대로) | [삭제]를 누르는 순간 삭제 | 가장 빠르다 | [수정] 옆을 한 번 잘못 누르면 되돌릴 수 없다 |
| B. 확인 창 한 번 (권장) | 브라우저 확인 창 "OOO 학생과 출결·성적·상담 기록을 모두 삭제합니다. 되돌릴 수 없습니다." → [확인]이면 삭제 | 클릭 두 번으로 끝나 2단 확인보다 훨씬 가볍고, 오클릭은 막는다. [퇴원] 버튼과 같은 방식이다 | 습관적으로 [확인]을 누르면 막지 못한다 |

## 대안 분석

위 A·B 외에 검토한 안:

| 대안 | 판단 |
|---|---|
| C. 즉시 삭제 + 몇 초간 [되돌리기] | 되돌리려면 삭제를 미루거나 소프트 삭제(데이터 모델 변경)가 필요하다. 요청 범위를 넘는다 — 기각 |
| D. 행 [삭제]만 즉시, 수정 창 [삭제]는 2단 유지 | 같은 동작이 두 방식이라 혼란 — 기각 |

**ADR을 만들지 않는 이유:** 요구사항(확인 절차)의 조정이며 저장·구조 결정이 아니다.

## 마이그레이션과 롤백

- 마이그레이션: 없음.
- 롤백: 학생 `DELETE`의 이름 확인과 화면 삭제 창 호출을 되돌리면 `v13`. 이미 지운 학생은 백업 복원으로만 되돌린다.

## 검증 방법

- API: 학생 `DELETE` 본문 없이 204·기록 전부 삭제·다른 학생 불변, 본문의 이름이 달라도 204, 강사 403, 감사 로그 유지. 반 `DELETE` 이름 불일치 422 유지.
- 웹: (안 A) [삭제] 클릭 즉시 `DELETE`·목록에서 빠짐 / (안 B) 확인 창 [확인] → `DELETE`, [취소] → 요청 없음. 수정 창 [삭제]도 같은 동작. 강사 화면에 [삭제] 없음.

## 남은 위험과 미해결 사항

- 안 A를 고르면 오클릭 보호가 전혀 없다.
- 자동 백업이 없는 상태에서는 어떤 안이든 실수 복구가 어렵다 — TASK-57을 실데이터 입력 전에 하는 것을 권한다.
