## 요약

- 변경 분류: **요구사항 변경 + 권한 모델·데이터 모델 변경** — 기준선 제외 항목이던 "학부모·학생용 로그인 포털"을 범위에 넣는다. 원장이 학생 관리 탭에서 학생·학부모 계정을 전화번호로 원클릭 발급하고(FR-48), 학생·학부모는 **전용 화면**에서 본인(자녀)의 출결·진도·과제·테스트·강사 피드백·시험 결과·상담 기록·받은 문자를 본다(FR-49). 포털 역할은 기존 원장·강사 API에 접근할 수 없다(기본 거부, [ADR-014](./ADR-014-포털-권한-모델.md)).
- 변경 요지: ① 역할 `student`·`guardian` 추가와 계정–학생 연결 테이블 ② 발급·재발급 REST와 학생 목록의 발급 상태 ③ `/api/portal/*` 조회 REST 7건과 모바일 우선 포털 UI ④ 학생 삭제 시 계정 삭제, 퇴원 시 비활성화 ⑤ 상담 기록은 본인 것 전부 노출(방식 A).
- 사용자 결정: 상담 기록은 **방식 A(본인 기록 전부)**로 확정(2026-10-11). 초기 비밀번호를 로그인 ID와 같게 하는 안(사용자 제안)은 완화책 2건과 함께 승인되었다.
- 사용자 재승인 결과: **승인 (2026-10-11)** — 기준선 `v24` → `v25` 발행

## 변경 사유와 증거

- **계기:** 2026-10-11 사용자 요청. 원장·강사용 학생 관리에 더해 학생·학부모에게 접속 경로를 열고 개인화된 학습 기록을 보여 주는 전용 UI를 만든다. 사용자가 제시한 요구 7건과 검토 뒤 사용자 결정(아래 "사용자 결정")이 입력이다.
- **기준선 충돌:** 요구사항 [범위 제외](../../requirements.md#제외)에 "학부모·학생용 로그인 포털 — 통보는 단방향 메시지로 충분하며 요청되지 않았다"가 있다. 이번 요청으로 제외 사유가 사라졌으므로 요구사항 변경이다.
- **확인한 사실(코드·문서):**
  1. 계정은 `app_user`(역할 `director`·`teacher`, `login_id` **전역 유일**, `must_change_password`)이며, `must_change_password`가 참이면 [공통 스코프 검사](../../../apps/api/src/mathdesk/scope.py)가 `GET /auth/me`·로그아웃·`POST /auth/password` 외 모든 요청을 403으로 막는다([DCR-009](./DCR-009-비밀번호-변경과-재설정.md)). 웹은 이 상태에서 `ForcedPasswordChange` 화면만 보인다. 최초 접속 비밀번호 변경 강제는 **이미 있다**.
  2. 권한은 `Scope.require_director()` 한 가지뿐이다. 모든 라우터가 "강사도 가능"을 기본으로 하므로 역할을 추가하기만 하면 새 역할이 기존 API 전부를 쓸 수 있다. 포털 역할은 **기본 거부** 구조가 필요하다.
  3. 학생 전화번호(`student.phone`)는 NULL일 수 있고, 보호자 전화번호(`guardian.phone`)는 필수다. 보호자는 학생마다 N건이지만 학생 화면은 1건만 입력한다(DCR-014). 형제가 다니면 보호자 번호가 학생 둘에 겹친다.
  4. 학생 삭제는 [deletion.py](../../../apps/api/src/mathdesk/deletion.py)의 `STUDENT_CASCADE` 상수와 "학생을 가리키는 모든 테이블이 처리되는지" 검사하는 테스트로 보호된다. 새 연결 테이블은 여기에 더하면 된다. `app_user`를 가리키는 테이블은 `user_session`·`app_user_campus`·`audit_log.actor_id`·`consult_log.author_id`·`label_correction.corrected_by`·`class.teacher_id`·`class_session.attendance_confirmed_by`이며, 포털 계정이 가리켜질 수 있는 것은 앞의 셋이다.
  5. 포털에 보일 데이터는 모두 있다. 학생별 수업일 이력 `GET /daily/history`(출결·재검사·과제 등급·테스트명·점수·반 평균·코멘트, FR-45), 반 공통 기록(`class_session`의 교시별 진도·과제·영상 링크·강사 첨언, FR-10), 테스트 회차별 추이 `GET /stats/students/{id}`(FR-24), 시험 결과(`exam_attempt`·`exam_answer`), 상담 `consult_log`(FR-39), 발송 로그 본문 스냅샷 `message_log.body_snapshot`(FR-23), 시간표 `GET /timetable`(FR-42). 문자 본문 구획(FR-18 상세)이 학부모 관점 정보의 사실상 정본이다.
  6. 로그인 잠금(NFR-06, 기본 10회·3분), 세션 유휴 만료 12시간, `Secure` 쿠키는 계정 종류와 무관하게 적용된다.
  7. 운영은 클라이언트마다 서버 한 대·캠퍼스 하나라 `login_id` 전역 유일이 전화번호와 충돌하지 않는다.
- **보류한 구현:** 없음(새 기능).

## 제안

### 요구사항

**범위·대상**

- [포함](../../requirements.md#포함)에 "M10 학생·학부모 포털: 계정 발급, 전용 조회 UI"를 더한다. [제외](../../requirements.md#제외)에서 "학부모·학생용 로그인 포털" 행을 뺀다. 제외에 "포털에서의 입력(과제 제출·출결 신청·상담 예약 등) — 조회 전용으로 시작한다"와 "문자 인증·소셜 로그인 — 번호 소유 확인은 학원이 발급으로 대신한다"를 더한다.
- 대상과 시나리오의 "수신자 학부모·학생(시스템에 로그인하지 않음)"을 "포털 사용자 학생·학부모: 본인(자녀)의 학습 기록 조회"로 바꾸고, 시나리오 7 **포털 조회**를 더한다: 학부모가 휴대폰으로 로그인해 자녀를 고르고 최근 수업일 기록·출석률·테스트 추이·받은 문자를 본다.

**FR-02 사용자·역할 관리(수정):** 역할에 `학생`·`학부모`를 더한다. 두 역할은 **포털 계정**이며 설정의 계정 관리 화면이 아니라 학생 관리 탭에서 발급한다(FR-48). "원장이 정한 비밀번호로 로그인한 사용자는 새 비밀번호를 정하기 전에는 다른 기능을 쓸 수 없다"는 포털 계정에도 그대로 적용된다.

**FR-03 상세 역할별 권한(추가):** 학생·학부모는 포털 API만 쓸 수 있고 그 밖의 모든 API는 거부된다. 학생 계정은 본인 1명, 학부모 계정은 연결된 자녀만 본다.

**FR-48(신설) 포털 계정 발급:** 원장은 학생 관리 탭의 학생 행과 [수정] 창에서 학생 계정과 학부모 계정을 각각 **버튼 한 번**으로 발급한다. 로그인 ID는 그 학생(또는 보호자)의 전화번호에서 숫자만 남긴 값이고, 초기 비밀번호는 로그인 ID와 같다. 발급된 계정은 최초 로그인에서 비밀번호를 바꾸기 전에는 아무 기능도 쓸 수 없다(FR-02). 상세는 [FR-48 상세](#fr-48-상세).

#### FR-48 상세

- **전제:** 학생 계정은 학생 연락처가 있어야 발급할 수 있다. 없으면 버튼을 비활성화하고 "학생 연락처를 먼저 등록하세요"를 보인다. 학부모 계정은 보호자 연락처(FR-06)마다 발급할 수 있다(현재 화면은 보호자 1건).
- **전화번호 규칙:** 숫자만 남긴 10~11자리. 그 외는 발급을 거부하고 안내한다.
- **한 번호 = 계정 하나:** 같은 로그인 ID의 계정이 이미 있으면 ① 학부모 계정이고 발급하려는 것도 학부모 계정이면 새로 만들지 않고 **그 계정에 이 학생을 연결**한다(형제) ② 그 밖의 조합(학생 번호가 이미 학부모 계정인 경우, 학생 계정에 다른 학생을 연결하려는 경우, 원장·강사 계정과 같은 번호)은 거부하고 어떤 계정과 겹치는지 안내한다.
- **발급 상태:** 학생 목록과 [수정] 창은 학생 계정·학부모 계정 각각의 상태를 보인다 — `미발급`, `변경 대기`(발급 뒤 최초 비밀번호 변경 전, 남은 날짜 포함), `사용 중`, `만료`(변경 대기가 7일을 넘김), `비활성`(퇴원).
- **발급 유효기간:** 발급·재발급 뒤 **7일**(설정값) 안에 최초 비밀번호 변경이 없으면 로그인을 거부하고 "발급 기간이 지났습니다. 학원에 재발급을 요청하세요"를 보인다. 원장·강사 계정에는 적용하지 않는다(기존 동작 유지).
- **재발급:** [재발급]은 비밀번호를 로그인 ID로 되돌리고 변경 대기 상태로 만들며, 그 계정의 로그인을 모두 끊는다. 비밀번호를 잊었거나 선점이 의심될 때 쓴다. 로그인 ID는 발급 시점 번호로 고정되며 연락처를 바꿔도 따라가지 않는다. 번호를 바꾸려면 [재발급]이 아니라 새 번호로 다시 발급한다(기존 계정은 그 학생과의 연결이 끊기고, 연결이 0이 되면 삭제된다).
- **퇴원·삭제 연동:** 학생이 `퇴원`이 되면 그 학생에 연결된 계정 중 재원·휴원 학생 연결이 하나도 남지 않는 계정을 비활성화한다(로그인 불가). 재원으로 되돌리면 다시 활성화한다. 학생을 삭제하면(FR-05 상세) 연결을 지우고, 연결이 0이 된 계정을 세션과 함께 삭제한다.
- **감사:** 발급·재발급·연결 추가·자동 비활성·삭제는 감사 로그에 남긴다(대상 계정 ID·학생 ID, 전화번호는 쓰지 않음).
- **원장만:** 강사는 발급 상태를 볼 수만 있다. 발급·재발급 요청은 403.

**FR-49(신설) 학생·학부모 포털:** 학생·학부모 계정으로 로그인하면 원장·강사 화면이 아니라 **포털 전용 화면**이 열린다. 학부모 계정에 자녀가 여럿이면 자녀를 고른다. 포털은 다음을 보인다 — ① 홈: 재원 반·시간표, 최근 수업일 기록 요약, 출석률(최근 30일·전체), 최근 테스트 ② 수업일별 기록: 문자 본문(FR-18 상세)과 같은 구획 구성(반 공통 진도·오늘의 테스트·과제·영상 링크·선생님 코멘트, 본인 출결·과제 피드백과 등급 문구·테스트 점수와 반 평균·개별 코멘트)을 최신 수업일부터 목록으로 ③ 테스트 추이: FR-24의 본인 회차별 점수·반 평균 ④ 시험 결과: OMR·수동 채점 시험의 본인 점수와 문항별 정오답 ⑤ 상담 기록: 본인 상담 기록 전부(방식 A) ⑥ 받은 문자: 본인에게 발송된 문자 본문 ⑦ 비밀번호 변경·로그아웃. 상세는 [FR-49 상세](#fr-49-상세).

#### FR-49 상세

- **본인 데이터만:** 다른 학생의 이름·점수·출결은 어떤 화면에도 나오지 않는다. 반 평균(FR-13·FR-24)은 문자에 이미 들어가므로 허용한다. 성적 비고(`score_note`), 반 통계(FR-25), 대시보드(FR-15)는 보이지 않는다.
- **노출 시점:** 강사가 저장한 값은 즉시 보인다. 출결 확정 여부는 조건이 아니다. 출결이 `미확인`이면 "미확인"으로 보인다.
- **수업일 목록 범위:** 학생이 배정되어 있던 날 중 기록이 있는 세션(DES-05 상세의 정의)만. 20회씩 더 보기.
- **받은 문자:** 그 학생을 대상으로 성공(접수·대체 발송)한 발송의 본문 스냅샷. 같은 세션에 학생·학부모 두 번 보냈으면 본문이 같으므로 한 건으로 보인다. 테스트 모드 발송은 보이지 않는다.
- **기기:** 학부모는 휴대폰으로 쓴다. NFR-14의 **조회 부류**로 390px에서 완전히 사용 가능해야 하며, 데스크톱에서도 쓸 수 있다. 밀집 입력 화면 규칙(NFR-13)은 적용되지 않는다.
- **셸:** 원장·강사 화면의 메뉴·캠퍼스 선택·설정은 보이지 않는다. 테마(FR-41)는 포털에도 적용된다.

**FR-39 상담일지(수정):** 그 학생의 상담 기록 전부가 포털(FR-49 ⑤)에 보인다는 점을 명시한다(방식 A). 공개 표시 열은 두지 않는다.

**FR-05 상세 삭제(추가):** 학생을 삭제하면 그 학생과 포털 계정의 연결을 지우고, 연결이 남지 않은 포털 계정은 세션·캠퍼스 연결과 함께 삭제한다. 그 계정이 남긴 감사 로그는 행위자만 비우고 남긴다.

**NFR-07 권한 적용(추가):** 포털 역할로 포털 외 모든 API를 호출하면 403이어야 하며, 엔드포인트 목록에서 생성한 테스트가 누락을 탐지해야 한다. 반대로 원장·강사 역할로 포털 API를 호출해도 403이다.

### 설계

핵심 결정은 [ADR-014](./ADR-014-포털-권한-모델.md)에 있다. 여기서는 계약과 구조를 적는다.

- **DES-03 인증·권한(확장):** 역할 열거형에 `student`·`guardian`을 더한다. `current_scope`(기존)는 `director`·`teacher`만 통과시키고 포털 역할은 403이다. 새 의존성 `current_portal_scope`는 포털 역할만 통과시키고 `PortalScope(user, campus_id, student_ids)`를 돌려준다(`student_ids`는 연결 테이블에서 재원·휴원 학생만). 포털 라우터는 `/api/portal` 접두사 아래에만 있고 이 의존성만 쓴다. 로그인은 기존 `POST /auth/login`을 쓰되, 포털 역할이고 `must_change_password`가 참이며 `issued_at + 7일 < now`이면 401(만료 문구)이다. `GET /auth/me` 응답은 그대로이며 웹이 `role`로 셸을 고른다. 권한 매트릭스에 "학생·학부모: 포털 API만, 나머지 불가" 열을 더한다.
- **DES-04 마스터 데이터(확장) — 발급:**
  - `GET /students/{id}/portal-accounts` → `{student: {state, login_id?, user_id?}, guardians: [{guardian_id, state, login_id?, user_id?}]}`. 상태값은 FR-48 상세의 5가지. 원장·강사 조회 가능(강사는 담당 반 학생).
  - `POST /students/{id}/portal-accounts` 본문 `{kind: "student"|"guardian", guardian_id?}` → 201 `{user_id, login_id, state, linked: true|false}`(`linked`는 기존 학부모 계정에 연결만 한 경우). 원장만. 번호 없음·형식 오류 422, 충돌 409.
  - `POST /students/{id}/portal-accounts/{user_id}/reissue` → 204. 원장만.
  - `GET /students`(목록) 응답에 `portal: {student: state, guardian: state}` 요약을 더한다(목록 열 1개).
  - 발급 로직은 `portal_accounts.py`의 서비스 함수 `issue_portal_account(session, scope, student, kind, guardian)`로 두고 엔드포인트가 호출한다. 추후 학생 등록 시 자동 발급은 이 함수를 등록 핸들러에서 부르는 것으로 끝난다(범위 밖).
  - 학생 상태 변경(`PATCH /students/{id}`의 `status`)과 삭제가 연결 계정의 활성 여부를 재계산한다: 계정의 연결 학생 중 `enrolled`·`paused`가 하나 이상이면 `is_active=true`, 아니면 `false`. 비활성화 시 세션을 지운다.
- **DES-04 상세 삭제(확장):** `STUDENT_CASCADE`에 `app_user_student`를 더한다. 연결 삭제 뒤 연결이 0인 포털 계정의 `user_session`·`app_user_campus`를 지우고 `audit_log.actor_id`를 NULL로 바꾼 뒤 `app_user`를 지운다. 미리보기 `counts`에 `portal_accounts`를 더한다. 감사 로그 `student.delete`의 `detail`에 건수를 포함한다.
- **DES-26(신설) 포털 조회 서비스:** 기존 서비스의 내부 함수를 **재사용**하고 엔드포인트는 따로 둔다(포털 응답은 다른 학생 정보를 담지 않도록 별도 Pydantic 모델로 좁힌다).
  - `GET /portal/students` → `[{id, name, grade, status, classes: [{id, name, teacher_name}]}]` 연결 학생(재원·휴원).
  - `GET /portal/students/{id}/summary` → `{attendance: {last_30_days: {present, total}, all_time: {...}}, latest_session: {...기록 1건}, latest_tests: [...3건], timetable: [{class_name, weekday, start_time, end_time}]}`.
  - `GET /portal/students/{id}/sessions?before=&limit=20` → `[{date, class_name, progress: [{period, content}], homework, video_url, teacher_note, test_name, attendance, attendance_reason, homework_grade, grade_comment, recheck, test_score, class_average, comment}]`. `daily.py`의 이력 헬퍼(FR-45)와 `messaging.py`의 등급 문구 조회를 공유한다.
  - `GET /portal/students/{id}/test-trend?count=10|20` → `stats.py`의 학생 통계 함수(FR-24) 결과 중 본인 회차만.
  - `GET /portal/students/{id}/exams` → `[{exam_id, name, exam_date, score, max_score}]`, `GET /portal/students/{id}/exams/{exam_id}` → `{..., answers: [{no, raw_value, is_correct, points}]}`. 문항별 정답률 등 반 단위 통계는 담지 않는다.
  - `GET /portal/students/{id}/consults` → 본인 기록 전부 `[{consulted_on, content, follow_up}]`(방식 A).
  - `GET /portal/students/{id}/messages?before=&limit=20` → `[{sent_at, body}]` 성공 발송의 스냅샷, 같은 세션 중복 제거, `is_test` 제외.
  - 모든 포털 엔드포인트는 `student_id ∉ scope.student_ids`이면 403.
- **DES-01 Web SPA(확장):** `App.tsx`가 `role`이 포털 역할이면 `PortalApp`(별도 셸·라우트 `/portal/*`)을 그린다. `ForcedPasswordChange`·`LoginForm`·테마는 재사용한다. 포털 셸은 상단에 학원명·자녀 선택(자녀 2명 이상일 때)·로그아웃, 하단 탭(홈·기록·추이·시험·상담·문자)이다. 모바일 우선, 공통 컴포넌트(DES-24) 사용. 원장·강사 셸의 라우트는 포털 역할에서 렌더되지 않는다.
- **학생 관리 화면(확장):** 학생 목록에 "포털" 열(학생/학부모 상태 배지), [수정] 창에 "포털 계정" 구획(상태·[발급]/[재발급] 버튼·비활성 사유 안내). 원장만 버튼이 보인다.
- **데이터 모델(변경):**
  - `user_role` 열거형에 `student`·`guardian` 추가.
  - `app_user.issued_at`(timestamptz, NULL 허용) — 발급·재발급 시각. 포털 역할만 쓴다.
  - `app_user_student`(신설) — `user_id`(FK `app_user`, PK), `student_id`(FK `student`, PK), `guardian_id`(FK `guardian`, NULL 허용, 학부모 계정이 어느 보호자 번호로 발급됐는지), `created_at`.
  - 포털 계정도 `app_user_campus`에 학생의 캠퍼스 1행을 가진다(기존 세션·캠퍼스 코드 재사용).
  - 마이그레이션 1건, `downgrade` 제공.
- **보안·운영:** 비밀번호 해시·세션·잠금·`Secure` 쿠키는 기존 그대로. 포털 역할의 권한 거부도 감사 로그에 남긴다(NFR-10). 포털 응답에는 전화번호·보호자 정보를 넣지 않는다. 설정값 `MATHDESK_PORTAL_ISSUE_TTL_DAYS`(기본 7).
- **성능:** 포털 조회는 학생 1명 단위라 기존 이력·통계 쿼리보다 가볍다. 별도 집계 테이블 없음.

## 남은 위험과 미해결 사항

- **선점 위험:** 초기 비밀번호가 전화번호라 번호를 아는 제3자(현실적으로 학생이 학부모 계정)가 먼저 로그인해 바꿀 수 있다. 7일 만료·재발급·감사 로그로 완화하되 완전히 막지는 못한다. 원장이 발급 직후 학부모에게 알리는 운영 절차를 안내문에 둔다.
- **학생 연락처 부재:** 학생 번호가 없는 학생이 많으면 학생 계정 효용이 낮다. 학부모 계정이 주 경로다.
- **공개 표면 확대:** 로그인 주체가 늘어 잠금 임계값·로그 양이 늘 수 있다. 기본값 유지, 운영에서 관찰(NFR-10).
- **상담 기록 품질:** 방식 A라 강사가 쓰는 상담 내용이 모두 학부모에게 보인다. 내부 메모는 상담일지가 아닌 곳(성적 비고 등)에 쓰도록 안내문에 둔다.
