# DCR-005: 화면별 차등 모바일 지원

> 문서 유형: `dcr`
> 작업 ID: `20260922-mathdesk-baseline`

> 기준선: `v6`
> 작성일: `2026-09-23`
> 최종 갱신: `2026-09-23`
> 관련 문서: [REQ-mathdesk: 요구사항](../../requirements.md), [DESIGN-mathdesk: 설계](../../design.md), [ADR-010: 웹 UI 디자인 시스템](./ADR-010-웹-UI-디자인-시스템.md), [DCR-003](./DCR-003-브랜드-자산으로서의-시각-설계.md), [결정 등록부](../../decisions.md)

## 요약

- 변경 분류: **요구사항 변경** — 지원 환경(NFR-14)과 사용성 요구(NFR-13)의 적용 범위가 바뀐다.
- 변경 요지: 최소 지원 폭을 1280px에서 **390px**로 내리되 **화면마다 목표를 다르게** 둔다. 조회·발송 중심 화면은 휴대폰에서 완전히 사용 가능해야 하고, **일일 수업 입력은 데스크톱을 전제**로 유지한다. NFR-13의 키보드 이동은 데스크톱 요구사항임을 명시한다.
- 사용자 재승인 결과: **승인 (2026-09-23)** — 기준선 `v5` → `v6` 발행
- 우선순위: **후순위.** [TASK-45](../../plan.md#task-45-리포트-카드-html-렌더러-전환)·[TASK-46](../../plan.md#task-46-카드-재설계와-브랜드-반영)(리포트 카드) 뒤에 수행한다.

## 변경 사유와 증거

- **계기:** 사용자가 **휴대폰(약 390px)** 으로 테스트 운영 주소를 열어 화면을 확인했고, 헤더 메뉴가 한 글자씩 세로로 쪼개지는 것을 스크린샷 5장으로 보고했다.
- **즉시 조치(완료):** nav 링크의 줄바꿈 방지는 [경량 경로로 수정](../../plan.md)했다. 이 DCR의 대상이 아니다.
- **드러난 사실:** 기준선은 "업무용 도구 = 데스크톱"을 전제로 [NFR-14](../../requirements.md#비기능-요구사항)를 1280px 이상으로 고정했다. **그 전제가 실제 사용과 다르다.** 사용자가 원장으로서 외부에서 대시보드와 발송 화면을 보는 상황이 실재한다.
- **검증되지 않은 전제였다:** 요구사항 도출 시 모바일 필요 여부를 사용자에게 확인한 기록이 없다. [DCR-003](./DCR-003-브랜드-자산으로서의-시각-설계.md)에서 디자인 요구사항이 통째로 누락되었던 것과 같은 종류의 도출 단계 누락이다.
- **보류한 구현:** 없음. 모바일 대응 코드는 작성하지 않았다.

## 기존 설계와 제안 설계

### 기존 (기준선 `v5`)

- [NFR-13](../../requirements.md#비기능-요구사항): "일일 입력 화면은 마우스 이동을 최소화하는 표 기반 입력과 키보드 이동을 지원해야 한다." 적용 환경을 명시하지 않는다.
- [NFR-14](../../requirements.md#비기능-요구사항): "최신 Chrome·Edge·Safari에서 **1280px 이상** 화면을 지원한다."
- [DES-24 상세](../../design.md#des-24-상세): "1280px 이상 데스크톱 전용(NFR-14). 모바일 반응형은 범위 밖."

### 제안 (기준선 `v6`)

화면을 두 부류로 나누고 목표를 다르게 둔다.

| 부류 | 화면 | 휴대폰(390px) 목표 |
|---|---|---|
| 조회·발송 | 종합 대시보드, 알림문자, 학생/반 **목록** | **완전히 사용 가능.** 가로 스크롤 없이 읽고 조작한다 |
| 밀집 입력 | 일일 수업 & 성적 입력, 학생/반 **등록 폼** | **데스크톱 전제.** 휴대폰에서는 표를 가로 스크롤로 읽고 간단한 수정만 가능하면 된다 |

- **NFR-14 개정:** 최소 지원 폭 390px. 화면 부류별 목표를 위 표로 규정한다.
- **NFR-13 명확화:** 키보드 이동과 마우스 이동 최소화는 **데스크톱 요구사항**임을 명시한다.
- **AC-35 신설:** 390px에서 조회·발송 화면이 가로 스크롤 없이 조작 가능하다.
- **DES-24 상세 갱신:** 대상 환경 항목을 부류별 목표로 교체한다.

## 변경 항목

| 항목 | 기존 | 변경 | 이유 |
|---|---|---|---|
| NFR-14 | 1280px 이상 지원 | 최소 390px. 화면 부류별 목표 차등 | 실제 사용 환경이 전제와 달랐다 |
| NFR-13 | 적용 환경 미명시 | 키보드 이동·마우스 최소화는 **데스크톱** 요구사항 | 휴대폰에는 키보드도 마우스도 없다. 명시하지 않으면 NFR-14와 충돌한다 |
| AC-35 | 없음 | **신설** — 390px에서 조회·발송 화면이 가로 스크롤 없이 조작 가능 | NFR-14 개정 검증 |
| DES-24 상세 | "1280px 이상 데스크톱 전용. 모바일 반응형은 범위 밖" | 부류별 목표와 레이아웃 방침 | 개정 반영 |

## 대안 분석

| 대안 | 장점 | 단점·위험 | 판단 |
|---|---|---|---|
| A. 화면별 차등 지원 (선택) | 실제 수요(외부에서 조회·발송)를 채우면서 NFR-13과 충돌하지 않는다. 일일 입력 표를 다시 짜지 않아도 된다 | 화면마다 지원 수준이 달라 "어디까지 되는지"를 문서로 관리해야 한다 | **채택** |
| B. 전 화면 균일 지원 | 사용자가 어느 화면이든 같은 기대를 갖는다 | 일일 입력 표(13명 × 5열, 행마다 버튼 10개)를 학생별 카드로 다시 짜야 한다. **휴대폰에서 NFR-13의 키보드 이동을 포기한다는 별개 결정이 필요**하고, 한 화면에 입력 방식 두 벌을 유지해야 한다 | 기각 — 비용 대비 수요가 불명확 |
| C. 태블릿(768px)까지만 | 작업량이 가장 적다 | 사용자가 실제로 쓰는 휴대폰 폭을 여전히 덮지 못해 이번에 보고된 문제가 남는다 | 기각 — 계기를 해결하지 못한다 |

**ADR을 만들지 않는 이유:** 이 변경은 지원 범위(요구사항)의 조정이며, 구현 수단은 [ADR-010](./ADR-010-웹-UI-디자인-시스템.md)이 이미 정한 Tailwind 반응형 유틸리티를 그대로 쓴다. 새로운 기술 결정이나 되돌리기 어려운 결정이 없다.

## 검증 방법

- **AC-35:** 390px 뷰포트에서 대시보드·알림문자·목록 화면을 렌더해 가로 스크롤이 발생하지 않고 주요 조작 요소에 접근 가능함을 확인한다(VER-35).
- 기존 웹 테스트 36건이 수정 없이 통과해야 한다. 역할·레이블 보존 원칙([DES-24](../../design.md#des-24-상세))은 그대로다.
- 실제 기기 확인은 자동화하지 않고 사용자 육안 확인으로 둔다.

## 남은 위험과 미해결 사항

- 일일 입력 화면의 휴대폰 사용성은 "가로 스크롤 조회 + 간단 수정" 수준에 머문다. 실사용에서 부족하다고 판단되면 대안 B를 다시 검토해야 하며, 그때는 별도 DCR이 필요하다.
- 조회 화면의 "가로 스크롤 없이"는 발송 내역·학생 목록처럼 열이 많은 표에서 달성하기 어려울 수 있다. 표 자체의 가로 스크롤은 허용하되 **페이지 본문이 가로로 밀리지 않는 것**을 기준으로 삼는다.
