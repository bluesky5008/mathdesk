## 요약

- 변경 분류: **요구사항 변경 + 공개 인터페이스 추가** — 일일 입력 [학생별 정보] 탭의 내용(학생 이름부터 표 끝까지)을 **이미지 파일로 저장·복사**할 수 있게 한다(FR-45 상세 보강, AC-47 신설). 알림 문자의 [리포트 이미지 저장]과 같은 방식이다. 조회 전용 REST 1건을 더한다. 데이터 모델 변경은 없다.
- 변경 요지: ① 서버가 학생별 정보 카드 HTML(머리말: 학원명·로고·학생 이름·반·기간, 요약 2개, 날짜별 표)을 조립해 기존 리포트 렌더러(헤드리스 Chromium, [ADR-011](./ADR-011-리포트-카드-HTML-렌더링.md))로 PNG를 만든다 — `GET /daily/history-image`. ② [학생별 정보] 탭의 학생 선택 옆에 **[이미지 복사]·[이미지 저장]** 버튼을 둔다. 저장 파일명은 `학생별정보-<학생명>-<선택 날짜>.png`.
- 사용자 결정 필요: 없음(이미지의 폭·구성은 Claude 추천안으로 정했다. 수정 요청으로 바꿀 수 있다).
- 사용자 재승인 결과: **승인 (2026-10-11)** — 기준선 `v21` → `v22` 발행

## 변경 사유와 증거

- **계기:** 사용자 요청(2026-10-11) — "학생별 정보 탭에 출력된 정보를 이미지 파일로 출력하고 싶다. 알림 문자의 리포트 이미지 저장과 같은 기능이다. 범위는 학생 이름부터 아래까지 전체 내용."
- **확인한 사실:**
  1. 알림 문자의 [리포트 이미지 저장]은 `GET /api/messages/report-image`가 돌려주는 PNG를 웹이 `downloadImage(url, 파일명)`(`<a download>`)로 받는 구조다. [이미지 복사]는 같은 URL을 `copyImage`로 클립보드에 넣는다(`apps/web/src/clipboard.ts`).
  2. PNG는 서버의 `report.py`가 만든다: HTML 템플릿에 웹과 같은 `tokens.css`를 인라인하고 `ReportRenderer`(FastAPI lifespan 동안 warm 상태의 Chromium 1개)가 `body`를 촬영한다. 폭 760 CSS px, 2배 촬영(`CARD_WIDTH`·`SCALE`). 브랜드 색·로고는 `branding.load_brand`로 읽고 웹 테마는 따르지 않는다(DES-08 상세).
  3. 렌더러는 이미 **템플릿 2종**(리포트 카드, 난이도 분석표 `render_difficulty_html`)을 쓴다. `render_html(html)`이 공개 메서드라 세 번째 템플릿을 더하는 데 렌더러 변경이 필요 없다.
  4. [학생별 정보] 탭의 데이터는 `GET /daily/history`(DCR-020) 하나로 모두 나온다(학생·반·행). 요약 2개(출석 N/M회·테스트 평균)는 웹이 행에서 계산한다 — 이미지에서도 같은 식으로 서버가 계산하면 된다.
  5. 표는 6열(날짜·출결·이전 과제 재검사·과제피드백·테스트·코멘트)이다. 리포트 카드 폭 760에 6열을 넣으면 코멘트가 좁아진다.
  6. 시각 회귀 테스트(`test_report_visual.py`)는 기준 이미지가 있을 때만 돌고 컨테이너에서 만든다. 새 카드에는 기준 이미지를 두지 않아도 기존 테스트는 영향이 없다.
- **보류한 구현:** 없음(구현 시작 전).

## 제안 (기준선 `v22`)

### 요구사항

- **FR-45 상세 보강 — 이미지 저장:** [학생별 정보] 탭은 보이는 내용(학생 이름부터 표 끝까지)을 **이미지 파일로 저장**하고 **클립보드에 복사**할 수 있다. 학생 선택 옆에 [이미지 복사]·[이미지 저장] 버튼을 둔다. 이미지는 학원 브랜드(FR-40: 학원명·로고·시그니처 색)를 따르고 웹 테마(FR-41)를 따르지 않으며, 리포트 카드(FR-20)와 같은 디자인 토큰을 쓴다(NFR-18). 이미지의 내용은 그 시점 화면의 학생·반·선택 날짜·회차 수와 같다. 파일명은 `학생별정보-<학생명>-<선택 날짜>.png`.
- **이미지 구성(위에서 아래로):**
  1. 머리말(브랜드 색 배경): 학원명(로고가 있으면 로고), `<학생명> 학습 기록`, `<반명> · <선택 날짜>까지 최근 <N>회`
  2. 요약 타일: `출석 N / M회`, `테스트 평균 X점 (N회)`(표본 없으면 `—`)
  3. 표: 날짜(요일) · 출결(상태·사유) · 이전 과제 재검사 · 과제피드백 · 테스트(테스트명, 점수 / 반평균) · 코멘트 — 화면과 같은 열·같은 값·같은 순서. 기록이 없으면 표 대신 "선택한 날짜까지 기록이 있는 수업이 없습니다"
- **AC-47(신설) 학생별 정보 이미지:** ① [학생별 정보]에서 학생을 고르고 [이미지 저장]을 누르면 `학생별정보-<학생명>-<날짜>.png`가 내려받히고, [이미지 복사]를 누르면 같은 이미지가 클립보드에 들어간다. ② 이미지에는 학원명, 학생 이름, 반명, 화면 표와 같은 날짜·출결·재검사·등급·테스트명·점수/반평균·코멘트가 있고, 조회만 한 날은 없다. ③ 요약의 출석·테스트 평균이 화면의 요약과 같다. ④ 학원 시그니처 색을 바꾸면 머리말 색이 바뀌고 웹 테마를 바꿔도 이미지는 바뀌지 않는다. ⑤ 강사가 담당하지 않는 반 학생의 이미지 API는 403이고, 로그인 없이는 401이다. ⑥ 응답은 `image/png`이며 캐시되지 않는다.

### 설계

- **데이터 모델:** 변경 없음. 마이그레이션 없음.
- **REST 추가(일일 기록, 조회 전용):** `GET /daily/history-image?class_id=&student_id=&to=&limit=` → `image/png`. 매개변수·권한·행 구성은 `GET /daily/history`와 같다(같은 함수로 `HistoryOut`을 만든 뒤 렌더). 응답은 기존 API와 같이 캐시 금지 헤더를 받는다(기존 미들웨어).
- **렌더 템플릿(DES-08 상세에 추가):** `report.render_history_html(history: HistoryOut, campus_name, brand_colour, logo_data_url)`. 기존 카드의 머리말(`.hero`)·요약(`.facts`)·토큰 인라인·브랜드 색 검증(`HEX_COLOUR`)·`header_ink`를 그대로 쓰고 표 스타일만 더한다. **폭은 960 CSS px**(6열 표를 위해 리포트 카드 760보다 넓게), 2배 촬영은 같다. `ReportRenderer.render_html`에 폭 인자를 더해 템플릿별 폭을 받는다(기본 760, 기존 호출 불변). 외부 입력은 모두 `escape`한다.
- **요약 계산:** 서버가 행에서 계산한다(등원 `present·late·early_leave` 수 / 행 수, 점수 평균 소수 1자리). 웹과 같은 규칙이다.
- **화면:** `StudentDailyPage`의 학생 선택 줄 오른쪽에 [이미지 복사]·[이미지 저장] 버튼(`outline`). URL은 `api.ts`의 `dailyHistoryImageUrl(classId, studentId, to, limit)`. 동작은 `clipboard.ts`의 `copyImage`·`downloadImage` 재사용. 학생이 없으면 버튼 비활성.
- **브랜드:** `branding.load_brand(session, campus_id)`로 색·로고를 읽고, 학원명은 `Campus.name`(스코프의 캠퍼스).
- **성능(NFR-19):** 카드 1장과 같은 경로(warm 브라우저, 페이지 1개). 행 20개 표라 리포트 카드보다 조금 길지만 수 초 안이다.

## 대안 분석

| 대안 | 장점 | 단점·위험 | 판단 |
|---|---|---|---|
| A. 서버 HTML 템플릿 → 기존 Chromium 렌더러 PNG | 리포트 카드와 같은 경로·같은 토큰·브랜드 반영. 렌더러·다운로드·복사 코드 재사용. 웹 테마에 좌우되지 않는다 | 템플릿 1개·REST 1개 추가 | **채택** |
| B. 브라우저에서 화면 DOM을 캔버스로 촬영(html2canvas 등) | 서버 변경 없음 | 새 의존성(ADR-010 저장소 소유 원칙과 충돌), 사용자 테마 색이 그대로 찍혀 사람마다 다른 이미지, 폰트·레이아웃이 브라우저마다 다름 | 기각 |
| C. 브라우저 인쇄(PDF) | 구현 거의 없음 | 이미지 파일이 아니고 "리포트 이미지 저장과 같은 기능" 요청에 어긋남 | 기각 |
| 폭 760(리포트 카드와 동일) | 상수 공유 | 6열 표에서 코멘트 열이 좁아 줄바꿈이 많아진다 | 기각 — 960 |
| 화면 그대로 7열(학생 선택 포함) 캡처 | 요청 문구 그대로 | 선택 컨트롤은 정보가 아니다. 학생 이름은 머리말에 크게 넣는다 | 기각 — 머리말에 이름 |

**ADR을 만들지 않는 이유:** ADR-011의 결정(HTML/CSS → Chromium, warm 브라우저)을 그대로 적용해 템플릿을 하나 더하는 변경이며 새 기술·경계·계약 형식을 도입하지 않는다.

## 검증 방법

- API(선행 테스트): `history-image`가 `image/png`·폭 960×2를 돌려주고(AC-47 ⑥), 내용이 바뀌면 이미지가 바뀌며, 비로그인 401·담당 외 403(⑤). `render_history_html`이 학원명·학생명·반명·행의 값(날짜·출결 라벨·재검사·등급·테스트명·점수/반평균·코멘트)과 요약(출석 N/M회·평균)을 담고(②③), 빈 행이면 안내 문구, 외부 입력은 이스케이프, 브랜드 색은 `--md-color-brand`만 덮고 `data-theme`가 없다(④). 기존 `render_html` 호출(폭 기본값) 불변.
- 웹(선행 테스트): 버튼 2개와 비활성 조건, [이미지 저장] 클릭 시 `downloadImage(url, '학생별정보-학생1-2026-09-18.png')`, [이미지 복사] 클릭 시 `copyImage(url)`.
- API·웹 전체, `npm run build`. 공개 주소: 고1 인A 오인성으로 PNG를 받아 눈으로 확인.

## 남은 위험과 미해결 사항

- 코멘트가 길면 행이 높아져 이미지가 길어진다. 20행 상한이 있어 무한히 길어지지는 않는다.
- 시각 회귀 기준 이미지는 이 카드에 두지 않는다(리포트 카드만 기준 이미지가 있다). 필요해지면 컨테이너에서 추가한다.
