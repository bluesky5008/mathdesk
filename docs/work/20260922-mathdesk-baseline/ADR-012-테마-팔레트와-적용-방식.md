## 요약

- 결정: 웹 테마를 **`data-theme` 속성으로 전환하는 순수 CSS 팔레트**로 구현하고, 테마는 **브라우저에 저장하는 개인 설정**으로 둔다. 팔레트는 **색 토큰만** 덮어쓰고 타이포·간격·라운드·그림자 스케일은 전 테마 공통으로 고정한다. 리포트 카드는 테마를 따르지 않고 `light` 팔레트에 학원 시그니처 색(FR-40)을 얹는다.
- 핵심 이유: 색과 스케일을 분리하면 "웹은 개인 취향, 카드는 학원 브랜드"라는 두 목적이 서로를 침범하지 않으면서도 **한 토큰 파일**을 계속 공유한다. NFR-18의 일관성은 색이 아니라 스케일에서 나온다.
- 주요 단점: 색 토큰이 5벌로 늘어 팔레트 하나를 빠뜨리면 그 테마에서만 깨진다. 테스트로 막는다.

## 배경

[ADR-010](./ADR-010-웹-UI-디자인-시스템.md) 결정 7은 "다크 모드는 토큰 레벨에서 지원하되 초기 기본값은 라이트"로 정했고, [TASK-44](../../plan.md#task-44-디자인-토큰과-공통-컴포넌트-기반)가 `tokens.css`에 `.dark` 블록 하나를 두는 것으로 구현했다. 실제 화면에는 전환 수단이 없어 그 블록은 쓰이지 않는 상태다.

사용자가 라이트·다크에 더해 **블루·그린·핑크**를 요청했다. 이는 토큰 레벨 지원을 넘어 **사용자가 고르는 제품 기능**이므로 요구사항 변경이다.

동시에 [FR-40](../../requirements.md#기능-요구사항)이 이미 "학원 시그니처 색을 리포트 카드와 **웹 화면**에 반영"을 규정하고 있어 충돌한다. 학원 시그니처 색이 빨강인데 강사가 블루모드를 고르면 웹 화면의 주색이 무엇인지 기준선이 답하지 못한다.

사용자 결정(2026-09-23): **테마는 개인 설정이다.** 원장과 강사가 각자 다른 테마를 쓰며, 학원 시그니처 색은 학부모에게 가는 리포트 카드에만 쓴다.

## 영향을 받는 요구사항과 제약

- [FR-40](../../requirements.md#기능-요구사항): "웹 화면에 반영" 부분이 테마와 충돌한다. 카드 전용으로 좁혀야 한다.
- [NFR-18](../../requirements.md#비기능-요구사항): "색·간격·타이포를 단일 디자인 토큰에서 취해 시각적으로 일관" — 테마마다 색이 달라지므로 일관성의 정의를 스케일 기준으로 고쳐야 한다.
- [AC-31](../../requirements.md#인수-조건): "같은 토큰 값(주요 색·타이포 스케일)을 사용" — 색은 더 이상 같지 않다.
- [NFR-14](../../requirements.md#비기능-요구사항): 1280px 이상 데스크톱. 테마 전환 UI도 같은 환경만 고려한다.
- `tokens.css`의 순수 CSS 제약([ADR-011](./ADR-011-리포트-카드-HTML-렌더링.md)): 카드 렌더러가 이 파일을 `<style>`에 그대로 인라인하므로 팔레트도 전처리 문법 없이 표현해야 한다. [VER-30](../../plan.md#검증-계획)의 기존 테스트가 이를 강제한다.

## 고려한 대안

### 가. 테마 전환 방식

| 대안 | 장점 | 단점·위험 |
|---|---|---|
| A. `data-theme` 속성 + CSS 변수 덮어쓰기 (선택) | 순수 CSS로 표현되어 카드 인라인 제약을 그대로 만족. 런타임 재계산 없음. 카드가 `data-theme="light"`를 명시해 테마를 고정할 수 있다 | 팔레트 수만큼 블록이 늘어난다 |
| B. 클래스(`.dark`·`.blue`) | 현재 구현과 같은 방식 | 5개로 늘면 클래스 충돌·중복 적용 위험이 있고, 어느 테마인지 읽어내려면 클래스 목록을 뒤져야 한다 |
| C. JS로 CSS 변수를 런타임 주입 | 팔레트를 서버에서 받아올 수 있다 | 파일이 더 이상 순수 CSS가 아니게 되어 카드 인라인이 깨진다. VER-30 위반 |

### 나. 테마가 덮어쓸 범위

| 대안 | 장점 | 단점·위험 |
|---|---|---|
| A. 색 토큰만 (선택) | 스케일이 고정되어 테마를 바꿔도 레이아웃이 흔들리지 않는다. 웹·카드가 스케일을 계속 공유해 NFR-18이 유지된다 | 테마 간 차이가 색에 한정된다 |
| B. 색 + 타이포·간격 | 테마별 개성이 커진다 | 화면 밀도가 테마마다 달라져 NFR-13의 표 기반 입력이 테마에 따라 불리해진다. 카드와의 공유 기반이 사라진다 |

### 다. 저장 위치

| 대안 | 장점 | 단점·위험 |
|---|---|---|
| A. `localStorage` (선택) | 서버·스키마 변경 0. 사용자별로 다르다는 의미가 저장 위치에 그대로 드러난다 | 브라우저를 바꾸면 초기화된다. 개인 설정이므로 수용 가능 |
| B. `app_user` 컬럼 추가 | 어느 브라우저에서나 유지 | 마이그레이션과 API가 필요하다. 취향 설정에 치르는 비용으로 과하다 |
| C. `integration_setting` | 기존 테이블 재사용 | 캠퍼스 단위 저장이라 **개인 설정이라는 결정과 어긋난다** |

## 결정

1. **`data-theme` 속성으로 전환한다.** `tokens.css`는 `:root`에 라이트 팔레트를 두고 `[data-theme='dark']`·`[data-theme='blue']`·`[data-theme='green']`·`[data-theme='pink']`가 색 토큰을 덮어쓴다. 전처리 문법을 쓰지 않으므로 카드 인라인 제약을 유지한다.

2. **테마는 색 토큰만 덮어쓴다.** 타이포 스케일·간격·라운드·그림자는 `:root`에만 정의하고 어느 팔레트도 재정의하지 않는다. 이것이 웹과 카드의 공유 기반이자 NFR-18의 근거가 된다.

3. **팔레트는 모두 같은 색 토큰 집합을 정의한다.** 하나라도 빠지면 그 테마에서만 색이 어긋나므로, 전 팔레트가 동일한 키 집합을 갖는지 테스트로 강제한다.

4. **블루·그린·핑크는 색조를 입힌 라이트 테마다.** 주색(`--md-color-brand`)뿐 아니라 배경·표면·테두리에도 같은 색조를 옅게 넣는다. 버튼 색만 바뀌면 "테마"가 아니라 "강조색 변경"으로 읽힌다.

5. **상태색(`success`·`warning`·`danger`)은 다크 팔레트에서만 재정의한다.** 출결 구분은 의미 전달이 목적이라 색조 테마에서 흔들리면 안 된다. 다크에서는 대비 확보를 위해 밝기만 올린다.

6. **테마는 `localStorage`에 저장하는 개인 설정이다.** 키는 `mathdesk-theme`. 첫 페인트 전에 적용해 화면이 번쩍이지 않게 한다.

7. **리포트 카드는 테마를 따르지 않는다.** 카드 템플릿은 `data-theme`를 지정하지 않아 `:root` 라이트 팔레트를 쓰고, `--md-color-brand`만 학원 시그니처 색(FR-40)으로 덮어쓴다. 학부모가 받는 자산이 강사의 취향에 좌우되면 안 된다.

8. **테마 선택 UI는 앱 셸 헤더에 둔다.** 모든 화면에서 같은 위치에 있어야 하고, 이미 있는 `Select` 공통 컴포넌트로 충분하다.

## 이유

1. 색과 스케일의 분리가 이 결정의 핵심이다. NFR-18이 지키려던 "시각적 일관성"은 실제로는 타이포 리듬과 간격 리듬에서 나온다. 색은 같을 필요가 없고, 오히려 웹(내부 도구)과 카드(학부모용 브랜드 자산)는 **달라야 하는** 자산이다.
2. `data-theme`는 순수 CSS 제약을 지키면서 카드가 팔레트를 **명시적으로 고정**할 수 있게 한다. 카드가 "테마를 안 따른다"를 코드로 표현할 수단이 생긴다.
3. 개인 설정이라는 사용자 결정이 `localStorage`라는 가장 싼 저장소를 정당화한다. 스키마·API·마이그레이션이 전부 불필요하다.
4. 전 팔레트 동일 키 집합을 테스트로 강제하면, 팔레트가 늘어날 때 생기는 유일한 실질 위험이 닫힌다.

## 결과와 감수할 단점

- 색 토큰이 5벌이 되어 `tokens.css`가 길어진다. 스케일은 한 벌이므로 증가분은 색에 한정된다.
- 브라우저를 바꾸면 테마가 초기화된다. 개인 취향 설정이므로 수용한다.
- FR-40의 "웹 화면에 반영"이 축소된다. 학원 시그니처 색은 웹 화면에서 더 이상 쓰이지 않는다.
- 테마별 대비(contrast) 점검이 5벌로 늘어난다. 상태색을 색조 테마에서 고정해 점검 대상을 줄였다.
