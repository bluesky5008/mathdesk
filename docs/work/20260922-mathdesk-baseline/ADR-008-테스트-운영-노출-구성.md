## 요약

- 결정: 테스트 운영은 전용 Cloudflare 터널 `mathdesk`가 단일 오리진(`localhost:8090`)으로 향하고, 그 오리진은 웹 정적 빌드를 함께 서빙하는 API 컨테이너가 담당한다. 접근 통제는 앱 로그인이며, 그 전제로 로그인 시도 제한을 필수화한다.
- 핵심 이유: 기존 home-wiki 서비스와 수명주기를 분리하면서, 개발 서버를 노출하지 않고 세션 쿠키가 단일 오리진에서 정상 동작하게 하는 가장 작은 구성이다.
- 주요 단점: 로그인 화면이 공개 인터넷에 노출되므로 시도 제한이 선행 조건이 되고, 테스트 운영용 이미지 빌드 경로가 하나 늘어난다.

## 배경

[ADR-001](./ADR-001-기술-스택과-실행-형태.md)은 Phase A를 로컬 `docker compose`, Phase B를 컨테이너 배포로 정했다. 실사용 피드백을 받으려면 그 사이에 원격 접근 가능한 형태가 필요하다.

이 맥미니는 이미 `cloudflared` 터널 `homewiki`로 `yongs-wiki.com`(→ `localhost:3000`)을 서비스하고 있고, mathdesk 개발 스택도 같은 장비에서 돈다. 현재 웹은 Vite 개발 서버이고, 세션 쿠키에 `Secure`가 없으며, 웹(5173)과 API(8080)가 서로 다른 오리진이다.

## 영향을 받는 요구사항과 제약

- [NFR-06 인증 보안](../../requirements.md#비기능-요구사항): HTTPS 노출 시 `Secure` 쿠키와 시도 제한이 필요하다.
- [NFR-08 이식성](../../requirements.md#비기능-요구사항): 테스트 운영도 같은 코드·같은 스키마를 써야 한다.
- 사용자 결정: 접근 통제는 앱 로그인, 터널은 분리, 데이터는 합성 시드, 시점은 지금.
- 개발 완료 후 배포처를 옮길 계획이므로 제거가 쉬워야 한다.

## 고려한 대안

| 대안 | 장점 | 단점·위험 | 전환 비용 |
|---|---|---|---|
| A. 전용 터널 + 단일 오리진 API 서빙 (선택) | home-wiki 무중단, 개발 서버 미노출, 쿠키 단일 오리진, 제거 용이 | 정적 빌드를 포함한 이미지 경로가 하나 늘어남 | 낮음 |
| B. 기존 터널에 ingress 추가 | 설정 한 블록 | cloudflared 재시작 시 home-wiki 순단, 수명주기 결합 | 낮음 |
| C. 웹·API를 각각 다른 하위 도메인으로 노출 | 컨테이너 구성 변경 없음 | 교차 오리진 쿠키 처리(`SameSite=None`·CORS)가 필요해 보안 설정이 복잡해짐 | 중간 |
| D. nginx 컨테이너를 앞단에 두고 정적 서빙 + `/api` 프록시 | 표준적 구성 | 컨테이너·설정 파일이 하나 더 늘어남. 현재 규모에 과함 | 중간 |
| E. Vite 개발 서버 직접 노출 | 작업 없음 | 소스맵·HMR 노출, `allowedHosts` 우회 필요, 운영 부적합 | 없음 |

## 결정

1. 전용 터널 `mathdesk`와 전용 launchd 서비스를 만들고 기존 `homewiki` 터널 설정을 수정하지 않는다.
2. 터널 ingress는 `mathdesk.yongs-wiki.com → http://localhost:8090` 하나이며, 그 외는 404다.
3. `localhost:8090`은 API 컨테이너가 담당한다. API는 `/api/*`를 처리하고 나머지 경로에서 웹 정적 빌드를 SPA fallback으로 서빙한다.
4. 세션 쿠키의 `Secure` 플래그는 `MATHDESK_COOKIE_SECURE` 설정값으로 제어하며 테스트 운영에서 `true`다.
5. 로그인 시도 제한을 노출 전 필수 조건으로 두며 기본값은 연속 실패 10회 → 3분 잠금이고 설정값으로 노출한다.
6. 테스트 운영 구성에서는 postgres와 API의 호스트 포트를 게시하지 않는다. 터널만 유일한 외부 경로다.
7. 테스트 운영 데이터는 합성 시드로 한정한다. 실제 학생·학부모 정보 투입은 별도 결정 대상이다.

## 이유

1. 터널 분리는 home-wiki의 가용성과 mathdesk의 잦은 재시작을 서로 독립시킨다. 배포처 이전 시에도 터널·DNS·launchd 3개만 제거하면 된다.
2. 단일 오리진은 `SameSite=Lax` 쿠키를 그대로 쓰게 해 준다. 교차 오리진으로 가면 `SameSite=None`과 CORS 허용이 필요해져 노출 환경에서 방어면이 넓어진다.
3. FastAPI가 이미 의존성에 있으므로 정적 서빙에 새 구성 요소(nginx)를 추가할 이유가 없다.
4. 앱 로그인만으로 공개하기로 한 이상, 시도 제한 없이 로그인 화면을 인터넷에 두는 것은 받아들이기 어려운 위험이다.

## 결과와 감수할 단점

- 로그인 화면이 공개 인터넷에 노출된다. 시도 제한과 Argon2id 검증 비용으로 완화하되, 위험이 커지면 Cloudflare Access를 터널 앞단에 추가한다.
- 테스트 운영용 이미지는 웹 빌드 산출물을 포함하므로 개발용 이미지와 빌드 경로가 다르다. 로컬 개발은 기존 2컨테이너 구성을 그대로 쓴다.
- 미완성 기능이 함께 노출된다. 합성 데이터와 테스트 운영 표시로 오해를 줄인다.
