# ADR-016: 운영 기록 분리 — 클라이언트 운영 기록은 비공개 저장소에

> 문서 유형: `adr`
> 작업 ID: `20260922-mathdesk-baseline`
> 상태: `approved`
> 기준선: `v28` (요구사항·설계의 의미 변화 없음 — 새 기준선을 발행하지 않는다)
> 작성일: `2026-11-11`
> 최종 갱신: `2026-11-11`
> 관련 문서: [ADR-013: 운영 배포처](./ADR-013-운영-배포처-클라이언트별-Lightsail-단일-서버.md), [ADR-015: 배포 파이프라인](./ADR-015-배포-파이프라인.md), [작업 기록](./work-log.md), [결정 등록부](../../decisions.md)

## 요약

- 결정 대상: 공개 저장소에 쌓이던 클라이언트 운영 기록(계정 번호·도메인·담당자·서버 구축 경과·사고 경위)을 어디에 둘지, 이미 올라간 이력은 어떻게 할지.
- 결정(사용자, 2026-11-11): **이 저장소는 공개로 유지하고, 클라이언트 운영 기록만 비공개 저장소 `mathdesk_private`로 옮긴다. 이미 올라간 식별 정보는 git 이력 재작성으로 지운다. 앞으로도 분리해서 기록한다.**
- 바뀌는 것: 작업 기록의 운영 이관 절 11개를 요약 1개로 대체, 인계 절의 운영 관련 "다음 행동"은 비공개 쪽이 정본. 2026-10-20의 "전화번호 이력 유지" 결정(선택 1)은 이 결정으로 **대체**된다.
- 요구사항·설계·코드·배포 구성은 바뀌지 않는다.

## 배경

- 저장소가 공개인 것은 [ADR-015](./ADR-015-배포-파이프라인.md)의 전제다. 환경 비밀값과 필수 승인자는 무료 요금제에서 공개 저장소에만 제공된다(GitHub 문서, 2026-11-11 확인). 비공개로 바꾸면 배포 키 보관과 승인 절차가 동작하지 않고, Pro로 올려도 필수 승인자는 돌아오지 않는다. 컨테이너 이미지의 공개 여부는 저장소와 별개라 저장소만 비공개로 바꿔도 코드는 가려지지 않는다.
- 2026-11-11 전수 검사(추적 파일 293개, 커밋 222개): API 키·토큰·비밀번호·개인키·서버 주소는 없다. 남아 있던 것은 전화번호 원문 1건(2026-10-20 커밋), 담당자 실명, 클라이언트 AWS 계정 번호, 도메인, 문자 서비스 아이디, 그리고 서버 구축 경과·사고 경위·클라이언트 사정의 서술이다.
- 보안 위험은 낮다(이 정보만으로 계정·서버 접근 불가). 문제는 개인정보(실명·전화번호)와 클라이언트 신뢰다 — 클라이언트의 운영 사정이 공개 저장소에 계속 쌓인다.

## 검토한 대안

| 대안 | 내용 | 판단 |
|---|---|---|
| A. 저장소 전체 비공개 | 저장소를 private로 | 기각 — 배포 키 보관·승인 절차 상실, 이미지는 여전히 공개, Actions 사용량 유료 구간 |
| B. 공개 유지 + 식별 정보만 가림 | 실명·번호만 지우고 경과는 공개에 계속 기록 | 기각 — 운영 사정의 서술이 계속 쌓인다 |
| **C. 공개 유지 + 운영 기록 분리** | 운영 기록만 비공개 저장소로, 이력 재작성 | **채택** |

분리 방식도 세 가지를 비교했다: 공개 저장소 안의 추적 제외 폴더(설정이 한 번 어긋나면 같은 문제 재발), 서브모듈(비공개 저장소 주소·커밋이 공개에 남고 워크플로 권한이 복잡), **나란히 둔 독립 저장소(채택 — 물리적으로 분리돼 섞일 길이 없다)**.

## 결정

1. **저장소 두 개, 나란히 둔다.** 로컬 `…/mathdesk/`(공개)와 `…/mathdesk_private/`(비공개)는 서로 독립된 git 저장소이고 각자 자기 원격에만 연결한다. 서브모듈·심볼릭 링크를 두지 않는다.
2. **기록 위치.**

   | 내용 | 위치 |
   |---|---|
   | 코드, 테스트, 워크플로, 배포 스크립트·절차서 | 공개 |
   | 요구사항, 설계, ADR·DCR, 계획, 기능 작업 기록 | 공개 |
   | 운영 상태 한 줄("밤 서버 가동, 태그 …") | 공개 |
   | 클라이언트 계정 번호, 도메인, 서버 주소, 문자 서비스 아이디, 담당자 이름·전화번호 | 비공개 `clients.md` |
   | 서버 구축·이관 경과, 사고 경위, 클라이언트 사정, 클라이언트별 다음 할 일 | 비공개 `ops-log.md` |
   | 비밀번호, API 키, 토큰, SSH 개인키 | **어느 저장소에도 적지 않는다** |

3. **공개 저장소에서는 클라이언트를 별칭(밤·핑수)으로만 부른다.** 환경 이름 `bam`·`pingsu`도 별칭이다.
4. **링크 방향.** 공개 문서는 비공개 문서로 링크를 걸지 않는다(글로만 "비공개 운영 기록"). 비공개 문서는 `../mathdesk/…`로 공개 문서를 가리킨다.
5. **커밋.** 한 작업이 양쪽을 건드리면 각 저장소에 따로 커밋·push한다. TASK 단위 커밋·push 규칙은 두 저장소에 같이 적용한다.
6. **재개 순서.** 공개 작업 기록의 인계 절 → 비공개 `ops-log.md`의 "다음 할 일". 운영 이관의 다음 행동은 비공개 쪽이 정본이다.
7. **이력 재작성(1회).** 재작성 전 상태를 백업한 뒤, 모든 커밋에서 (a) 옮긴 작업 기록 절을 지우고 (b) 전화번호 원문·담당자 실명·AWS 계정 번호·도메인·문자 서비스 아이디를 가린 문자열로 바꾼다. 커밋 메시지에도 같은 치환을 적용한다. 릴리스 태그는 새 커밋에 다시 단다(이미지는 그대로). 학원 이름(시드·개요 문서)과 스테이징 주소는 그대로 둔다.
8. **커밋 전 확인.** 공개 저장소에 커밋하기 전 식별 정보·비밀값을 검색한다(계정 번호 12자리, 운영 도메인, 전화번호, 서버 주소, 키·토큰 형태).

## 결과

- 좋은 점: 배포 구조(ADR-015)를 건드리지 않고 클라이언트 정보가 공개 이력에서 빠진다. 운영 기록에 서버 주소·연락처를 가리지 않고 적을 수 있어 재개가 쉬워진다.
- 비용: 재개할 때 두 곳을 읽는다. 커밋 번호가 전부 바뀐다(이전 Actions 실행 기록은 옛 커밋을 가리킨다).
- 남는 위험: 재작성 전 공개 기간에 이미 복제·수집됐을 가능성은 없앨 수 없다(포크·스타 0). GitHub 서버의 옛 커밋 캐시는 지원 요청으로만 완전히 지워진다. 분리 규칙은 사람과 에이전트의 규율에 달려 있다 — 결정 8의 검색으로 보완한다.
