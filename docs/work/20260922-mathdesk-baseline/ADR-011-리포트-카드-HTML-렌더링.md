## 요약

- 결정: 리포트 카드를 **Pillow 직접 드로잉에서 HTML/CSS → 헤드리스 Chromium(Playwright) 스크린샷으로 전환**한다. 카드 템플릿은 [ADR-010](./ADR-010-웹-UI-디자인-시스템.md)의 `tokens.css`를 인라인해 웹 UI와 같은 브랜드 언어를 쓴다. 브라우저 인스턴스는 앱 수명주기 동안 1개를 warm 상태로 유지한다.
- 핵심 이유: 리포트 카드는 **학부모에게 반복 도달하는 유일한 시각 자산**이며 학부모 간 전파(스크린샷 공유)의 매개다. Pillow 직접 드로잉은 그라데이션·아이콘·차트·정교한 타이포 계층·그림자를 사실상 만들 수 없어 심미적 상한이 낮다.
- 주요 단점: 컨테이너 이미지가 약 300~400MB 증가하고 렌더 프로세스가 메모리를 점유한다.

## 배경

설계 [DES-08](../../design.md#컴포넌트와-책임)은 원래 "렌더된 본문을 **카드형 HTML로 구성해 이미지로 변환**"으로 정의되어 있었다. 구현 단계에서 [Q-10](../../design.md#가정과-미해결-질문)을 "서버에서 생성하되 헤드리스 브라우저 대신 이미지 라이브러리로 직접 그린다"로 해소했고, `report.py`(105줄)에 Pillow 기반 렌더러를 구현했다. **그때의 판단 기준은 의존성 무게였지 심미적 상한이 아니었다.**

사용자가 매출 확대 목표를 밝히면서 판단 기준이 달라졌다. 요구사항을 실측한 결과 학부모 도달 경로는 다음과 같다.

| 자산 | 학부모 도달 | 빈도 | 전파 |
|---|---|---|---|
| 리포트 이미지 카드([FR-20](../../requirements.md#기능-요구사항)) | 카톡·문자로 직접 | 매 수업 | 스크린샷 공유 가능 |
| 문자 본문 텍스트 | 직접 | 매 수업 | 제한적 |
| 난이도 분석표 카드([FR-30](../../requirements.md#기능-요구사항), 미구현) | 시험 때 | 시험마다 | 가능 |
| 웹 UI 12개 화면 | **도달하지 않음** | — | — |

[범위 · 제외](../../requirements.md#제외)가 "학부모·학생용 로그인 포털"을 명시적으로 제외하고, [대상과 시나리오](../../requirements.md#대상과-시나리오)가 수신자를 "시스템에 로그인하지 않음"으로 규정한다. 사용자도 도달 경로를 "카톡·문자로 받는 리포트 카드(현행)"로 한정 확인했다.

즉 **매출 관점의 심미 투자 1순위는 웹 UI가 아니라 리포트 카드다.**

현재 카드의 실측 상태: 760px 고정 폭, 단색 배경 + 둥근 사각형 + 상단 액센트 바 + 텍스트 나열, 폰트 3단계, 색 5개.

## 영향을 받는 요구사항과 제약

- [FR-20](../../requirements.md#기능-요구사항)·[FR-22](../../requirements.md#기능-요구사항): 카드 렌더와 클립보드 복사.
- [FR-30](../../requirements.md#기능-요구사항): 난이도 분석표 카드 이미지. 같은 렌더러를 재사용한다.
- [AC-16](../../requirements.md#인수-조건): "본문과 동일한 내용의 이미지". 내용 동치를 요구하며 시각 규격은 지정하지 않는다.
- **성능 예산 부재:** NFR-01·NFR-02는 대시보드와 일일 입력에 대한 것이고 카드 생성 시간에 대한 요구사항이 없다. 이 결정과 함께 [NFR-19](../../requirements.md#비기능-요구사항)를 신설한다.
- [NFR-04](../../requirements.md#nfr-04-상세): 카드에는 학생 식별 정보가 들어가지만 외부 API로 나가지 않는다. 렌더링은 서버 내부에서 끝난다.
- 컨테이너: `python:3.12-slim` + `fonts-nanum`([apps/api/Dockerfile](../../../apps/api/Dockerfile), [Dockerfile.testops](../../../Dockerfile.testops)).

## 고려한 대안

| 대안 | 심미적 상한 | 단점·위험 | 전환 비용 |
|---|---|---|---|
| A. Playwright(Chromium) 스크린샷 (선택) | **상한 없음.** 실제 브라우저이므로 Tailwind가 만드는 flex·grid·그라데이션·그림자·웹폰트·SVG 차트를 그대로 렌더 | 이미지 +300~400MB, 인스턴스 메모리, 콜드 스타트 | 중간 |
| B. WeasyPrint(Python 네이티브) | 중간. Pillow보다 훨씬 낫지만 CSS grid 미지원·flexbox 제한 | **Tailwind 출력을 제대로 그리지 못하면 토큰 공유의 핵심 이점이 무너진다.** 심미 상한이 목표인데 상한이 낮다 | 낮음 |
| C. Satori + resvg (HTML/JSX → SVG → PNG) | 높음. 경량 | 런타임에 Node 프로세스가 필요. Python 백엔드에 별도 런타임을 들이는 복잡도 | 중간 |
| D. Pillow 유지 + 디자인 강화 | 낮음. 사각형·텍스트·단색 위주 | 의존성 0으로 가장 안전하나 사용자가 지정한 판단 기준("미관 최우선")에 미달 | 낮음 |

사용자가 "변경 범위가 커지더라도 기능적으로 가장 좋고 미관적으로 가장 이쁜 솔루션"을 판단 기준으로 지정했으므로 A를 선택한다. B는 토큰 공유라는 구조적 이점을 살리지 못해 기각한다.

## 결정

1. **`report.py`를 HTML 템플릿 + Playwright(Chromium) 스크린샷 방식으로 교체한다.** 템플릿은 서버가 조립하며 [ADR-010](./ADR-010-웹-UI-디자인-시스템.md)의 `tokens.css`를 인라인한다.

2. **브라우저 인스턴스를 앱 수명주기에 1개 warm으로 유지한다.** FastAPI lifespan에서 기동·종료하며 요청마다 새 페이지만 연다. 콜드 스타트(1~2초)를 요청 경로에서 제거한다.

3. **[NFR-19](../../requirements.md#비기능-요구사항)를 신설한다** — 카드 1장 생성이 warm 상태에서 p95 3초 이내. 초과하면 이 결정을 재검토한다.

4. **난이도 분석표 카드([FR-30](../../requirements.md#기능-요구사항))도 같은 렌더러를 쓴다.** 템플릿만 다르다.

5. **웹 미리보기와 발송 이미지가 같은 HTML/CSS를 쓴다.** 현재는 Pillow가 따로 그려 미리보기와 실제 이미지가 갈라질 수 있다. 이 전환은 심미 개선이자 **정합성 개선**이다.

6. **시각 회귀를 스냅샷으로 고정한다.** 렌더 결과 이미지의 해시 또는 기준 이미지 비교를 테스트에 둔다. 폰트 가용성 차이로 로컬과 컨테이너 결과가 달라진 전례([TASK-18 작업 기록](./work-log.md#수행-기록))가 있으므로 **컨테이너에서 검증한다.**

7. **Playwright는 Chromium만 설치한다.** `playwright install --with-deps chromium`. Firefox·WebKit은 받지 않는다.

## 이유

1. 카드는 학부모에게 반복 도달하고 전파되는 유일한 자산이다. 학원 신규 모집의 실제 경로가 학부모 입소문이라면, 그 입소문에 실려 나가는 물건에 심미 투자를 집중하는 것이 목표에 가장 직접적이다.
2. 760px 고정 캔버스를 서버에서 렌더하므로 브라우저·기기 차이가 없다. **웹 UI보다 오히려 디자인 통제가 완벽하다.**
3. 실제 브라우저를 쓰면 웹과 카드가 같은 CSS를 해석한다. 토큰 공유가 명목이 아니라 실질이 된다.
4. 브랜드(학원명·로고·시그니처 색)를 실을 자리가 생긴다. 매주 학부모 폰에 남는 브랜드 노출이다.

## 결과와 감수할 단점

- 컨테이너 이미지가 약 300~400MB 증가한다. 개발·테스트 운영 두 이미지 모두 해당한다.
- Chromium 프로세스가 상시 메모리를 점유한다(약 200MB). 맥미니 1대에서 home-wiki와 공존하므로 실측이 필요하다.
- 렌더러 장애가 카드 생성 실패로 이어진다. 실패 시 사용자에게 사유를 알리고 문자 본문 발송은 계속 가능해야 한다(카드는 첨부이지 본문이 아니다).
- 보안 표면이 늘어난다. 템플릿에 들어가는 값은 서버가 조립한 내부 데이터뿐이며 외부 입력을 렌더하지 않는다.
- Pillow 경로와 관련 테스트를 제거한다. 글리프 커버리지 테스트는 렌더러 교체로 의미가 달라지므로 새 방식에 맞게 다시 쓴다.
