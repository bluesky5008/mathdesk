## 변경 사유와 증거

사용자가 개발 중인 서버를 `yongs-wiki.com` 하위 도메인으로 노출해 테스트 운영하기를 요청했다. 승인된 기준선 `v1`은 실행 형태를 Phase A(로컬 `docker compose`)와 Phase B(Kubernetes)로만 규정하므로, 원격에서 접근 가능한 중간 형태가 기준선에 없다.

저장소·실행 환경에서 확인한 사실은 다음과 같다.

| 사실 | 확인 방법 |
|---|---|
| 이 장비(`yongseuui-Macmini.local`)가 mathdesk 개발 스택과 `yongs-wiki.com` 서비스를 함께 돌린다 | `hostname`, `docker compose ps`, `launchctl list \| grep homewiki` |
| 기존 터널 `homewiki`(`bcf8c378…`)가 `yongs-wiki.com → localhost:3000` 하나만 라우팅한다 | `cloudflared tunnel list`, `~/.cloudflared/config.yml` |
| 웹은 Vite 개발 서버로 기동된다(`npm run dev -- --host`) | [apps/web/Dockerfile](../../../apps/web/Dockerfile) |
| 세션 쿠키에 `Secure` 플래그가 없다 | [apps/api/src/mathdesk/auth.py](../../../apps/api/src/mathdesk/auth.py)의 `set_cookie` |
| 웹(5173)과 API(8080)가 서로 다른 오리진이며 개발 프록시로 연결된다 | [compose.yaml](../../../compose.yaml), [apps/web/vite.config.ts](../../../apps/web/vite.config.ts) |
| 로그인 시도 제한이 미구현이다 | [TASK-40](../../plan.md#task-40-로그인-시도-제한), [작업 기록의 설계와 달라진 점](./work-log.md#설계와-달라진-점) |

## 기존 기준선과 설계

- [범위](../../requirements.md#포함): "Phase A(로컬 `docker compose` 실행) 동작"만 포함하고, [제외](../../requirements.md#제외)에 "Phase B 실제 배포"를 둔다.
- [NFR-06](../../requirements.md#비기능-요구사항): 비밀번호 해시, 세션 쿠키 `HttpOnly`·`SameSite`, 유휴 만료만 규정한다. `Secure`와 시도 제한은 없다.
- [NFR-08](../../requirements.md#비기능-요구사항): Phase A와 Phase B가 동일 이미지를 쓰고 환경변수로 차이를 흡수한다.
- [설계 보안과 품질 속성](../../design.md#보안과-품질-속성): "로그인 실패 지연·시도 제한"을 규정하지만 요구사항에는 대응 항목이 없다.
- [설계 시스템 경계](../../design.md#시스템-경계와-구조): 브라우저 → SPA → FastAPI 경로만 있고 외부 노출 경계가 없다.

## 제안 설계

실행 형태에 **Phase A′ 테스트 운영**을 추가한다.

```text
인터넷 ── HTTPS ── Cloudflare ── cloudflared 터널 `mathdesk` (이 맥미니)
                                      │
                                      └── http://localhost:8090
                                              │
                                   [API 컨테이너: FastAPI]
                                     ├── /api/*        REST
                                     └── /*            web 정적 빌드(SPA fallback)
                                              │
                                        [postgres 컨테이너] (호스트 게시 없음)
```

1. **단일 오리진 서빙**: 웹을 정적 빌드하여 API 컨테이너가 함께 서빙한다. 개발용 Vite 서버를 노출하지 않고, 쿠키가 한 오리진에서 동작한다.
2. **Secure 쿠키**: `MATHDESK_COOKIE_SECURE`(기본 `false`, 테스트 운영 `true`)로 `Secure` 플래그를 켠다.
3. **로그인 시도 제한**: 노출 전 필수로 승격한다. 기본값은 **연속 실패 10회 → 3분 잠금**이며 설정값으로 노출한다.
4. **터널 분리**: 기존 `homewiki` 터널을 건드리지 않고 `mathdesk` 터널과 전용 launchd 서비스를 만든다.
5. **데이터**: 합성 시드만 사용한다. 실제 학생·학부모 정보를 넣지 않는다.
6. **노출 표면 축소**: 테스트 운영 구성에서 postgres 호스트 포트 게시와 API 직접 포트 게시를 제거한다.
7. **시크릿 교체**: 초기 원장 비밀번호와 DB 비밀번호를 개발용 값에서 교체한다.

## 영향 범위

- 요구사항과 인수 조건: NFR-06·NFR-08 수정, NFR-17·AC-28·AC-29 신설. 기존 FR은 변경 없음.
- 인터페이스와 데이터: REST 계약·데이터 모델 변경 없음. 쿠키 속성과 서빙 경로만 바뀐다.
- 보안과 운영: 새 외부 노출 경계가 생긴다. 시크릿 교체, 시도 제한, 포트 게시 축소가 선행 조건이다.
- 진행 중인 구현: 없음. TASK-12까지 완료·통합되었고 TASK-14는 착수 전이라 보류할 구현이 없다.
- 테스트와 문서: VER 항목 2개(AC-28·AC-29) 추가, README에 테스트 운영 절차 추가.

## 고려한 대안

| 대안 | 장점 | 단점·위험 | 전환 비용 |
|---|---|---|---|
| A. 별도 터널 + 단일 오리진 + 앱 로그인 (선택) | home-wiki 무중단, 개발 서버 미노출, 배포처 이전 시 깨끗이 제거 | 시도 제한이 선행 조건이 됨 | 낮음 |
| B. 기존 `homewiki` 터널에 ingress 추가 | 가장 빠름 | cloudflared 재시작 시 home-wiki 순단, 두 서비스 수명주기 결합 | 낮음 |
| C. Cloudflare Access(Zero Trust) 앞단 통제 | 미완성 앱을 공개하지 않음, 시도 제한 없이도 안전 | 접근자마다 이메일 정책 필요 — 사용자가 "앱 로그인만"을 선택 | 낮음 |
| D. Vite 개발 서버를 그대로 노출 | 추가 작업 없음 | 소스맵·HMR 노출, `allowedHosts` 우회 필요, 운영 부적합 | 없음 |

사용자 선택은 A이며, C는 기각이 아니라 선택되지 않았을 뿐이므로 필요해지면 터널 앞단에 추가할 수 있다.

## 구현된 코드의 처리

- 유지: TASK-02~TASK-12의 모든 구현과 검증 기록. 이 변경은 기존 동작을 바꾸지 않는다.
- 수정: 쿠키 설정(`Secure` 플래그 주입), `compose` 구성(테스트 운영용 오버레이 추가), `auth.py`(시도 제한 추가).
- 되돌림: 없음.

## 마이그레이션과 롤백

- 데이터 마이그레이션 없음. 테스트 운영도 같은 스키마·같은 Alembic 리비전을 쓴다.
- 기동: 테스트 운영 compose로 빌드·기동 → `cloudflared tunnel create mathdesk` → DNS 라우트 → launchd 등록.
- 롤백: `launchctl bootout`으로 터널 서비스 해제 → DNS 레코드 삭제 → 테스트 운영 컨테이너 중지. 기존 `homewiki` 터널과 home-wiki 서비스는 어느 단계에서도 건드리지 않는다.
- 개발 완료 후 배포처 이전 시, 이 구성은 launchd·터널·DNS 3개만 제거하면 흔적이 남지 않는다.
