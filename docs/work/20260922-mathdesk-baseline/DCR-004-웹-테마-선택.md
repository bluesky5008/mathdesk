## 요약

- 변경 분류: **요구사항 변경** — 제품 동작(테마 선택)과 인수 조건(AC-31)이 함께 바뀐다.
- 변경 요지: 웹에 라이트·다크·블루·그린·핑크 **5개 테마 선택**을 추가하고(FR-41 신설), 학원 시그니처 색(FR-40)의 적용 범위를 **리포트 카드 전용**으로 좁힌다. 디자인 일관성(NFR-18)의 기준을 색이 아니라 **타이포·간격·라운드·그림자 스케일**로 재정의한다.
- 사용자 재승인 결과: **승인 (2026-09-23)** — 기준선 `v4` → `v5` 발행

## 변경 사유와 증거

- **계기:** 사용자 요청(2026-09-23) — "색감은 현재를 라이트모드로 두고 다크모드, 블루모드, 그린모드, 핑크모드를 추가해줘."
- **발견한 충돌:** [FR-40](../../requirements.md#기능-요구사항)이 이미 "학원명·로고 이미지·시그니처 색을 설정하고 리포트 카드와 **웹 화면**에 반영"을 규정한다. 테마를 추가하면 학원 시그니처 색이 빨강인데 강사가 블루모드를 고른 경우 웹 화면의 주색이 무엇인지 기준선이 답하지 못한다. **임의 해석이 불가능한 제품 결정이라 사용자에게 확인했다.**
- **사용자 결정:** 테마는 **개인 설정**이다. 원장과 강사가 각자 다른 테마를 쓰고, 학원 시그니처 색은 학부모에게 가는 리포트 카드에만 쓴다.
- **현재 코드 상태(증거):** [TASK-44](../../plan.md#task-44-디자인-토큰과-공통-컴포넌트-기반)가 `apps/web/src/styles/tokens.css`에 `.dark` 블록 하나를 만들었으나 **전환 수단이 없어 사용되지 않는다.** 실측: 저장소 전체에서 `.dark` 클래스를 부여하는 코드 0건.
- **보류한 구현:** 없음. 이 변경에 해당하는 코드는 아직 한 줄도 작성하지 않았다. 완료된 [TASK-44](../../plan.md#task-44-디자인-토큰과-공통-컴포넌트-기반)·[TASK-47](../../plan.md#task-47-기존-화면-5개-재작성)은 당시 기준선에 대한 완료 기록이므로 상태를 되돌리지 않는다.

## 기존 설계와 제안 설계

### 기존 (기준선 `v4`)

- [FR-40](../../requirements.md#기능-요구사항): 시그니처 색을 **리포트 카드와 웹 화면**에 반영한다.
- [NFR-18](../../requirements.md#비기능-요구사항): 웹 화면과 리포트 카드는 **색**·간격·타이포를 단일 디자인 토큰에서 취해 시각적으로 일관되어야 한다.
- [AC-31](../../requirements.md#인수-조건): 리포트 카드와 웹 화면이 **같은 토큰 값(주요 색·타이포 스케일)** 을 사용함을 확인할 수 있다.
- [DES-24 상세](../../design.md#des-24-상세): 다크 모드는 토큰 레벨에서 지원하되 기본값은 라이트. 전환 수단은 정의하지 않았다.

### 제안 (기준선 `v5`)

- **FR-41 신설:** 사용자는 웹 화면의 테마를 라이트·다크·블루·그린·핑크 중에서 고르고, 선택이 유지된다.
- **FR-40 축소:** 시그니처 색의 반영 대상을 **리포트 카드**로 한정한다. 학원명·로고는 그대로다.
- **NFR-18 재정의:** 웹과 카드는 **같은 토큰 파일**에서 타이포·간격·라운드·그림자 스케일을 공유한다. 색은 웹이 사용자 테마를, 카드가 학원 시그니처 색을 따른다.
- **AC-31 개정 / AC-33·AC-34 신설** (아래 표).
- **DES-24 상세 갱신:** `data-theme` 전환, 색 토큰만 덮어쓰기, 전 팔레트 동일 키 집합, 카드의 팔레트 고정.

결정의 근거와 기각한 대안은 [ADR-012](./ADR-012-테마-팔레트와-적용-방식.md)에 있다.

## 마이그레이션과 롤백

- **마이그레이션:** 없음. DB 스키마와 API가 바뀌지 않는다. 기존 사용자는 저장된 값이 없으므로 라이트로 시작한다.
- **롤백:** `tokens.css`의 팔레트 블록과 테마 선택 UI를 되돌리면 끝난다. 데이터가 남지 않으므로 되돌림 비용이 사실상 0이다.

## 검증 방법

- **AC-33:** 테마를 고른 뒤 새로고침해도 같은 테마가 적용됨을 컴포넌트 테스트로 확인한다.
- **AC-34:** `tokens.css`를 파싱해 5개 팔레트가 동일한 색 토큰 키 집합을 갖는지 테스트한다(VER-32). 기존 [VER-30](../../plan.md#검증-계획) 테스트를 확장한다.
- **AC-31(개정):** 타이포·간격·라운드·그림자 토큰이 어느 팔레트에서도 재정의되지 않음을 테스트로 확인한다.
- **AC-30:** 카드가 테마와 무관하게 라이트 팔레트 + 시그니처 색을 쓰는지는 TASK-45·46에서 확인한다.
- 대비(contrast) 점검은 자동화하지 않고 사용자 육안 확인으로 둔다. 팔레트 색값은 심미 판단 항목이다.

## 남은 위험과 미해결 사항

- 팔레트 4벌의 실제 색값은 심미 판단이라 **사용자가 보고 확정해야 한다.** 구현 후 시안 확인을 받는다.
- 다크 팔레트의 상태색 대비는 육안 점검에 의존한다. WCAG 수치 검증은 범위 밖으로 둔다.
- 브라우저를 바꾸면 테마가 초기화된다. 개인 설정 결정의 자연스러운 귀결로 수용한다.
