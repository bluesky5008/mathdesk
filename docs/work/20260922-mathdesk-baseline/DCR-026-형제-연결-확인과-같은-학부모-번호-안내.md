## 요약

- 변경 분류: **요구사항 변경(FR-48 상세·FR-05·FR-06 보강) + 공개 인터페이스 변경(발급 API 확인 매개변수, 조회 응답 필드)** — 두 번째 학생의 학부모 번호가 **이미 다른 학생의 학부모 계정**이면 바로 연결하지 않고, 연결된 학생 이름을 보이는 **확인 카드**를 거쳐야 연결한다. 서버는 확인 없는 요청을 거부한다. 발급 전부터 "이 번호는 ○○○ 학부모 계정과 같습니다"를 안내하고, 학생 등록·수정 때도 같은 학부모 번호를 가진 다른 학생이 있으면 안내한다(저장은 막지 않는다).
- 변경 요지: ① `POST …/portal-accounts`에 `confirm_link`(기본 거짓) — 기존 학부모 계정 연결은 참일 때만, 아니면 409 ② `GET …/portal-accounts`의 학부모 항목에 `existing: {login_id, students: [이름]}` ③ 학생 응답에 `guardian_phone_shared_with: [이름]` ④ 수정 창 확인 카드·사전 안내, 등록 폼·목록·수정 창의 같은 번호 안내.
- 사용자 결정: 2026-10-11 검토 요청 → 추천안(확인 카드 + 서버 거부 + 사전 안내) + 등록·수정 시 같은 번호 안내 네 가지를 **승인**.
- 사용자 재승인 결과: **승인 (2026-10-11)** — 기준선 `v26` → `v27` 발행

## 변경 사유와 증거

- **계기:** 2026-10-11 사용자 지적 — 학부모 번호는 수기로 입력되므로 오타가 날 수 있고, 오타로 **다른 집 학부모 계정에 학생이 연결되면** 그 학부모가 남의 자녀 출결·점수·상담 기록을 보게 된다. 개인정보 노출이므로 연결 전 확인이 필요하다.
- **확인한 사실:** `issue_account`는 같은 로그인 ID의 학부모 계정이 있으면 **확인 없이** `app_user_student`를 추가하고 `linked: true`를 돌려준다. 화면은 "기존 학부모 계정에 연결했습니다"만 보인다. 학생 등록·수정은 학부모 번호 중복을 검사하지 않는다(형제는 같은 번호가 정상이므로 막을 수는 없다).
- **보류한 구현:** 없음.

## 제안

### 요구사항

- **FR-48 상세 "한 번호 = 계정 하나"(개정):** 같은 로그인 ID의 학부모 계정이 있으면 ① **바로 연결하지 않는다.** 화면은 그 계정에 연결된 학생 이름과 번호를 보이는 확인 카드를 띄우고, 원장이 [형제가 맞습니다, 연결]을 눌러야 연결한다. 서버는 확인 표시가 없는 요청을 거부한다(409) ② 발급 전부터 [수정] 창의 학부모 계정 줄에 "이 번호는 ○○○ 학생의 학부모 계정과 같습니다"를 안내한다 ③ 그 밖의 조합은 기존대로 거부한다.
- **FR-05·FR-06(추가):** 학생을 등록·수정할 때 같은 캠퍼스의 다른 학생이 같은 학부모 번호(숫자만 비교)를 가지면 "학부모 연락처가 ○○○ 학생과 같습니다. 형제가 아니면 번호를 확인하세요"를 **안내**한다. 저장은 막지 않는다. 학생 목록의 학부모 연락처 칸과 [수정] 창에도 같은 안내가 보인다.
- **AC-50 ④(개정):** 형제 둘의 보호자 번호가 같을 때 두 번째 발급을 누르면 "○○○ 학생의 학부모 계정" 확인 카드가 보이고, 확인 없이 보낸 요청은 409이며 연결이 생기지 않는다. [형제가 맞습니다, 연결]을 누르면 새 계정 없이 연결만 늘고 그 학부모 로그인에서 자녀 둘이 보인다.
- **AC-53(신설) 같은 학부모 번호 안내:** 김나윤의 학부모 번호와 같은 번호로 김정현을 등록하면 등록 직후 "학부모 연락처가 김나윤 학생과 같습니다"가 보이고 학생은 저장된다. 목록의 김정현 학부모 연락처 칸과 [수정] 창에도 같은 안내가 보인다. 번호를 `010 9876 5432`처럼 달리 적어도 숫자가 같으면 안내한다. 번호가 다른 학생에게는 안내가 없다.

### 설계

- **REST(DES-26 상세 발급):** `POST /students/{id}/portal-accounts` 본문 `{kind, guardian_id?, confirm_link?: bool}`. 기존 학부모 계정에 연결하게 되는 경우 `confirm_link`가 참이 아니면 `409 "이미 다른 학생의 학부모 계정인 번호입니다. 형제가 맞으면 확인 후 연결하세요."`. `GET /students/{id}/portal-accounts`의 `guardians[]`에 `existing: {login_id, students: [이름…]} | null` — 그 보호자 번호가 이미 학부모 계정이고 이 학생은 아직 연결되지 않았을 때.
- **REST(DES-04 학생):** `StudentOut`에 `guardian_phone_shared_with: [이름…]`(같은 캠퍼스의 다른 학생 중 대표 보호자 번호의 숫자열이 같은 학생, 이름순). 목록·등록·수정 응답 모두.
- **웹:** `PortalAccountsSection` — `existing`이 있으면 줄 아래 안내, [학부모 계정 발급]을 누르면 확인 카드(연결된 학생 이름·번호, [형제가 맞습니다, 연결]/[취소]) → 확인 시 `confirm_link: true`로 요청. `StudentsPage` — 등록 직후 응답의 `guardian_phone_shared_with`로 폼 아래 안내(`role=status`), 목록 학부모 연락처 칸에 "○○○과 같음", 수정 창 학부모 연락처 칸 아래 안내(저장된 값 기준).

## 검증 방법

- API(선행 테스트): 확인 없는 형제 발급 409·연결 없음, `existing` 내용, 확인 후 201 `linked`; 등록·수정·목록의 `guardian_phone_shared_with`(형식 달라도 숫자 같으면 포함, 본인 제외, 번호 없으면 빈 목록).

## 남은 위험

- 첫 학생의 번호가 오타여도 다른 학생에게 같은 번호가 없으면 안내가 없다. 그 계정은 번호 주인이 모르면 쓰이지 않고 7일 뒤 만료되며, 진짜 학부모의 로그인 불가 신고로 드러난다.
