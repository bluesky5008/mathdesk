## 요약

- 변경 분류: **요구사항 변경(FR-50·AC-54 신설, FR-12·FR-18·FR-45·FR-49 보강) + 데이터 모델·공개 인터페이스 변경.**
- 변경 요지: 원장이 학원 설정에서 ① "이전 과제 재검사" 항목을 **보이기/숨기기**하고 ② 학생마다 그날 한 줄로 적는 **추가 항목**(예: "수업태도")을 만들 수 있다. 추가 항목은 일일 입력 표, 학생별 정보, 학생별 정보 이미지, 학생·학부모 포털, 문자 본문에 모두 나온다. 설정을 건드리지 않은 학원은 지금과 완전히 같다.
- 사용자 결정(2026-11-12): 한 클라이언트는 재검사를 빼고 수업태도를 넣는다. 재검사는 나중에 다시 필요할 수 있다. 다른 클라이언트는 현행 유지. 항목은 원장이 정한다. 노출 범위는 보이는 곳 전부("이 칸의 목적이 보여 주는 데 있다").

## 변경 사유와 증거

- **계기:** 2026-11-12 사용자 요청. 학생별 정보 화면(날짜·출결·이전 과제 재검사·과제피드백·테스트·코멘트)에서 한 클라이언트가 재검사 대신 수업태도를 보이고 싶어 한다.
- **확인한 사실:**
  - 재검사는 `student_daily_record.recheck_result`에 저장되고 다음 여섯 곳에 나온다: 일일 입력 표(`DailyPage`), 학생별 정보(`StudentDailyPage`), 학생별 정보 이미지(`report.py`), 포털(`portal.py`·`portal/pages.tsx`), 대시보드 과제 KPI의 "재검사 대상 N명"(`stats.py`·`DashboardPage`), 재검사 저장 API.
  - 문자 본문에는 재검사가 없고 학생별 코멘트만 개별 구획에 들어간다(`messaging.py`, FR-18).
  - 학원 단위 설정은 `integration_setting(campus_id, key, value)`에 저장한다(`branding.py`).
- **보류한 구현:** 없음.

## 제안

### 요구사항

- **FR-50(신설) 일일 기록 항목 구성:** 원장은 학원 설정의 [일일 기록 항목]에서 다음을 정한다. 저장 즉시 모든 화면에 반영된다.
  1. **이전 과제 재검사 보이기**(기본 켬). 끄면 아래 "노출 위치" 전부에서 재검사가 사라진다. 저장된 재검사 결과는 지우지 않으며 다시 켜면 그대로 보인다.
  2. **추가 항목** 0~5개. 항목마다 이름(1~20자, 학원 안에서 중복 불가). 값은 학생·수업마다 한 줄 텍스트(100자 이내, 비울 수 있음). 이름을 바꿔도 값은 유지된다. 항목을 삭제하면 화면에서 사라지지만 값은 지우지 않는다(삭제 전 확인).
  - 강사·조교는 설정을 읽기만 한다.
- **노출 위치(FR-12·FR-45·FR-49·AC-47 보강):**

  | 위치 | 재검사(켬일 때) | 추가 항목 |
  |---|---|---|
  | 일일 입력 표(반별 정보) | 현행 열 | 재검사 자리(출결 다음)에 항목마다 입력 열. 방향키·Enter 이동, 표 일괄 저장(FR-14), 출결 확정 후에도 입력 가능 — 코멘트(FR-44)와 같다 |
  | 학생별 정보 표 | 현행 열 | 같은 자리에 읽기 전용 열 |
  | 학생별 정보 이미지 | 현행 열 | 같은 자리에 열 |
  | 학생·학부모 포털 수업 상세 | 현행 구획 | 값이 있는 항목만 `항목 이름` 구획으로 |
  | 대시보드 과제 KPI | "재검사 대상 N명" | 해당 없음 |
  | 문자 본문 개별 구획(FR-18) | 해당 없음(현행) | 값이 있는 항목만 `■ 개별 코멘트` 앞에 `■ <항목 이름>` 한 줄씩 |

- **기록이 있는 수업(FR-45 상세 보강):** 추가 항목 값이 하나라도 저장된 세션도 "기록이 있는 수업"이다.
- **AC-54(신설):**
  1. 설정을 바꾸지 않은 학원에서 일일 입력·학생별 정보·이미지·포털·대시보드·문자 미리보기가 변경 전과 같다.
  2. 원장이 재검사를 끄고 추가 항목 "수업태도"를 저장하면, 일일 입력 표와 학생별 정보에서 "이전 과제 재검사" 열이 없고 그 자리에 "수업태도" 열이 있다. 대시보드에 "재검사 대상" 문구가 없다.
  3. 한 학생의 수업태도에 "집중 좋음"을 적고 표 일괄 저장 뒤 새로고침하면 값이 유지되고, 학생별 정보·이미지·그 학생의 포털 수업 상세·문자 미리보기 개별 구획에 "수업태도"와 "집중 좋음"이 보인다. 값을 비운 학생에게는 포털·문자에 그 구획이 없다.
  4. 재검사를 다시 켜면 끄기 전에 저장한 합격·불합격이 그대로 보인다.
  5. "수업태도"를 "태도"로 바꾸면 기존 값이 "태도" 아래에 보인다. 항목을 삭제하면 모든 위치에서 사라진다.
  6. 강사 계정으로 설정 저장을 요청하면 403이다. 여섯 번째 항목, 빈 이름, 중복 이름, 101자 값은 422다.

### 설계

- **DES-27(신설) 일일 기록 항목 구성:**
  - 설정 저장: `integration_setting` 키 `daily.fields`, 값은 JSON `{"recheck": true, "extra": [{"id": "x1", "label": "수업태도"}], "next_id": 2}`. 행이 없으면 `{"recheck": true, "extra": []}`로 본다. 항목 `id`는 `x<일련번호>`로 서버가 발급하고 삭제 뒤에도 재사용하지 않는다(`next_id`).
  - 값 저장: `student_daily_record.extra`(JSONB, NOT NULL, 기본 `{}`) — `{"x1": "집중 좋음"}`. 빈 문자열은 키를 지운다.
  - REST: `GET /api/settings/daily-fields`(직원 전원) → `{recheck, extra: [{id, label}]}`. `PUT /api/settings/daily-fields`(원장) 본문 `{recheck, extra: [{id?, label}]}` — `id` 없는 항목은 신규 발급, 본문에 없는 기존 `id`는 삭제로 본다.
  - 일일 기록: `DailyRecord`·이력 행 응답에 `extra: {id: 값}` 추가. 표 일괄 저장 본문의 학생 항목에 `extra`(선택) 추가 — 설정에 없는 `id`는 422. 재검사 저장 API는 그대로 둔다(숨김은 표시의 문제이며 서버가 거부하지 않는다).
  - 표시 규칙은 서버가 한 곳에서 정한다: `daily.py`에 설정 조회 함수 하나를 두고 `report.py`(이미지)·`portal.py`·`messaging.py`·`stats.py`가 그것을 쓴다. 포털 응답은 `recheck`를 설정이 끔이면 `null`로, `extra`를 `[{label, value}]`(값 있는 것만, 설정 순서)로 준다 — 포털은 설정 API를 부르지 않는다. 대시보드 KPI 응답은 `recheck_targets`를 끔이면 `null`로 준다.
  - 웹: 설정 화면에 [일일 기록 항목] 카드(재검사 스위치, 항목 목록 추가·이름 변경·삭제·순서는 추가 순). `DailyPage`·`StudentDailyPage`는 설정을 읽어 열을 그린다.
- **DES-05·DES-26 상세:** 위 응답 필드를 반영한다.

## 영향 범위

- 요구사항과 인수 조건: FR-50·AC-54 신설, FR-12·FR-18·FR-45·FR-49·AC-47 보강.
- 인터페이스와 데이터: 응답 필드 추가(기존 필드 유지), `recheck`·`recheck_targets`가 `null`일 수 있음(재검사를 끈 학원에서만). 마이그레이션 1건(열 추가, 기본값 있음).
- 보안과 개인정보: 추가 항목 값은 학생 평가 정보이며 **그 학생 본인과 연결된 학부모에게 보인다**(코멘트와 같은 범위). 다른 학생에게는 보이지 않는다. 이름·값은 HTML 이미지에 들어가므로 이스케이프한다.
- 비용: 추가 항목이 문자 본문에 들어가면 본문이 길어져 SMS(90바이트)에서 LMS로 넘어가는 경우가 늘 수 있다. 값이 있을 때만 넣는다.
- 통계: 추가 항목은 자유 텍스트라 성적 통계·내보내기에 넣지 않는다.
- 진행 중인 구현: 없음.

## 고려한 대안

| 대안 | 판단 |
|---|---|
| "재검사" 열의 이름만 "수업태도"로 바꾸는 설정 | 기각 — 재검사는 합격/불합격 판정이고 직전 등급에 묶여 있어 의미가 다르다. 나중에 둘 다 쓰려면 다시 만들어야 한다 |
| 수업태도를 고정 열로 추가하고 스위치만 제공 | 기각 — 다음 요청(다른 이름의 항목)마다 마이그레이션·배포가 필요하다 |
| 추가 항목마다 테이블 행(EAV) | 기각 — 5개 이하의 한 줄 텍스트에 과하다. JSONB 열 하나로 충분하다 |
| 등급형·선택형 항목까지 한 번에 | 보류 — 요청은 텍스트 칸이다. `extra` 항목에 `type`을 더하는 것으로 나중에 확장할 수 있다 |
| 항목별 "문자에 포함" 스위치 | 보류 — 사용자가 전부 노출을 택했다. 문자 길이가 문제가 되면 추가한다 |

## 마이그레이션과 롤백

- 마이그레이션: `student_daily_record.extra` 열 추가(기본 `{}`). 기존 행에 영향 없음.

## 검증 방법

- API(선행 테스트): 설정 기본값·저장·검증(403·422)·id 재사용 금지, 일일 저장·조회의 `extra`, 이력·이미지·포털·문자 미리보기·KPI가 설정에 따라 달라짐, 설정 없는 캠퍼스의 응답이 기존 테스트 그대로 통과.
