## 요약

- 결정: `LlmAdapter`의 계약을 **공급자 중립**(문항 입력 → 구조화된 분석 결과)으로 정의하고, 구현체를 테스트 모드·Anthropic·OpenAI 호환 3종으로 두어 설정값으로 교체한다. Anthropic 구현은 공식 `anthropic` Python SDK를 사용하며 기본 모델은 `claude-opus-5`다.
- 핵심 이유: Anthropic Messages API는 OpenAI 호환 형식이 아니므로, 기존 계약을 유지한 채로는 Claude를 붙일 수 없다. 호환 shim으로 우회하면 구조화 출력·프롬프트 캐싱·토큰 사용량 기록을 모두 잃는다.
- 주요 단점: 공급자별 구현이 2종으로 늘어 유지 대상이 증가한다. 요청·응답 변환이 각 구현체 안에 갇힌다.

## 배경

[ADR-003](./ADR-003-AI-작업-분리와-개인정보-경계.md) 결정 2는 `LlmAdapter`를 "OpenAI 호환 `chat/completions` 클라이언트"로 고정했다. 이 결정은 승인 시점에 공급자가 미정(Q-05)이었고, OpenAI 호환 형식이 사실상의 공통 분모라는 전제에 서 있었다.

사용자가 M6의 공급자를 차후 가변으로 두고 현재 사용 중인 Claude를 연결하는 방안을 요청했다. Anthropic Messages API는 OpenAI 호환 형식이 아니다.

| 항목 | OpenAI 호환 | Anthropic Messages API |
|---|---|---|
| 엔드포인트 | `POST /v1/chat/completions` | `POST /v1/messages` |
| 인증 | `Authorization: Bearer` | `x-api-key` + `anthropic-version` |
| 시스템 프롬프트 | `messages[0].role="system"` | 최상위 `system` 필드 분리 |
| 응답 본문 | `choices[].message.content` | `content[]` 블록 배열 |
| 구조화 출력 | `response_format` | `output_config.format` |
| 사용량 | `usage.prompt_tokens` | `usage.input_tokens` + 캐시 읽기·쓰기 토큰 분리 |

실행 환경도 확인했다. 이 장비에는 `ant` CLI가 설치되어 있지 않고, `ANTHROPIC_API_KEY`가 설정되어 있지 않으며, `~/.config/anthropic` 자격증명 프로필도 없다. **현재 개발에 사용 중인 Claude Code 로그인은 구독 인증이며 애플리케이션 서버가 재사용할 수 있는 API 자격증명이 아니다.** Claude 연결에는 별도 발급한 API 키가 필요하다.

## 영향을 받는 요구사항과 제약

- [NFR-12 테스트 가능성](../../requirements.md#비기능-요구사항): 외부 연동은 인터페이스 뒤에서 가짜 구현으로 교체 가능해야 한다.
- [AC-23 LLM 어댑터 교체](../../requirements.md#인수-조건): 설정 변경만으로 다른 구현을 호출해야 한다. 현재 문구는 "엔드포인트" 교체를 전제한다.
- [NFR-04 개인정보 경계](../../requirements.md#nfr-04-상세)와 [AC-27](../../requirements.md#인수-조건): 외부로 나가는 데이터는 학생 식별 정보가 없는 문항 텍스트·이미지로 한정한다.
- [NFR-15 비용 통제](../../requirements.md#비기능-요구사항): 시험지 단위 토큰 상한과 호출 기록이 필요하다.
- 사용자 결정: 기본 모델은 `claude-opus-5`.
- 제약: API 키가 없는 상태에서도 개발·테스트가 막히면 안 된다.

## 고려한 대안

| 대안 | 장점 | 단점·위험 | 전환 비용 |
|---|---|---|---|
| A. 공급자 중립 계약 + 구현체 3종 (선택) | 공급자 교체가 설정 한 줄, Anthropic 고유 기능 전부 사용, 경계 테스트 위치 불변 | 구현체 2종 유지, 변환 로직이 구현체마다 존재 | 중간 |
| B. ADR-003 유지 + OpenAI 호환 shim으로 Claude 호출 | 계약 변경 없음, 코드 변경 최소 | 구조화 출력·프롬프트 캐싱·캐시 토큰 기록 상실, shim 의존성 추가, 오류 표현이 뭉개짐 | 낮음 |
| C. Anthropic 전용으로 교체 (OpenAI 호환 제거) | 구현 1종, 가장 단순 | 사용자 요청의 "가변"을 만족하지 못함, 로컬 폴백([ADR-003](./ADR-003-AI-작업-분리와-개인정보-경계.md) 결정 2·RISK-04 완화책) 상실 | 낮음 |
| D. LangChain 등 범용 추상화 계층 도입 | 공급자 다수 즉시 지원 | 이 프로젝트가 쓰는 공급자는 2종뿐이라 과한 의존성. 어댑터 5개를 직접 정의한 [설계 방침](../../design.md#컴포넌트와-책임)과 불일치 | 중간 |

B는 사용자가 요청한 "Claude 연결"을 형식적으로는 만족하지만, 이 결정의 실익(구조화 출력으로 FR-28 파싱 안정화, 캐싱으로 NFR-15 비용 절감)을 대부분 잃으므로 기각한다. C는 "가변"을 만족하지 못하므로 기각한다.

## 결정

1. **`LlmAdapter` 계약을 공급자 중립으로 정의한다.** 입력은 문항 번호·문항 텍스트·문항 이미지와 분석 지시, 출력은 단원·세부 유형·난이도·판단 근거·신뢰도와 사용량(입력·출력·캐시 읽기·캐시 쓰기 토큰, 비용)이다. 계약에 특정 공급자의 요청·응답 형식을 노출하지 않는다.

2. **구현체를 3종 둔다.**

   | 구현체 | 용도 | 기본값 |
   |---|---|---|
   | `TestModeLlm` | 개발·자동 테스트. 외부 호출 0, 고정 응답 | **기본 공급자** |
   | `AnthropicLlm` | 운영. 공식 `anthropic` Python SDK | `claude-opus-5` |
   | `OpenAICompatLlm` | 로컬 폴백·타 공급자(vLLM·Ollama 등) | 엔드포인트 설정 필수 |

3. **선택은 설정값으로 한다.** `MATHDESK_LLM_PROVIDER`(`test`·`anthropic`·`openai_compat`, 기본 `test`)가 구현체를, `MATHDESK_LLM_MODEL`이 모델을 정한다. 캠퍼스별 재정의는 `integration_setting`에 두고 환경변수를 우선한다([DES-20](../../design.md#컴포넌트와-책임)). API 키가 없으면 `anthropic` 선택 시 기동 시점이 아니라 **첫 호출 시점**에 명확한 오류를 반환한다.

4. **전송 필드 화이트리스트는 `QuestionAnalyzer`에 유지한다.** 어댑터가 아니라 분석기에서 강제하므로 공급자를 바꿔도 [NFR-04](../../requirements.md#nfr-04-상세) 경계와 [AC-27](../../requirements.md#인수-조건) 테스트 위치가 바뀌지 않는다. 바뀌는 것은 나가는 호스트뿐이다.

5. **Anthropic 구현은 다음 기능을 사용한다.**
   - 구조화 출력(`output_config.format`, `json_schema`)으로 분석 결과 스키마를 강제한다. FR-28 응답 파싱 실패를 제거하고 FR-29의 신뢰도 임계값 판정을 안정화한다.
   - 프롬프트 캐싱으로 단원 분류 체계 프롬프트를 시험지 한 건의 문항 전체에 재사용한다.
   - `stop_reason == "refusal"`을 실패로 분류해 문항 단위 재시도 경로([설계 시험지 분석 흐름](../../design.md#시험지-분석) 5번)로 넘긴다. 응답 본문을 무조건 읽지 않는다.
   - 공식 SDK만 사용한다. `httpx`로 Anthropic 엔드포인트를 직접 호출하지 않는다.

6. **호출 기록에 공급자와 캐시 토큰을 포함한다.** `llm_call_log`에 `provider`, `cache_read_tokens`, `cache_write_tokens`를 추가한다. 캐싱 적용 후에도 실제 비용을 재구성할 수 있어야 한다([NFR-15](../../requirements.md#비기능-요구사항)).

7. **기본 토큰 상한을 확정한다.** 시험지 1건당 입력 200,000 토큰, 출력 30,000 토큰. 30문항 기준 추정 사용량(입력 약 60,000·출력 약 9,000)의 약 3배 여유이며 설정값으로 노출한다. 상한 초과 시 작업을 중단하고 사용한 비용을 알린다. 이로써 [Q-05](../../requirements.md#가정과-미해결-질문)가 해소된다.

## 이유

1. Anthropic API가 OpenAI 호환이 아니므로 계약 변경 없이는 Claude를 붙일 수 없다. 계약을 어차피 건드려야 한다면 특정 공급자 형식이 아니라 도메인 의미(문항 → 분석)로 정의하는 것이 교체 가능성(NFR-12·AC-23)에 부합한다.
2. 구조화 출력은 이 도메인에 직접적인 이득이다. 분석 결과는 5개 필드가 고정된 구조체이고, 자유 텍스트 파싱은 30문항 × 시험지마다 실패 가능성이 누적된다.
3. 프롬프트 캐싱은 시험지 단위 작업 형태와 맞아떨어진다. 문항마다 반복되는 분류 체계 프롬프트가 캐시 대상이다.
4. 테스트 모드를 기본값으로 두면 API 키 없이도 M6 구현과 전체 테스트가 진행된다. [ADR-005](./ADR-005-메시징-어댑터-단일화.md)에서 `MessagingAdapter`에 이미 적용해 검증된 패턴이다.
5. 화이트리스트를 분석기에 두면 공급자 교체가 개인정보 경계의 회귀 위험을 만들지 않는다.

## 결과와 감수할 단점

- 공급자 구현이 2종이 되어 유지 대상이 늘어난다. 계약 테스트를 공유해 두 구현이 같은 계약을 만족하는지 검증한다.
- Anthropic 기본 모델 `claude-opus-5` 기준 시험지 1건당 약 $0.53(약 740원)으로 추정된다(30문항, 문항당 입력 약 2,000·출력 약 300 토큰 가정, 캐싱·배치 미적용). 추정치이며 실측으로 보정한다.
- API 키가 운영 시크릿으로 추가된다. `integration_setting`의 암호화 저장([NFR-05](../../requirements.md#비기능-요구사항))과 `.env` 관리 대상이다.
- 구조화 출력 스키마가 분석 결과 구조와 결합한다. 결과 필드가 바뀌면 스키마도 함께 바뀐다.
- Message Batches(50% 할인)는 이번 결정에 포함하지 않는다. 최대 24시간 지연이 시험지 분석의 사용성과 맞지 않을 수 있어 실측 후 별도 판단한다.
